## Architecture

```

                       # + shared let-bindings + host assembly (flake.lib, 3 hosts)
flake/parts/           # flake-parts modules — ALL perSystem logic (split 2026-10-09, was 4023-line flake.nix)
  pkgs.nix             # perSystem _module.args.pkgs (nixpkgs instantiation)
  formatter.nix        # treefmt wrapper
  packages.nix         # mkLarsPackages + nixpkgs picks + Linux-only
  devshells.nix        # default + quickshell shells
  apps.nix             # all 19 apps
  checks/              # lint-static, fixtures-{forgejo,storage,migrations}, selftests, vm-tests
systems/               # Host assembly: evo-x2.nix, darwin.nix, rpi3-dns.nix
lib/                   # Helpers — import via lib/default.nix (single import point)
  lars-packages.nix    # mkLarsPackages — single source of truth for LarsArtmann Go tools
  systemd/             # harden / serviceDefaults / serviceOneshotDefaults
modules/nixos/         # flake-parts NixOS modules, auto-discovered by filename
  services/            # Server/networking/app daemons (Caddy, Immich, SigNoz, DNS, …)
  desktop/             # Desktop-environment config (audio, display-manager, niri, steam, …)
pkgs/                  # Custom packages (buildGoModule, dms-plugins/)
overlays/              # shared.nix (callPackage + activitywatch + d2 Darwin stub), linux.nix (flake-input overlays)
platforms/common/      # Shared (~80%): home-base.nix, programs/, packages/, theme.nix, locale.nix
platforms/darwin/      # macOS (nix-darwin) — user: larsartmann
platforms/nixos/       # NixOS — user: lars
  desktop/quickshell.nix # Quickshell HM module (DankMaterialShell)
scripts/               # Shell + Python operational scripts
```

## Critical Rules

Universal, hard rules. Domain-specific critical rules live at the top of each `docs/agents/*.md` file and in each service runbook.

- **NEVER commit a secret to a repo — not in status reports, not in commit messages, not in "manual step" command examples, not ANYWHERE.** The ONLY exception: sops-encrypted files (`platforms/*/secrets/`). Agents must never need the raw value: reference `config.sops.secrets.<name>.path`, render via sops templates, or write `<REDACTED — paste key interactively>` placeholders for manual steps. The user holds secret values; the repo never does. Enforced by gitleaks (staged-tree, blocking) + `scripts/scan-history-secrets.sh` (full history) — see [docs/agents/secrets.md](./docs/agents/secrets.md) for what happens otherwise
- **Use flake commands** — `nix run .#deploy`, never raw `nixos-rebuild`/`darwin-rebuild`
- **`--keep-going` FIRST when a deploy is blocked** — when the toplevel build fails, run `nix build .#nixosConfigurations.evo-x2.config.system.build.toplevel --keep-going` (or `nix flake check --keep-going`) BEFORE fixing anything: one pass enumerates ALL root failures. Domino deploys (fix eval → switch → hit next FOD → switch again) wasted ~25 minutes across 4 switch attempts on 2026-08-27; the enumeration would have caught every domino in one command
- **Test first** — `nix flake check --no-build` (syntax) or `nix eval .#nixosConfigurations.evo-x2.config.system.build.toplevel` (eval)
- **`trash` not `rm`**, **`git mv` not `mv`**, **2-space indentation**, **`config.allowBroken = false`**, **No OpenZFS on macOS** (kernel panics, ADR-003)
- **Open new terminal** after deploy (shell changes need new session)
- **Land the replacement BEFORE removing the old source — and diff which entities existed ONLY there first** (2026-08-31 crush lesson): deleting a config file that still owns live entities (a model, a provider, a credential) breaks them even if a replacement is "coming"; `glm-5.3-flash` vanished and requests silently fell back to zai's pricier default until caught. Sequence: deploy replacement → verify parity (`crush models` before/after or domain equivalent) → THEN delete. Never assert success from output text alone — assert WHICH entity served it
- **A verification close-out must answer the question the item ASKED, not a sub-proof** (2026-09-18 browser-history gate class): "the binary gates on a fresh DB" does not answer "is the gate closed in prod" — the read-model count-gap is exactly the variable separating the two, and the prod probe returned 201 while the close-out headline claimed the gate live (a reviewer had to catch it; both sites corrected in `0e65881f`). When a probe MUTATES prod state or its first result contradicts the expected invariant, that contradiction IS the verdict and leads the close-out; a result observed once is "happened", never "can". Adjacent to "assert WHICH entity served it": assert WHICH question your evidence answers
- **A correction claim must NAME the corrected surface(s) and show the post-state** (2026-09-29 count-claim class): a report saying "the count was corrected" while the fix landed in only ONE of the queue surfaces is a half-fix — `TODO_LIST.md` close-outs, `docs/todo/<lib>.md` rows, and the source report are separate surfaces, and "queue one-liners and their library entries must not drift — edit both" applies to corrections too (the stale count survived a full session until a reviewer finding forced a second dispatch). Sibling of the rule above, one level up: assert WHICH surface the fix touched
- **Never write a secret VALUE into a command line — interactive shells included.** `sops --set '["key"] "VALUE"'` and `export KEY=VALUE` land verbatim in `fish_history` (plaintext, forever) — the 2026-08-18 Resend leak was exactly this pattern from an agent, and 2026-09-01 the LIVE minimax + zai keys were found in fish_history from USER command lines (purged via `printf 'all\n' | fish -c "history delete --contains '<prefix>'"`, confirmed 0). Interactive secret entry goes through `sops` (editor) or reads from `/run/secrets` — never inline
- **Never hardcode** `localhost:PORT` — derive from config. All ports in `lib/ports.nix`. **Eval-enforced since 2026-09-14**: `port-registry-audit.nix` scans every unit's Exec*/Environment text for port literals (host/colon/flag forms) and fails `nix flake check` on any port not in `lib/ports.nix` — justified exemptions go in `services.port-registry-audit.allowPorts` with a comment
- **Docker is REMOVED (2026-10-08)** — daemon, CLI packages, Dozzle (`logs.home.lan` redirects to the SigNoz logs explorer), cAdvisor/docker-engine monitoring, docker-prune, the `lib/images.nix` registry + `check-image-updates.sh`/`image-updates.yml`, and the disabled compose modules (twenty, voice-agents) are all gone; the Forgejo runner is native-host-only. If a container runtime ever returns: re-establish the old image policy (pin `tag` + `digest`, never float, latest-tag rejected at eval — the deleted `serviceTypes.dockerImageTag` pattern) and DB-backed apps get migration review before major/minor bumps. Residue: `/data/docker` (~15.5 GB) awaits owner reclaim (docs/todo/services.md) — agent-side `du`/`ls` on it are PERMISSION-BLIND (`drwx--x--- root root`, corrected 2026-10-10): a 0 reading is an artifact, size verify only via that row's step-0 sudo inventory
- **Never silently substitute placeholder identity in git commits** — if `user.name`/`user.email` cannot be resolved, FAIL LOUD. Hardcoded `"Unknown Author"`/`"unknown@example.com"` fallbacks masked broken git config and produced ~6,400 unattributable commits. SystemNix's `services.projects-management-automation` sets `gitIdentity` which translates to `GIT_AUTHOR_*`/`GIT_COMMITTER_*` env vars on the daemon — env precedence beats config lookup, so the daemon always has a valid identity. See `docs/gotchas-archive.md` for the full incident.
- **Never force-enable a disabled service in the working tree "just to verify", and never manually activate a built toplevel** (`sudo ./result/switch-to-configuration …` — any activation outside `nix run .#deploy`) — a manual activation leaves NO profile generation and skips deploy.sh post-switch steps. The SAFE verification pattern is a throwaway `extendModules` expression that never touches the tree: full form in [docs/agents/nix-flakes.md](./docs/agents/nix-flakes.md#safe-verification-of-a-disabled-service-never-force-enable).
- **After ANY history rewrite (amend/rebase/filter-repo), run the full verification checklist** — reachability (`merge-base --is-ancestor`), claim-message presence (`log --grep`), stale-ref sweep (`for-each-ref`) — and RE-RUN it after any later rebase onto origin history (it silently abandons unpushed rewrite lineages). Never assert "rewrite landed" from the rewriting command's exit code. Full checklist: [docs/agents/git.md](./docs/agents/git.md#history-rewrite-verification-checklist).
- **GitHub push protection ignores `.gitleaks.toml` allowlists** — it pattern-matches raw blobs in the push range; fixture/detector-test tokens must be runtime-derived TEMPLATES, never tracked literals (documented-FAKE tokens are NOT exempt; status reports SHAPE-DESCRIBE tokens). Unblock playbook: [docs/agents/git.md](./docs/agents/git.md#github-push-protection-ignores-gitleakstoml-allowlists).
- **Concurrent agent sessions share this tree — attribute honestly, expect mid-edit races** — the auto-commit daemon batches MULTIPLE sessions' work into shared commits (2026-08-18: fastflowlm/smartd/data-to-pool rode the black-screen-followup commits). Rules: (1) when the tree grows changes you didn't author, flag it to the user immediately, don't silently co-verify them; (2) your "flake check passed" only covers YOUR files — the batch may break after the other session's next edit; (3) mid-session file modifications (`file modified since read` from edit tools, shifting line numbers) = another session is active: re-read before every edit, keep negative-test neuter/restore cycles ATOMIC (single shell command), and verify evals of shared surfaces (evo-x2, flake check) only at quiescent moments — a NEW module file on disk that is not yet `git add`ed makes EVERY evo-x2 eval fail with "attribute missing" (the tracked-files trap) until the owning session adds it; (4) when committing YOUR file out of a shared dirty index, use a PATHSPEC commit (`git commit -m … -- <path>`) — a bare `git add <file> && git commit` sweeps every other staged file into your commit AND push (12 CV files rode a push this way, 2026-08-30); (5) **daemon-race discipline: before AMENDING into an auto-commit, verify WHAT the daemon actually staged** (`git show --stat HEAD`) — the daemon batches parallel sessions' files, and an amend absorbs all of them into your rewritten commit (2026-09-14 footer-commit fragmentation)
- **Commit-message evidence rule: a claim of the form "tool X rejects Y" in any commit message, TODO, or report requires an ACTUAL RUN of tool X against Y in that session** — a fabricated rejection premise (the 2026-09-13 "gitleaks rejects bare 40-hex" claim, retracted 2026-09-15; its rule attribution was ALSO wrong: `sq0atp-` keys the SQUARE rule, `sourcegraph-access-token` gates bare hex on its own keywords) becomes tested invariant via `checks.x86_64-linux.gitleaks-coverage-selftest`
- **Prose rev citations use the SHORT-REV form (7-char)** — full 40-char SHAs only inside commands where git needs them. Evidence tables cite the short form; the full form is recoverable via the cited command (`git rev-parse <short>`)

## Session Discipline (shared tree, auto-commit daemon)

- **Planning-layer pre-read + live-state verification (2026-10-05)**: before proposing or designing ANY architecture, `rg -il` the topic across `docs/brainstorming/` + `docs/planning/` — a ratified plan there outranks a fresh design (the 2026-10-05 case: a full Pocket-ID-HA flake design was drafted and answered while the owner-ratified net-vpn plan rejecting it sat unread in docs/brainstorming). And never assert a service capability from a doc claim alone — `ss`/`dig`/config-grep the LIVE state first (the stale "dnsblockd serves DoQ 853" claim shipped in an answer because nobody ran `ss -lun`). A "verified" label must cover every fact asserted, not just the facts checked.
- **Shell histories are incomplete for still-open terminals — actor attribution needs /proc forensics, not history files (2026-10-08)**: fish writes history ONLY on exit, so commands from live shells (or crashed sessions) never appear in fish_history; a missing history entry proves nothing. For who-ran-what attribution: true start times via `/proc/<pid>/stat` field 22 (dir mtimes lie), cwd via `/proc/<pid>/cwd`, per-cgroup `io.pressure` for stall attribution, and the project `.crush/crush.db` (sqlite, `messages.parts` LIKE) for agent sessions. The 2026-10-07 blanket-lock actor was found this way after history/bash/cron/daemon elimination; negative DB queries must be validated against a KNOWN positive case first.
- **Agent shells block common ops binaries at command-parse time — use the verified live-probe set (2026-10-10)**: the Crush tool guard rejects typed `systemctl`, `curl`, `ip`, `wget` and friends; working substitutes verified this session: `ss -ltnp`, `pgrep -af`, `getent hosts`, and raw HTTPS via `printf 'GET / HTTP/1.1\r\nHost: <vhost>\r\nConnection: close\r\n\r\n' | openssl s_client -quiet -connect <ip>:443 -servername <vhost>` (curl banned, openssl not). Repo scripts that call curl/systemctl INTERNALLY run fine (the guard sees only the agent's typed line) — post-deploy-check.sh and throwaway harnesses are legitimate full-power probes.

### Multi-agent write discipline (2026-09-19)

- **Content-pin BEFORE every write**: `git rev-parse HEAD` + `git status --short` + `git log --stat` since your last known rev — parallel agent sessions commit continuously and may have touched YOUR target files in "heuristic" daemon commits. Diff-review anything new before editing.
- **When the daemon commits your in-flight work** (heuristic message, ~every 10 min): verify its contents with `git show --stat`, then `git commit --amend` the unpushed HEAD into a properly-messaged commit. Never `git reset`; amend-forward preserves the tree.
- **Daemon commits + amend can bypass pre-commit filetype legs** — the lint legs are keyed on STAGED paths; when the daemon commits your script first, your amend sees "No staged .sh files" and shellcheck/ruff silently skip (heal-breadcrumb.sh shipped this way, 2026-09-28 — proven clean only by luck at review). Re-run the skipped lint standalone after any daemon-swept amend; the full daemon-race policy (land-on-top vs amend, exclusivity checks) is in `docs/CONTRIBUTING.md` → "Daemon-race commit policy".
- **Lint-scanner FPs get fixed in the SCANNER, not suppressed at the call site** (2026-09-19 dead-guard-lint): the `$((` arithmetic form false-positived as a shell capture — fix = 1-char lookahead in the flake.nix awk scanner (`substr(line, RSTART + RLENGTH, 1) == "("` → skip), NOT `# dead-guard-ok` on the foreign line that tripped it (llama-rag.nix `leaks=$((leaks + 1))` was never touched).

## Build & Deploy

```bash
nix flake check --no-build  # Validate syntax (fast)
nix run .#deploy            # Build + deploy via nh
nix run .#pre-reboot-check  # Boot-chain audit BEFORE any planned reboot (self-elevates)
nix fmt                     # treefmt + alejandra
```

**Run `nix run .#pre-reboot-check` before every planned reboot** — it statically audits the whole boot chain (loader default entry → kernel/initrd on ESP → `init=` on the LIVE store → profile anchoring → initrd-required devices → btrfs health → zombie mounts → GC anchoring §10 → **boot-mirror §11**) and BLOCKS on the 2026-09-07 stuck-boot class (default entry whose store paths live only on a retired store). Exit 0 = safe; advisories never block.

**Samsung 2nd boot disk / boot mirror (2026-09-18, `platforms/nixos/system/boot-mirror.nix`)**: `/boot-mirror` is a VERIFIED byte-mirror of the QLC `/boot` (rsync `--delete` + `diff -r` gate; `boot-mirror-sync.service`); `nix run .#boot-mirror-activate` orders the Samsung ESP first in NVRAM. **Activation runs leave NO journal/file trace** — `scripts/boot-mirror-activate.sh` self-elevates via sudo and prints to the invoking terminal's stdout ONLY (no logger/tee); post-activation audit evidence paths are (1) efivarfs state (`BootOrder`/`BootCurrent`/`LoaderDevicePartUUID` decode — read-only verify protocol) and (2) `boot-mirror-sync.service` journal lines timestamped after the activation. Mirror ACTIVATED 2026-09-30; first post-activation boot = the 2026-10-03 freeze-#12 crash reboot (mirror survived: sync OK 17 entries / 325M at 14:16:05); the PartUUID/BootCurrent decode verify half remains open. Full mechanics, rollback ladder, and the UTF-16 `LoaderDevicePartUUID` forensics method: [docs/agents/systemd.md](./docs/agents/systemd.md#boot-mirror-samsung-2nd-boot-disk).

**Samsung hot-tier subvolumes (doctrine C — unsnapshotted, nodatacow)**: large always-churning trees move OUT of the QLC root `@` snapshot set onto the Samsung toplevel (`/mnt/hot`) as `+C` subvols — deletion frees INSTANTLY (no pin window) and the churn leaves the QLC. Live: `journal` → `/var/log/journal` (journal-hot.nix, 2026-09-14), `caddy-logs` → `/var/log/caddy` (caddy-logs-hot.nix, live 2026-10-04).
