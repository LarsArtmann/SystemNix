## [Unreleased]

### Added

- **Eval-time OTel endpoint audit (`services.otel-endpoint-audit`)** — new auto-discovered module (`modules/nixos/services/otel-endpoint-audit.nix`) that fails `nix flake check` when any `OTEL_EXPORTER_OTLP*_ENDPOINT` env var violates the consuming SDK's parsing contract — the bug class behind the browser-history startup hang (`parse "127.0.0.1:4317": first path segment in URL cannot contain colon`, 2026-08-14 outage: a schemeless endpoint passed to a URL parser). Scans `systemd.services.*.environment`, `.serviceConfig.Environment`, and `oci-containers.*.environment`. Generic rules for ANY service (unregistered included): gRPC port 4317 ⇒ `http://` scheme REQUIRED; scheme ∈ {none, http} (never https — plaintext localhost receiver); host ∈ {localhost, 127.0.0.1, host.docker.internal} (traces must not leave the machine); port ∈ {signoz-otlp-grpc 4317, signoz-otlp-http 4318} derived from `lib/ports.nix`; no path components. Plus a per-service `expectations` registry (`grpc-url` = Go otlptracegrpc/Rust tonic, `http-url` = Python/Node/Docker SDKs, `http-host-port` = Go otlptracehttp — a scheme corrupts its self-built URL) covering all 9 current OTel-exporting services. Verified: 8 distinct bad-endpoint classes caught in a minimal eval (incl. the `OTLP_TRACES_ENDPOINT` variant and a container env); zero false positives on the live evo-x2 config. Limitation documented in-module: env vars baked into generated docker-compose files (manifest) are not scannable. Closes 16-20 report §f.23
- **`*_templ.go` committed-enforcement at three layers** — the AGENTS.md gotcha ("templ-generated Go files MUST be committed or Nix builds fail with `undefined: someFragment`") now has enforcement instead of documentation-only: (1) `scripts/check-templ-committed.sh` — git-index-based check (works in any repo, catches a staged `.templ` without staged `*_templ.go`), wired into `.githooks/pre-commit` (fast guard) and `.github/workflows/nix-check.yml`; (2) upstream in go-nix-helpers `modules/go-standard.nix`: a `checks.templ-committed` eval-time throw that fires in EVERY go-standard consumer's `nix flake check` — the flake source contains only tracked files, so walking it for `.templ` and checking sibling `*_templ.go` via `pathExists` sees exactly the committed set; zero cost for repos without templ files; 3 new module tests (117 total pass). Closes 16-20 report §f.24
- **zram fill monitoring + Discord alert (system-health + Gatus)** — with zram as the ONLY swap (28 GiB, no disk fallback), a full zram forces the kernel into page-cache reclaim — the documented BTRFS I/O storm precursor — and nothing watched it. The `system-health` collector now emits `system_zram_swap_fill_percent` (orig_data_size/disksize from `/sys/block/zram0/mm_stat`), `system_zram_swap_orig_data_bytes`, `system_zram_swap_disksize_bytes`, `system_zram_mem_used_bytes`, and the pre-computed `system_zram_fill_over_threshold` flag (≥90%). Auto-disabled on hosts without `zramSwap`; metrics are emitted ONLY when `/sys` is readable, so an absent metric fails the Gatus condition fail-closed (no phantom greens — the nvme phantom-zero lesson applied). New "ZRAM Fill" Gatus check (2m interval, matches the collector cadence) alerts Discord with the page-cache-reclaim context and remediation. Live-verified: current fill 19.9% → flag 0; simulated 95% → flag 1. Closes 16-20 report §f.26
- **Build cache GC + cache-key unification + sccache (`services.buildcache.gc`, `home.nix`)** — the build cache SSD hit 96% (198G/220G) ONE DAY after deployment. Root causes (verified from the cache contents itself): (1) `GOTOOLCHAIN=auto` silently downloaded go1.26.6 for go-codec's go.mod demand and forked the cache under a second key (15,415 duplicate entries in one day); (2) per-repo GOEXPERIMENT split every compilation 2x (75 flag-less repos vs 70 flagged); (3) Go's native 5-day LRU trim is mtime-based and gopls's `markUsed` refreshes mtimes on every analysis pass — with 5 gopls instances nothing ever ages out, so go-build is effectively unbounded; (4) cargo compiles dependencies into each project's private `target/` (35 GB of duplicated artifacts); (5) no size cap anywhere. Fixes: `GOTOOLCHAIN=local` + `GOEXPERIMENT=jsonv2` in sessionVariables (ONE cache key for all 162 repos — `jsonv2` gates only the `encoding/json/v2` package, v1 output byte-identical, verified on go1.26.5 where a v2 import without the flag is a hard build error); new weekly `buildcache-gc` service (Sun 05:00, `ioTier.maintenance`, runs as primaryUser: `npm cache verify`, `pnpm store prune`, stale rust targets >14d, and a `go clean -cache` nuclear guard at ≥90% usage so the disk can never wedge a build); sccache wired for Rust (`RUSTC_WRAPPER`, `SCCACHE_DIR=/mnt/buildcache/sccache`, 32G LRU cap) — content-addressed cross-project compile cache where project B's serde is a cache HIT (rustc never runs), which the per-project target-dir scheme structurally cannot do. Also: `scripts/report-goexperiment-gaps.sh` (21 satellite repos import `encoding/json/v2` but set the flag nowhere in nix — devShells broken for contributors without this machine's global env) and `scripts/buildcache-btrfs-convert.sh` (deferred maintenance-window runbook: zstd:1 ≈ 2x effective capacity + checksums convert the SandForce silent-corruption class into EIO → cache miss → rebuild). Full analysis + Pareto: `docs/planning/2026-08-15_21-23_SMART-BUILDCACHE-OVERHAUL.md`

- **macOS-style `open` command that works over SSH (`platforms/nixos/users/home.nix`)** — new `open` script (HM package) + `mpv` installed as the default for 11 audio MIME types (`audio/mpeg`, `flac`, `ogg`, `opus`, `wav`, `webm`, …; videos stay on Helium). Fixes two failure modes: (1) SSH sessions carry no graphical-session env, so `xdg-open` fell back to its browser waterfall and died with `no method available for opening 'file.mp3'`; (2) no audio player was registered at all, so even local `xdg-open` failed with `Failed to find default application for content type 'audio/mpeg'`. The wrapper rebuilds the session env when missing — derives `WAYLAND_DISPLAY` from niri's IPC socket filename (`niri.wayland-1.<pid>.sock` → `wayland-1`, falls back to any `wayland-*` socket for the Sway backup WM), sets `DBUS_SESSION_BUS_ADDRESS` from `$XDG_RUNTIME_DIR/bus`, and defaults `XDG_CURRENT_DESKTOP=niri`. It validates the target file's MIME association BEFORE launching (one actionable error line pointing at `xdg.mimeApps.defaultApplications`, instead of xdg-open's cryptic fallback output), absolutizes relative paths, and detaches via `setsid --fork` so the spawned app survives SSH logout. When no compositor session exists at all, it exits 1 with a clear message listing the searched socket locations. Verified via build + `nix flake check --no-build` + traced end-to-end in a simulated SSH env (no `WAYLAND_DISPLAY`): socket detection, `audio/mpeg → mpv.desktop` resolution, and detached launch all correct

- **Fullscreen shutdown countdown overlay (`services.shutdown-overlay`)** — new desktop module: when systemd has a shutdown/reboot scheduled and ≤60s remain (`thresholdSeconds`), a Quickshell layer-shell overlay covers EVERY monitor on the `Overlay` layer (above fullscreen movies and DMS), showing a giant pulsing countdown, the wall message, and a `sudo shutdown -c` hint. Click-through (`mask: Region {}`) so the session stays usable; polls `/run/systemd/shutdown/scheduled` every 200ms so `shutdown -c` hides it instantly. Runs as a second Quickshell instance (same 0.3.0 derivation DMS uses) in its own user service. Known limit: niri's compositor-drawn hotkey overlay ("Important hotkeys", visible only while a keybind chord is pending) still renders above it — niri draws that above the entire layer-shell Overlay layer (`niri.rs render_inner`), so no client can beat it

- **Build cache SSD (`/mnt/buildcache`)** — repurposed a healthy-but-idle SanDisk SDSSDA240G (USB 3.0, SandForce, 60 TBW) as the build-cache drive: new `services.buildcache` module (ext4 `data=writeback` mount + `buildcache-init` dir oneshot + `buildcache-metrics` SMART/usage textfile collector + 2 Gatus checks + smartd `-d sat` entries for both USB SSDs). Migrated ~115 GB of rebuildable caches off the QLC NVMe — the same churn class that drove the SLC-exhaustion WDT crashes: `GOCACHE` (64 GB), `GOMODCACHE`, `golangci-lint`, `goimports`/`go` (HM symlinks), pip, npm/pnpm store, Playwright browsers, and Rust `target/` dirs (`snapshots.nix` symlinks now point at `/mnt/buildcache/rust/<project>`, replacing the `/rust-cache` NVMe partition's role). Env vars in `platforms/nixos/users/home.nix` (NixOS-only — darwin unaffected). One-time migration: `nix run .#migrate-buildcache` (rsync + byte/file verification + trash-put sources). Also fixes stale-green monitoring: the collector always writes metrics even when the drive is absent. Analysis: `docs/status/2026-08-14_13-15_ssd-repurposing-options.md`
- **PMA daemon liveness watchdog** — new `pma-daemon-watchdog` (5-min timer): probes the project-discovery unix socket health endpoint and restarts `projects-management-automation` after 2 failed probes 30s apart. The PMA hang class is "hung but active" — the process stays running with the socket accepting connections that never get answered, invisible to systemd; before this, recovery required a manual restart (a 21h outage on 2026-08-14 503'd Overview the entire time). Runs as root (`systemctl restart`); Overview's `partOf` PMA bounces with each (rare) recovery restart

### Fixed

- **SigNoz→Discord routing regression — alerts silently dropped without route policies (2026-08-16)** — the entire alert pipeline was silently dead for ~30 min: SigNoz's custom dispatcher resolves receivers EXCLUSIVELY through route policies whose name equals the ruleId (`nfmanager Match()` → `GetAllByName`), and v1-API-provisioned rules never get policies auto-created (that path only runs for UI rules carrying `notificationSettings`). `preferredChannels` is not a route; `receivers: ["default-receiver"]` in `/api/v1/alerts` is display-only. Emergency live fix first (20 policies via direct API), then made durable: the provisioner (`_signoz-scripts.nix` v6) now converges route policies after rules — one policy per desired ruleId (`expression: 'ruleId == "<uuid>"'`, `channels: ["Discord Alerts"]`, tags `systemnix`+`auto-provisioned`), deletes orphans and duplicates filtered strictly by the `systemnix` ownership tag (untagged/user policies are never touched), and asserts exactly-one-per-rule + zero orphans (fail-loud). Live-proven twice on its first production run: (1) all convergence branches unit-tested offline against a stateful mock API (orphan/duplicate/create/skip); (2) the deploy's signoz restart silently WIPED all 20 API-created policies — the convergence loop recreated them within 13 seconds and the second run was fully idempotent (20× "Policy unchanged", 0 errors). Root cause + API shapes + the truncation-warning delivery probe are recorded in AGENTS.md
- **SigNoz `{{ $value }}` rendered empty — upstream template preprocessor exact-match quirk** — rule annotations used `{{ $value }}` (with spaces) but SigNoz's `preprocessTemplate` only special-cases the EXACT strings `{{$value}}`/`{{$threshold}}`; the spaced form was rewritten to `{{index .Labels "value"}}` → empty render ("current: " with no value in Discord). `mkRule` now emits `{{$value}}` (zero spaces, enforced by an inline why-comment); machine-proven via a `vector(42)` probe rule whose fired alert rendered `probe value=[42]`
- **SigNoz ruleSource stuck on localhost — signoz.yaml changes never restarted the service** — `alertmanager.signoz.external_url` was committed 03:08 but the running process (started 02:41) never restarted: `systemd.services.signoz` had no `restartTriggers`, so config changes silently never applied (the rules engine bakes external_url into every rule object at construction/startup). Added `restartTriggers = [ config.environment.etc."signoz/signoz.yaml".source ]` (adding the trigger changed the unit file → the deploy's switch restarted signoz and applied the URL) plus rule-file sources to the provisioner's triggers. Machine-proven: fired probe alert carries `ruleSource: https://signoz.home.lan/alerts/overview?ruleId=…` (was `http://localhost:8080/…`)
- **Gatus self-check read a phantom zero forever — rewritten to read gatus's sqlite directly** — the old meta-check curled gatus's HTTP API, which sits behind OIDC and returns 401 to unauthenticated curl; the `|| =0` fallback turned the OIDC failure into a permanently-green phantom 0. The `system-health` collector now queries `/var/lib/private/gatus/gatus.db` with `sqlite3 -readonly` (new `gatus.dbPath` option; DynamicUser hides `/var/lib/gatus` behind `/var/lib/private` on the host; WAL readonly works as root): sustained failure = endpoints with results but zero successes in the entire retained window (gatus self-prunes retention), staleness = db+wal mtime >15 min (gatus wedged or dead). Emits `system_gatus_meta_scrape_errors` (1 = the check itself failed — DB unreadable/query error) and, ONLY on success, `system_gatus_endpoints_in_error_long` + `system_gatus_results_stale` — absence fails the Gatus pat() conditions fail-closed (no phantom greens). The "Gatus Sustained Failures" endpoint now asserts all three. Post-deploy truth restored: the metric reports 6 sustained-failure endpoints (the known monitor365/browser-history outage family) where the old check showed a phantom 0 forever
- **Test artifacts from the routing-regression diagnosis removed** — chain-proof test rule + its policy + one orphaned policy (rule deletion does not clean name-matched policies — empirically confirmed, hence the provisioner's orphan pass); live state re-verified as exactly 20 rules / 20 policies / exact one-per-rule

## [2026-08] — WDT Crash Chains, oomd Wars & Monitoring Closure

### Added

- **Systemd hardening baseline raise** — `harden()` in `lib/systemd.nix` now sets 5 additional safe primitives via mkDefault (all overridable per-service): `RestrictRealtime` (shared), `ProtectKernelTunables`, `ProtectKernelModules`, `ProtectControlGroups`, `SystemCallArchitectures=native` (system-only). Verified compatible with btrfs CAP_SYS_ADMIN services (ioctls bypass these directives), display-watchdog `/sys/class/drm` writes (ProtectKernelTunables only mounts `/proc/sys` read-only), and system-health cgroup reads (ProtectControlGroups = read-only, not inaccessible). Deliberately excluded as unsafe global defaults: ProcSubset/ProtectProc (breaks pgrep users), RestrictAddressFamilies (service-specific), UMask (app-specific), PrivateDevices (audio/video need /dev). RestartSec/TimeoutStopSec conventions documented in `lib/systemd/service-defaults.nix`
- **I/O-throttled dev command wrappers** — `wrapWithMemoryLimit` (`lib/default.nix`) now sets `IOSchedulingClass=best-effort/7` + `Nice=10` (matching `ioTier.build`) on the transient scope. All `-memlimit` wrappers inherit I/O throttling automatically; new `go-build-memlimit` and `cargo-build-memlimit` wrappers added. Prevents QLC NAND I/O storms from cargo/go builds starving the desktop (Helium 3 FPS video drops)
- **GOMEMLIMIT runtime validation tooling** — new `scripts/validate-gomemlimit.sh`: one-command post-deploy validation comparing cgroup MemoryCurrent vs MemoryMax (OOM proximity) and `go_memstats_heap_inuse_bytes` vs GOMEMLIMIT (GC pressure) across all 7 GOMEMLIMIT services. SigNoz OTel collector anomaly fixed (384MiB was 37.5% of MemoryMax; normalized to 768MiB = 75%)
- **VendorHash drift checks across 11 LarsArtmann Go repos** — replicated dnsblockd's `vendor-hash` FOD-realization check (interpolates `.goModules` into runCommand; stale hashes fail fast without compiling) in browser-history (server+agent), crush-daily, file-and-image-renamer (main+filechange), DiscordSync (discordsync+cqrs-lint), art-dupl, branching-flow, go-cqrs-lite (cqrs-lint+benchstat), go-humanize-linter, go-structure-linter, project-meta, projects-management-automation. **Caught and fixed 5 genuine stale hashes** (browser-history server+agent, filechange, benchstat source+vendorHash) plus a missing publicDeps entry (go-codec in browser-history) on first run
- **Browser-history registration lock (single-user)** — `POST /auth/register` was open to anyone on LAN. Now gated by `MaxUsers` config in cqrs-htmx `ServiceConfig` (0=unlimited, N=N users max; generalizes the requested `registration_open` boolean — auto-closes after the Nth user, no flag-flip deploy needed). Gate checks `readModel.Count() >= maxUsers` in `Service.Register()` and returns `ErrRegistrationClosed` (HTTP 403). Coverage is complete: OAuth2 (Pocket ID) first-login auto-provisioning is gated by the same cap in `OAuth2Service.matchOrCreateUser` (`usermgmt.oauth2.registration_closed`, 403), and the count-check-then-dispatch window is serialized by a shared registration mutex in both paths (closes the TOCTOU for concurrent registrations). Existing users can always log in (external-account and email matches bypass the gate). browser-history exposes `MAX_USERS` env (default 1, documented in README + docs/configuration.md); SystemNix `browser-history.nix` sets `MAX_USERS=1` explicitly. Upstream tests: 3 register-cap service tests + 5 OAuth2 gate service tests + 2 HTTP 403 handler tests + 1 mixed-concurrency regression test; full `usermgmt` suite + `-race` pass. **Deploy blocker:** requires new cqrs-htmx + browser-history tags (includes breaking `NewOAuth2Service` signature change), then flake input bump
- **dnsblockd memory limit raise (2G→4G)** — dnsblockd was being oomd-killed 730x/day (1,591 since boot) because 2G was too tight for Go GC + OTEL cardinality + SQLite tracking pages. GOMEMLIMIT raised 1500MiB→3GiB to match. PMA MemoryMax confirmed at 8G (already set). Root cause: PMA's 6.6 GiB page-cache reclaim drives system-slice pressure to 65%, triggering oomd's 50%/20s kill threshold on dnsblockd as the largest non-exempt target
- **Auth/DNS gate helpers (`mkOidcGate` / `mkDnsGate`)** — two composable Nix helpers in `lib/default.nix` that eliminate duplicated curl/getent shell scripts across the codebase. `mkOidcGate` probes `https://auth.${domain}/.well-known/openid-configuration` via curl (120s timeout, TLS verified), returning `{ after, wants, serviceConfig.ExecStartPre }`. `mkDnsGate` probes DNS resolution via `getent hosts` with optional non-fatal mode. Both support `includeProvision` for Pocket ID provision dependency. Documented in `AGENTS.md`
