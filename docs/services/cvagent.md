# cvagent (CV repo code-derived evidence)

**Service:** `services.cvagent` — `modules/nixos/services/cvagent.nix`. A daily timer (05:53 + jitter, `Persistent`) running the [cvagent](https://github.com/LarsArtmann/Code-To-CV-Agent) CLI (flake input, also on PATH via `lib/lars-packages.nix`): scans the configured repository checkouts into an event-sourced sqlite fact store, then exports the mesh artifacts into the CV checkout (`/home/lars/projects/CV`):

- `data/cv/lars_artmann-en-cvagent.patch.json` — RFC 6902 variant patch adding keywords/projects the curated base does not list yet; render it with `cv render --variant cvagent` (verified end-to-end 2026-11-01: the CV repo's own loader applies the patch and the delta appears in the output).
- `data/projects-v2/<slug>.md` — one evidence page per project; pages carrying the generated marker are refreshed, hand-curated pages are never overwritten.

Why it exists: the CV repo's project stories and keywords were hand-maintained and drifted from what the code actually says. This timer keeps a grounded delta flowing: PMA's auto-commit daemon commits the export, and `cv-server-content-sync` ships `data/projects-v2/` (a content dir) on the next deploy — no manual step in the happy path.

## Ops

- **Run semantics** — per-repo scan failures WARN and the run continues (one weird checkout must not page at 05:53); the unit fails only when the mesh export fails or EVERY scan fails. Failures route via OnFailure (Discord) + system-health metrics (daemon-less doctrine; no vHost, no port, no Gatus check).
- **Deterministic + idempotent** — re-runs produce byte-identical artifacts (no timestamps); curated pages are preserved; the fact store is append-only (rescan replaces a repo's facts in the read model, the journal keeps history).
- **Manual run** — `systemctl start cvagent.service && journalctl -u cvagent.service -n 30`; agent shells (systemctl banned) trigger via `busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager StartUnit "cvagent.service" "replace"`; or by hand: `cvagent scan <repos...> --db ~/.local/state/cvagent/cvagent.db && cvagent mesh --target ~/projects/CV --db ~/.local/state/cvagent/cvagent.db`.
- **Curating a generated page** — edit it freely and delete the `<!-- generated by cvagent ... -->` marker line: the next export preserves it forever.
- **TRAP: never pass config to this unit via `CVAGENT_*` env vars** — cvagent's koanf layer claims the whole `CVAGENT_*` namespace as config, so e.g. `CVAGENT_DB=...` decodes as `db: "string"` and every command dies with `config.unmarshal` corruption (caught live in the 2026-11-01 smoke test; the unit bakes its values into the script text instead).
- **TRAP: the unit's PATH carries only `runtimeInputs`** — cvagent exec's `git` for history collection, and the script needs `mkdir`; neither rides a unit's default PATH. The 2026-11-04 05:56 run failed systemic on `exec: "git": executable file not found in $PATH` (all 6 scans, OnFailure paged) — fixed by adding `pkgs.git` + `pkgs.coreutils` to `runtimeInputs`. New external binaries the script or CLI shells out to must join that list.
- **Reviewing the keyword delta** — `cd ~/projects/CV && go run ./cmd/cv render --variant cvagent --out /tmp/delta.html`; promote anything real into `data/cv/lars_artmann-en.json` (the next export then dedupes it out of the patch automatically).
