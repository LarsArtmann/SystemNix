# cvagent (CV repo code-derived evidence)

**Delegated (2026-11-08, SUPERB phase-2 P1):** the wrapper/scan contract
(options + the cvagent-scan unit + timer shape, wrapper runtime deps,
config render) lives upstream at `Code-To-CV-Agent/nix/nixos-module.nix`,
imported via `inputs.cvagent.nixosModules.default` (`6ff68d3`, VM-test
proven round 9). `modules/nixos/services/cvagent.nix` layers site
specifics: repo checkout paths, mesh run wiring, ioTier/onFailure,
harden bounds, system-health + tmpfiles wiring.

**Service:** `services.cvagent` — `modules/nixos/services/cvagent.nix`. A daily timer (05:53 + jitter, `Persistent`) running the [cvagent](https://github.com/LarsArtmann/Code-To-CV-Agent) CLI (flake input, also on PATH via `lib/lars-packages.nix`): scans the **31 curated repositories** (`scan.repositories` — 23 meta-ranked Go projects + the 8 minecraft-era checkouts added 2026-11-15) into an event-sourced sqlite fact store, then exports the mesh artifacts into the CV checkout (`/home/lars/projects/CV`). The curated list is BINDING on the export too: the mesh is restricted to exactly these streams (v0.2.0; the printed line is `restricting export to 31 curated repositories`), so discovery-era legacy streams can never flood the patch again.

- `data/cv/lars_artmann-en-cvagent.patch.json` — RFC 6902 variant patch adding keywords/projects the curated base does not list yet; render it with `cv render --variant cvagent` (verified end-to-end 2026-11-01: the CV repo's own loader applies the patch and the delta appears in the output).
- `data/projects-v2/<slug>.md` — one evidence page per project; pages carrying the generated marker are refreshed, hand-curated pages are never overwritten.

Why it exists: the CV repo's project stories and keywords were hand-maintained and drifted from what the code actually says. This timer keeps a grounded delta flowing: PMA's auto-commit daemon commits the export, and `cv-server-content-sync` ships `data/projects-v2/` (a content dir) on the next deploy — no manual step in the happy path.

## Ops

- **Run semantics** — per-repo scan failures WARN and the run continues (one weird checkout must not page at 05:53); the unit fails only when the mesh export fails or EVERY scan fails. Failures route via OnFailure (Discord) + system-health metrics. The SCAN unit stays daemon-less (no endpoint to probe); the DASHBOARD unit is the monitored long-running surface (vHost + Gatus + federation above).
- **Deterministic + idempotent** — re-runs produce byte-identical artifacts (no timestamps); curated pages are preserved; the fact store is append-only (rescan replaces a repo's facts in the read model, the journal keeps history).
- **Schema caps are a LOCKSTEP PAIR (v0.2.0)** — the CV's `schema.json` bounds and cvagent's exporter mirrors moved together to 75 projects / 250 keywords; when the curated base grows past a bound, BOTH sides move in one change or the resolved variant breaks with a claims-sentinel error.
- **Manual run** — `systemctl start cvagent.service && journalctl -u cvagent.service -n 30`; agent shells (systemctl banned) trigger via `busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager StartUnit "cvagent.service" "replace"` — polkit DENIES this unprivileged (live 2026-11-04: "requires interactive authentication"): agents go through script-internal sudo, and the explicit `ss` signature is REQUIRED (without it busctl eats the unit name as the signature and dies "Unknown signature type c"): `sudo -n busctl call org.freedesktop.systemd1 /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager StartUnit ss "cvagent.service" "replace"`; or by hand: `cvagent scan <repos...> --db ~/.local/state/cvagent/cvagent.db && cvagent mesh --target ~/projects/CV --db ~/.local/state/cvagent/cvagent.db`.
- **Curating a generated page** — edit it freely and delete the `<!-- generated by cvagent ... -->` marker line: the next export preserves it forever.
- **TRAP: never pass config to this unit via `CVAGENT_*` env vars** — cvagent's koanf layer claims the whole `CVAGENT_*` namespace as config, so e.g. `CVAGENT_DB=...` decodes as `db: "string"` and every command dies with `config.unmarshal` corruption (caught live in the 2026-11-01 smoke test; the unit bakes its values into the script text instead).
- **TRAP: the unit's PATH carries only `runtimeInputs`** — cvagent exec's `git` for history collection, and the script needs `mkdir`; neither rides a unit's default PATH. The 2026-11-04 05:56 run failed systemic on `exec: "git": executable file not found in $PATH` (all 6 scans, OnFailure paged) — fixed by adding `pkgs.git` + `pkgs.coreutils` to `runtimeInputs`. New external binaries the script or CLI shells out to must join that list.
- **AI extraction (owner decision 2026-11-04; routing update 2026-11-17)** — `aiEnable = true` (default): every scan passes `--ai` plus a Nix-rendered `--config` file (`ai.model = glm-5.3-flash`, `ai.baseurl = http://127.0.0.1:8107/v1/zai` — the ai-meter proxy path-route, IN TREE since 2026-11-17 pending the next switch; the deployed v0.2.0 config still points at `https://api.z.ai/api/coding/paas/v4` directly, so metering of cvagent traffic starts at the next deploy). The key story moves with it: the real zai key rides ai-meter's upstream copy; the unit env carries a runtime-minted CLIENT key (`OPENAI_API_KEY` — NOT `CVAGENT_`-prefixed, so the env trap below does not apply). AI failures fall back to rule-based extraction automatically (extractor name recorded per fact — check `cvagent facts` after a run to prove AI facts actually landed; a silent all-rule-based run with `--ai` armed means the endpoint rejected us, likely the strict `json_schema` response format — a live 429 on go-filewatcher 2026-11-17 proved the fallback path works).
- **Credit ceiling (owner decision 2026-11-05, raised 2026-11-15)** — `aiDailyFactCap = 800`: run-level gate; if the fact store already holds ≥800 AI facts dated today, the ENTIRE run goes rule-based (WARN in the journal). 31 repos since 2026-11-15 (23 + 8 minecraft-era): normal day ≈ 620 AI facts (31 × ~20); calls ≈ facts/20 and linear in credits — a fact cap is a spend cap.
- **Credit ceiling note** — see the AI bullet: cap 800 since the 31-repo wave; a fact cap is a spend cap, and once the ai-meter route deploys, spend is ALSO visible in the meter (the known direct-hit gap closes).
- **Repo list (owner directive 2026-11-04; minecraft wave 2026-11-15)** — `meta list --sort-by importance`, importance ≥ 80, real code checkouts; templates/forks and the CV export target itself excluded; buildflow dropped 2026-11-05 (meta lists it at 95 but NO local checkout exists — first cycle failed on stat). 23 meta-ranked repos + 8 Artmann-Minecraft checkouts (below the cutoff, owner-added for CV evidence — the 2018-2020 game-server era now has 7 standalone curated CV entries; the 8 repos with CV stories only, teammate satellites and websites stay unscanned) = **31 total**, `TimeoutStartSec` 110min (full cycle ~90-105 min sequential at ~2.5-3 min/repo with AI; measured live 2026-11-17 manual run).
- **Reviewing the keyword delta** — `cd ~/projects/CV && go run ./cmd/cv render --variant cvagent --out /tmp/delta.html`; promote anything real into `data/cv/lars_artmann-en.json` (the next export then dedupes it out of the patch automatically).
