# timesheets (event-sourced timesheet CLI + API server)

**Deployed as the timesheets unit + protected vHost (2026-11-10).** `timesheet` is the CLI over an event-sourced timesheet store (create/add-entry/import) plus its API window `timesheet serve` (`modules/nixos/services/timesheets.nix`): binds **127.0.0.1:8109 only** (`ports.timesheets`), fronted by the registry vHost **timesheets.home.lan** (`vHost.layer = "protected"` — oauth2-proxy forward-auth for external clients, LAN bypass). The API has NO authentication of its own and carries billing data — the journal-serve posture. Upstream: `github:LarsArtmann/timesheets` (**PRIVATE** — CI deploy key `systemnix-ci-readonly`, key id 169358071, fp `SHA256:abRrdaeZaw6RpJHKsPbPZ1NQG2jtNURDoio0oUPDfiQ`, served from `NIX_DEPLOY_KEYS_BUNDLE_2` `@REPO timesheets`).

## Ops

- **Data home: `~/timesheets/` (evo-x2).** The SQLite event store `timesheets.db` is the TRUTH for recorded timesheets; the CLI is the primary write path (`timesheet create/add-entry/import --db ~/timesheets/timesheets.db`), serve is the API window onto the same single store — USER data outside `/var/lib` deliberately (journal books precedent): the unit runs as the primary user so CLI and daemon share one store with no uid drift.
- **Serving**: `http://127.0.0.1:8109` (loopback); from LAN/VPN **https://timesheets.home.lan** (oauth2-proxy protected; LAN bypass). Endpoints: `/readyz` (200 = domain aggregate green: SQLite ping + projection workers), `/healthz` `/startupz`, `/health` (go-health HTML dashboard, title "Timesheets"), `/version`, SSE at `/api/events`. **`/` 302-redirects to `/health` since 2026-11-15** (upstream e90e7a1): serve has no browsing UI of its own, so a bare root used to answer net/http's `404 page not found`, which reads as a broken deployment. Unknown paths still 404 — there is no catch-all, and the API/CLI remain the only timesheet surfaces. CSRF stays ON (token-based, proxy-safe — NOT origin-based, so the proxy does not break it). Graceful drain: SIGTERM → 10s window, `/readyz` answers 503 for the whole drain. The `/health` dashboard is styled by a **compiled Tailwind v4 stylesheet** served at `/health/dashboard.css` (upstream `0372bb8`: `scripts/build-dashboard-css.sh` + `dashboard.WithCSSPath` — without it the library falls back to the Tailwind Play CDN, whose runtime-injected `<style>` elements violate the dashboard's own strict CSP: unstyled page + console spam; if it ever renders unstyled again, suspect the compiled-CSS rebuild step first — the sentinel drift test upstream pins it).
- **Restore drill (RUN 2026-11-10, receipt live)**: `gunzip < /mnt/pool/backups/timesheets/timesheets-db-2026-11-10.db.gz > scratch.db && sqlite3 scratch.db "PRAGMA quick_check"` → `ok`, 13 `meta_*` event-store tables present. The backup is a complete, openable SQLite store, not a copy of a hot file. First artifact was produced 2026-11-10 by a cap-fixed backup run (see the runbook's CAP_DAC_READ_SEARCH note); nightly timer 03:20 carries it from there.
- **vendorHash drift class**: NON-FOLLOWER — root nixpkgs bumps cannot re-hash its FOD. Re-stales only when timesheets' own lock moves: probe at rev first (`nix build github:LarsArtmann/timesheets/<rev>#default`), then `nix flake lock --update-input timesheets`.

## Deploy

- **Prefetch locked private inputs BEFORE `sudo nixos-rebuild`** (verified 2026-11-22, v0.3.0, 3m59s end-to-end): root cannot ssh-fetch the ~56 private flake inputs (no user ssh-agent/keys for root), so the rebuild fails on fetch unless every locked rev is prewarmed in the ROOT daemon's store first. As `lars`: iterate SystemNix `flake.lock` nodes picking `original.url` values containing `ssh` with their `locked.rev`, then `nix flake prefetch 'git+ssh://git@github.com/LarsArtmann/<repo>?rev=<rev>'` per input — the SCHEME MUST be `git+ssh://`, NOT the lock's raw `ssh://` (raw scheme failed 96/96 prefetches). Only then `sudo nixos-rebuild switch --flake .#evo-x2 -L`. Capture background-command exits with `PIPESTATUS[0]` — `cmd | tail; echo EXIT=$?` reported false `EXIT=0` twice during this deploy. Post-switch: verify `/readyz` 200 + `/version` matches the deployed timesheets commit, then `sudo -n systemctl start timesheets-backup.service` to close the deploy-day backup window.
