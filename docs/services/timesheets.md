# timesheets (event-sourced timesheet CLI + API server)

**Deployed as the timesheets unit + protected vHost (2026-11-10).** `timesheet` is the CLI over an event-sourced timesheet store (create/add-entry/import) plus its API window `timesheet serve` (`modules/nixos/services/timesheets.nix`): binds **127.0.0.1:8109 only** (`ports.timesheets`), fronted by the registry vHost **timesheets.home.lan** (`vHost.layer = "protected"` — oauth2-proxy forward-auth for external clients, LAN bypass). The API has NO authentication of its own and carries billing data — the journal-serve posture. ## Ops

- **Data home: `~/timesheets/` (evo-x2).** The SQLite event store `timesheets.db` is the TRUTH for recorded timesheets; the CLI is the primary write path (`timesheet create/add-entry/import --db ~/timesheets/timesheets.db`), serve is the API window onto the same single store — USER data outside `/var/lib` deliberately (journal books precedent): the unit runs as the primary user so CLI and daemon share one store with no uid drift.
- **Serving**: `http://127.0.0.1:8109` (loopback); from LAN/VPN **https://timesheets.home.lan** (oauth2-proxy protected; LAN bypass). Endpoints: `/readyz` (200 = domain aggregate green: SQLite ping + projection workers), `/healthz` `/startupz`, `/health` (go-health HTML dashboard, title "Timesheets"), `/version`, SSE at `/api/events`. CSRF stays ON (token-based, proxy-safe — NOT origin-based, so the proxy does not break it). Graceful drain: SIGTERM → 10s window, `/readyz` answers 503 for the whole drain.
- **Restore drill (RUN 2026-11-10, receipt live)**: `gunzip < /mnt/pool/backups/timesheets/timesheets-db-2026-11-10.db.gz > scratch.db && sqlite3 scratch.db "PRAGMA quick_check"` → `ok`, 13 `meta_*` event-store tables present. The backup is a complete, openable SQLite store, not a copy of a hot file. First artifact was produced 2026-11-10 by a cap-fixed backup run (see the runbook's CAP_DAC_READ_SEARCH note); nightly timer 03:20 carries it from there.
- **vendorHash drift class**: NON-FOLLOWER — root nixpkgs bumps cannot re-hash its FOD. Re-stales only when timesheets' own lock moves: probe at rev first (`nix build github:LarsArtmann/timesheets/<rev>#default`), then `nix flake lock --update-input timesheets`.
