## Google Sync (Drive → HDD pool mirror)

**STATUS: DORMANT (2026-08-31 finding, confirmed 2026-09-11) — NOT deployed.** `services.google-sync.enable = false` and NO units exist on evo-x2; nothing below describes a running service. Go-live is a USER sequence (interactive Google OAuth + `rclone authorize` per account + filling the sops scaffold): (1) Google Cloud OAuth client (Drive API, publishing status "In production"), (2) `rclone authorize "drive"` once per account, (3) fill the 3-remote placeholder in `platforms/nixos/secrets/google-sync.yaml` — every remote section needs `type = drive` (rclone `listremotes` HIDES sections without it — the config-check would fail "remote missing" despite the section existing), (4) flip `enable` + `nix run .#deploy`, (5) verify the ~1.9 TB seed. Do not trust this section as live until that checklist completes.

**Module:** `modules/nixos/services/google-sync.nix` (`services.google-sync`) — rclone one-way mirror of Google Drive to `/mnt/pool/backups` every 5 min (`interval` option), ONE SERVICE / MULTIPLE MIRRORS via the `mirrors` option (user layout 2026-08-18: `gdrive` = ~1.9 TB private My Drive, `gdrive-shared` = private shared-with-me, `gwork` = small Workspace work account). **Ships DISABLED** until the OAuth token is filled in (placeholder in sops `google_sync_rclone_config`, `platforms/nixos/secrets/google-sync.yaml` — must contain ALL three remote sections); a `google-sync-config-check` ExecStartPre fails fast with the go-live checklist pointer when the token is still a placeholder and verifies every configured remote exists in the INI (`rclone listremotes`, offline) — live-tested against synthetic configs.

- **Semantics:** Google Drive Desktop "Mirror" mode, minus its instant-deletion data loss: remote deletions park per-mirror in `/mnt/pool/backups/google-drive-deleted/<remote>/` (grace, 30d default) via `--backup-dir`. Grace tree MUST stay outside the synced destinations — rclone sync deletes local paths absent on the remote (a nested backup-dir deletes itself)
- **shared-with-me is a FOREST, not a tree** — its own rclone remote with `shared_with_me = true` in the config section; each shared item is a root (shared folders traverse normally). Someone unsharing a file = a deletion into grace, same as any remote delete. A Workspace team drive needs no module changes either: set `team_drive = <id>` in that remote's config section
- **Seed sizing (1.9 TB):** `TimeoutStartSec = 48h` (first seed runs many hours to days; converging runs take minutes and timer ticks don't stack) and `MemoryMax = 2G` (`--fast-list` holds ~1KB/object in memory — a 1.9 TB library can be 500k+ files)
- **rclone config is a sops FILE, not env vars** — the OAuth token is a JSON blob; systemd `EnvironmentFile` quote-stripping around embedded `"` is a footgun. Passed via `Environment = RCLONE_CONFIG_PATH=<sops path>`; rclone refreshes access tokens in memory (read-only config is fine)
- **Google OAuth client MUST be in "In production" publishing status** — testing-mode clients expire refresh tokens after 7 days (silent auth death a week after setup). Unverified-but-production is fine for personal use
- **`--drive-skip-checksum-gphotos` is load-bearing** — photos stored IN Drive get re-encoded server-side without md5 updates; without the flag those files re-download on every sync
- **`--fast-list` mandatory** for large trees (39k files: 22 min → 4 min listing); Google-native docs export as pdf (`exportFormats` option)
- **Mirror dirs are created by the mount-gated `google-sync-dirs` oneshot** (atticd-storage-dir pattern), NOT by an ExecStartPre mkdir inside the sync unit: systemd sets up mount namespacing BEFORE ExecStartPre, and a `ReadWritePaths` entry pointing at a missing path aborts the unit with `status=226/NAMESPACE` (live incident 2026-08-18 00:33 — a force-enable verification build was manually activated enabled OUTSIDE `nix run .#deploy` (no profile generation trail; banned in Critical Rules) and crash-looped 4× on this until the system-686 deploy at 01:21 brought the disable). deploy.sh restarts the oneshot after switches
- **Freshness:** the script touches `/var/lib/google-sync/last_success`; registered in `backup-coordination` (maxAge 25h) → the global `backup_all_healthy` Gatus check alerts. The mirror tree itself is NOT monitorable via backup-coordination (it checks top-level FILES only; a mirror is a dir tree)
- **Google Photos CANNOT ride this via API** (Library API serves originals only to the uploading app since 2025-03-31; rclone gphotos backend Tier 5, gphotos-sync archived). If a scheduled Takeout export ("Add to Drive" delivery) is enabled, its archives land inside this mirror automatically — immich-go (`nixpkgs`) can ingest them into Immich later

## Drive → Paperless/Immich ingest (2026-10-19)

**Module:** `modules/nixos/services/drive-paperless.nix` (`services.drive-paperless`) — hourly oneshot that scans the google-sync mirror trees and routes by extension: DOCUMENT types (pdf/doc/docx/odt/ods/xls/xlsx/ppt/pptx/txt/rtf/html/htm/eml/epub/md) upload into Paperless-ngx via the DRF API (`POST /api/documents/post_document/` — accepts correspondent/tags/title/created as multipart fields, verified against the pinned paperless-ngx 3.3.1 source); with `ingestImages = true`, raster images (jpg/jpeg/png/tiff/tif/webp/gif/heic/heif/avif/bmp) route to IMMICH via `POST /api/assets` instead (multipart `assetData` + required ISO `fileCreatedAt`/`fileModifiedAt` + `filename`, `x-api-key` auth — contract verified against the DEPLOYED immich 3.3.3 dist source 2026-10-19: v3 dropped `deviceAssetId`/`deviceId`, dedup is checksum-based, byte-identical duplicates answer 200 `status=duplicate`). Ships dormant COUPLED to google-sync: `configuration.nix` sets `drive-paperless.enable = config.services.google-sync.enable` — ONE go-live flip brings up mirror AND ingest; its `sources` default 1:1 from `google-sync.mirrors` (gdrive / gdrive-shared / gwork with account-named correspondents + per-remote tags + the global `google-drive` tag; the hyphenated `gdrive-shared` tag slugs to `meta_gdrive_shared` in the rendered bash — the slug function sanitizes `-`→`_`, pinned by the fixture).

- **API route, not the consume dir:** metadata is set atomically at upload; the consume dir would need global `PAPERLESS_CONSUMER_*` flag flips (recursive-consume + subdirs-as-tags) — instance-wide state changes that would bind every FUTURE consume-dir user to ingest semantics picked for this pipeline (none exist today — repo-grep verified 2026-10-19, self-review d5 — but the flags are the wrong shape regardless: per-upload metadata belongs at the upload call). Token minted per run by `drive-paperless-token` (bank-sync-paperless pattern: idempotent `drf_create_token` as the paperless user, tmpfs-only `/run/drive-paperless/env`, root `+`ExecStartPost chown handover)
- **Idempotence:** append-only journal `/var/lib/drive-paperless/journal.tsv` (`source TAB relpath TAB size`) gates re-uploads; a size change (new Drive revision) re-uploads as a new document; paperless dedups byte-identical content server-side anyway, so cross-account/cross-folder duplicates cost one rejected task, nothing more
- **Storm discipline:** `batchSize` 200/run + hourly `Persistent` timer + `ioTier.background` — a 1.9 TB tree can be six-digit files; unbounded walk+upload in one transaction is the IO-storm class this box forbids. `TimeoutStartSec=30min` (batch is disk-read-bound on the HDD pool)
- **Fail-loud:** any upload failure (paperless OR immich) → unit exit 1 (onFailure Discord), `failed.log` in the state dir, `last_success` NOT touched → backup-coordination `drive-paperless` row (maxAge 25h) alerts via the global `backup_all_healthy` check. `shopt -s inherit_errexit` guards the metadata resolution (a dead API aborts instead of uploading blank correspondent/tags — proven by the fixture's broken-stub leg). `StateDirectory = "drive-paperless"` creates the state dir pre-namespace — without it the first live run dies at mkdir against root-owned /var/lib (self-review §d.1, fixed + eval-pinned 2026-10-19)
- **Images → Immich (`ingestImages` option, default OFF):** when enabled, image extensions NEVER reach Paperless — they upload to Immich with the API key from the `drive_paperless_immich_api_key` sops secret (`platforms/nixos/secrets/drive-paperless-immich.yaml`, ships as PLACEHOLDER — go-live: Immich → Account Settings → API Keys, scope asset.read + asset.upload, then sops --set; the run fails loudly with this pointer while the placeholder remains). The unit orders after `immich-server.service` and preflights `/api/server/ping` + `/api/users/me` — docs + images are ONE pipeline, a dead/key-rejecting Immich fails the run (onFailure) rather than silently skipping half the payload. Takeout ZIPs and videos stay extension-skipped either way; Google-native Docs/Sheets/Slides arrive as real PDFs via the mirror's `--drive-export-formats pdf`
- **Fixture:** `checks.x86_64-linux.drive-ingest-fixture` (`scripts/test-drive-paperless.sh`) — real rendered ingest wrappers with a PATH-stubbed curl (controlled API responses), covering: extension/size/newline-name skips, sorted batch cap drain, metadata fields + ensure-before-upload ordering, journal idempotence, revision re-upload, failure injection (exit≠0, no last_success), missing-source skip, the images→Immich routing legs (preflight-before-upload ordering, x-api-key + ISO fileCreatedAt/fileModifiedAt + filename fields, doc/image cross-routing exclusion, immich failure injection, hyphenated-tag slug pin, PLACEHOLDER-key rejection), and the google-sync config-check legs (placeholder fail, valid 3-remote pass, missing-remote fail). The check evals ISOLATED nixosSystems — independent of the evo-x2 graph; first green `.#checks` build 2026-10-19 (after the go-standard fix landed in-tree)
- **rclone INI needs `type = drive` per section** — rclone 1.75 `listremotes` HIDES sections without a backend `type` key (fixture-proven 2026-10-19): the real sops scaffold must carry `type = drive` in all three remote sections or the config-check fails with "remote missing" despite the section existing
