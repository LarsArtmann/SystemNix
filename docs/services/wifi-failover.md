## WiFi Failover (eno1 → wlan0 standby, enabled 2026-09-06)

**Module:** `modules/nixos/services/wifi-failover.nix` (`services.wifi-failover`, enabled in configuration.nix)

- **THE KERNEL DOES NOT REMOVE ROUTES ON CARRIER LOSS — only on admin down** (2026-09-06 live incident: cable pulled, Kittyspot WiFi connected on wlan0 with a metric-100 default route, yet ZERO internet — the static metric-0 `default via 192.168.1.1 dev eno1` stayed in the table and blackholed ALL traffic). The daemon (`wifi-failover-watch`, poll 1s) reads `/sys/class/net/<if>/carrier` (read error = no carrier), deletes the pinned eno1 defaults (v4+v6, never the fallback route) on carrier loss — the NM fallback route takes over instantly — and re-adds `default via ${networking.local.gateway} dev eno1` (metric 0 beats the fallback's 100 again) on carrier return. `startLimitBurst 5/300` + `onFailure` + system-health `monitoredServices`.
- **CARRIER-based, never ISP-probe-based** — dual-wan's route-health-monitor failover'd on 2×2s probe blips to 1.1.1.1 and was disabled for it; its ECMP would ALSO split packets over the metered phone hotspot. An eval-time assertion rejects enabling `dual-wan` and `wifi-failover` together (`config.services.dual-wan.enable or false` — the isolated-VM module eval lacks the dual-wan option tree). eno1 stays deliberately NM-unmanaged/static (see networking.nix).
- **`trustFallbackInterface` (default true)** adds wlan0 to `networking.firewall.trustedInterfaces` so LAN-equivalent service access survives failover (hotspot = user's own LAN, same trust model).
- **`ip route show` ANNOTATES routes of a carrier-down link with the `linkdown` keyword, and `ip route del` REJECTS it as garbage** ("either 'to' is duplicate, or 'linkdown' is garbage") — parsing a `route show` line and feeding it verbatim back to `del` silently fails exactly when the link is down (the first VM-test run caught the eviction doing nothing). The daemon strips `linkdown` tokens before deleting (`del_route_line`). DEBUG_POLL=1 env knob emits per-poll carrier/last-state journal lines for diagnosis.
- **VM test `tests/test-wifi-failover.nix` simulates cable pull via veth PEER admin-down** — peer down gives ethfail NO-CARRIER while staying admin-up with the route INTACT, the exact kernel state the bug rides (admin-down of the interface itself would let the kernel remove the route and test nothing). Asserts: missing-interface boot tolerance, daemon OBSERVED the up-transition (journal `carrier UP`) before the down test, pinned-route eviction with standby (metric 100) serving, restore to metric-0 primary, FAILOVER/RESTORE journal markers.
