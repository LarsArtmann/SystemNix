## GitHub Auto-Assign (6h issue/PR self-assignment, 2026-09-17)

**Module:** `modules/nixos/services/github-auto-assign.nix` (`services.github-auto-assign`) — every 6h (`*-*-* 00/6:00:00` + 10min jitter, `Persistent`) runs `gh search issues|prs --owner LarsArtmann --state open --no-assignee --archived=false` (2 search calls cover ALL owned repos — no per-repo loop) and assigns every hit to `@me` via `gh issue|pr edit --add-assignee "@me"` (0.5s politeness sleep). Daemon-less: no HTTP endpoint, so monitoring = OnFailure (Discord) + `system-health.extraMonitoredServices` (cv-scan pattern). Enabled in configuration.nix. **DEPLOYED LIVE 2026-09-17 evening (system-782)** after the lock-war day; live-proof on the store binary: dry-run (43 forks identified, 0 fork leaks) → real run 7/7 assigned, 0 failures → convergence re-run clean (0 unassigned). The systemd layer (timer fire, ProtectHome gh auth as root context) proves itself at the first 6h tick — OnFailure pages if it doesn't.

- **Auth is the user's existing gh CLI — no new secret**: the unit runs as `primaryUser` with `harden { ProtectHome = "read-only"; }` so gh reads the 0600 `~/.config/gh/hosts.yml` (token scopes include `repo`; mr-sync ProtectHome precedent). `GH_NO_UPDATE_NOTIFIER`/`GH_PROMPT_DISABLED` keep gh non-interactive.
- **Search-API 1000 cap → self-convergence**: one search returns ≤1000 results; the bring-up backlog was ~1150 issues + 339 PRs and the manual prototype backfill (2 passes, 2026-09-17) assigned **1491 items with 0 failures**. Any future >1000 backlog converges across consecutive 6h runs by design. `TimeoutStartSec = 45min` is sized for a full 1000-item pass (~1s/item incl. sleep).
- **Forks SKIPPED by default (`excludeForks = true`, owner decision 2026-09-17)**: the initial prototype backfill also self-assigned ~100+ items on FORKED repos (zustand, tsup, usehooks-ts, tailwind-merge, typespec-_, template-_, …) — flagged as a unilateral judgment mistake; a fork carries the UPSTREAM tracker, so self-assignment there is noise in the assigned-to-me view. The deployed script fetches `gh repo list --fork` (43 repos at bring-up) and skips hits on them; a failed fork-list fetch is SYSTEMIC (exit 1) — silently assigning to forks must not be possible. The flag only stops FUTURE assignments: the already-assigned fork items are untouched. Mass cleanup if wanted: `gh repo list LarsArtmann --fork --json nameWithOwner --jq '.[].nameWithOwner'` → filter a `gh search` hit list by repo → `gh issue|pr edit <url> --remove-assignee LarsArtmann`.
- **Thresholded failure paging (owner decision 2026-09-17)**: search or fork-list failure → exit 1 → OnFailure pages. Assignment failures page ONLY when systemic — ALL attempts failed, or ≥50% of a ≥10-attempt run failed (auth/network breakage). Individual item failures WARN-log and retry on the next tick — one permanently-weird item must not page every 6h forever.
- **`--archived=false` is load-bearing**: PATCH-assignment on archived repos fails; the search qualifier excludes them up front. Idempotence comes from `--no-assignee`: a run after a successful run finds nothing.
