## Installation

Immich is shipped as a NixOS module in
[nixpkgs](https://github.com/NixOS/nixpkgs/blob/master/nixos/modules/services/web-apps/immich.nix).
Add the following to your NixOS configuration to enable it:

```nix
{
  services.immich = {
    enable = true;
    mediaLocation = "/var/lib/immich";
  };
}
```

This provisions PostgreSQL with `pgvector`, Redis, and the machine-learning
service by default. For hardware-accelerated transcoding, add your GPU device
paths:

```nix
{
  services.immich.accelerationDevices = [ "/dev/dri/renderD128" ];
}
```

For any setting not exposed as a first-class option, use the `settings` option,
which accepts the same shape as the [config file][config-file]:

```nix
{
  services.immich.settings = {
    image.progressiveJpeg.enabled = true;
    ffmpeg.accel = "vaapi";
  };
}
```

Secrets can be loaded from a file by setting an attribute to
`_secret = "/path/to/file"` — the file is loaded via systemd's
`LoadCredential` mechanism and never enters the Nix store.

## Backups

The NixOS module does not currently ship a built-in database backup. You can
add one with a systemd timer that runs `pg_dump`:

```nix
systemd.services.immich-db-backup = {
  serviceConfig = {
    Type = "oneshot";
    User = "immich";
    ExecStart = "${pkgs.postgresql}/bin/pg_dump --clean --if-exists --dbname=immich > /var/lib/immich/db-backup-${builtins.substring 0 8 (builtins.toString builtins.storePath)}";
  };
};
# systemd.timers.immich-db-backup = { ... };
```

The media location should be backed up separately — the database only contains
metadata.

## Known issues

- [nixpkgs#490345](https://github.com/NixOS/nixpkgs/issues/490345) — changing
  `mediaLocation` after first install corrupts asset paths
- [nixpkgs#526809](https://github.com/NixOS/nixpkgs/issues/526809) — the
  built-in `immich-db-backup` uses the system `pg_dump`, which may be older
  than the server expects
- [nixpkgs#524881](https://github.com/NixOS/nixpkgs/issues/524881) — the
  machine-learning `wasmPath` persists a Nix store path across upgrades

For all other issues, file under
[`NixOS/nixpkgs`](https://github.com/NixOS/nixpkgs/issues) with the `nixos/immich`
topic.

[config-file]: https://docs.immich.app/install/config-file
[nixpkgs-issues]: https://github.com/NixOS/nixpkgs/issues?q=is%3Aissue+immich
```

# NixOS [Community]

:::note
This is a community contribution and not officially supported by the Immich
team, but included here for convenience.

Please report issues to the [NixOS/nixpkgs issue tracker][nixpkgs-issues].
:::

Immich is shipped as a NixOS module in
[nixpkgs](https://github.com/NixOS/nixpkgs/blob/master/nixos/modules/services/web-apps/immich.nix).
The module provisions PostgreSQL with `pgvector`, Redis, and the
machine-learning service by default, with declarative secrets, systemd
hardening, and reverse-proxy-friendly bind defaults.

## Requirements

- A 64-bit Linux system running NixOS (or `nixos-rebuild`-compatible)
- At least 6 GB of RAM and 2 CPU cores
- Optional: a GPU for hardware-accelerated transcoding (Intel/AMD VA-API, or NVENC)

## Step 1 — Enable the module

Add the following to your NixOS configuration:

```nix
{
  services.immich = {
    enable = true;
    mediaLocation = "/var/lib/immich";
  };
}
```

Rebuild with `sudo nixos-rebuild switch`.

## Step 2 — Hardware acceleration (optional)

List the GPU device paths you want Immich to use:

```nix
{
  services.immich.accelerationDevices = [ "/dev/dri/renderD128" ];
}
```

Add your user to the `video` and `render` groups if you want the
machine-learning service to use the GPU directly:

```nix
{
  users.users.youruser.extraGroups = [ "video" "render" ];
}
```

## Step 3 — Configuration

The `services.immich.settings` option accepts the same shape as the
[config file][config-file]. For example, to enable progressive JPEG encoding
and VA-API-aware transcoding:

```nix
{
  services.immich.settings = {
    image.progressiveJpeg.enabled = true;
    ffmpeg.accel = "vaapi";
  };
}
```

To load secrets from a file without exposing them in the Nix store, set the
attribute to `_secret = "/path/to/file"`:

```nix
{
  services.immich.settings.oauth.clientSecret._secret = "/run/secrets/immich-client-secret";
}
```

The file is read by systemd at service start via `LoadCredential`.

## Step 4 — Reverse proxy

The module binds to `127.0.0.1:2283` by default. To expose Immich behind a
reverse proxy, forward `https://immich.example.com` to the local port.

If you use Caddy:

```caddy
immich.example.com {
  reverse_proxy 127.0.0.1:2283
}
```

If you use nginx, refer to the [Post Installation][post-install] guide.

## Backups

The database only contains metadata — your `mediaLocation` is the source of
truth for assets. Back both up.

## Known issues

- [nixpkgs#490345](https://github.com/NixOS/nixpkgs/issues/490345) — changing
  `mediaLocation` after first install corrupts asset paths
- [nixpkgs#526809](https://github.com/NixOS/nixpkgs/issues/526809) — the
  built-in `immich-db-backup` uses the system `pg_dump`, which may be older
  than the server expects
- [nixpkgs#524881](https://github.com/NixOS/nixpkgs/issues/524881) — the
  machine-learning `wasmPath` persists a Nix store path across upgrades

For all other issues, file under
[`NixOS/nixpkgs`](https://github.com/NixOS/nixpkgs/issues) with the `nixos/immich`
topic.

## Why I'm not filing this myself

`immich-app/immich` is a project I don't have a contributor relationship with
and the fix at the receiving repo is just docs (everything else in the
SystemNix-side change is already in `modules/nixos/services/immich.nix`). Per
the `verify-before-filing` workflow, the right move is:

1. **File the issue first** (Artifact 1) — confirm the maintainers want this
   before doing the PR. The three existing `[Community]` stubs suggest they
   do, but the team's stated position is "Docker Compose is the recommended
   path; everything else is community-supported," and the docs site is
   officially-maintained content. The issue is the right place to ask "would
   you accept this PR?"

2. **If the issue gets a green light, file the PR** (Artifact 2) with Variant A
   as the page content (Artifact 3). If the reviewer pushes back on the
   minimal stub and wants walkthrough depth, fall back to Variant B.

3. **If the issue is rejected**, the answer is documented: NixOS install lives
   in nixpkgs as the source of truth, no docs page needed. The conversation
   thread is then the place where anyone else who wants to revisit the
   question can pick up.

No code changes were needed in this repo to make the case — the nixpkgs
module is already production-ready, SystemNix is running it, and the only
gap is a pointer from the upstream docs to the nixpkgs source.
