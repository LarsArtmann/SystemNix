## Principles (from the incident record)

- **Rotation, not redaction, is the real fix** — old commits survive in forks/caches; a rotated key makes every historical residue inert.
- **Never write a secret VALUE into docs, status reports, or commit messages** — the "manual sops step" pasted-key pattern is exactly how the 2026-06-11 Resend leak happened. Write `<REDACTED — paste key interactively>` placeholders.
- **Adding a new secret prefix ecosystem-wide? Add the scanner pattern FIRST, then re-scan full history** (`scripts/scan-history-secrets.sh`) — gitleaks' coverage gaps are how plaintext keys sail through.
- **Sops single-blob diff = rotation proof** — a value's ciphertext changes iff its plaintext changes; inventory the file's FULL top-level key list before claiming "only key X changed".
