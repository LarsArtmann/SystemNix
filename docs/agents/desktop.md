## Quickshell (DankMaterialShell)

Quickshell is a QtQuick desktop shell replacing Waybar, Dunst, Wlogout, polkit_gnome, **and rofi** (launcher, clipboard, keybinds, emoji, calc). Since 2026-10-04 DMS is also the SOLE polkit authentication agent — the niri-flake-shipped polkit-kde-agent-1 is disabled (see the Qt bullet below). Configured via DankMaterialShell's upstream HM module.

- **Input:** `dankMaterialShell` (github:AvengeMedia/DankMaterialShell/stable) — brings `quickshell` transitively, no separate quickshell input
- **HM module:** `platforms/nixos/desktop/quickshell.nix` — imports DMS upstream, sets `programs.systemnix-quickshell.enable = true`, enables `systemd.enable = true` (defaults to false!)
- **DMS plugins:** `pkgs/dms-plugins/` — 13 SystemNix-native widgets + 2 community launcher plugins (dms-emoji-launcher, DankCalculator) declaratively installed via DMS's `plugins` option with port-templated settings from `lib/ports.nix`. Community plugins use `fetchFromGitHub`. Each uses `PluginComponent` + `plugin.json`
- **DevShell:** `nix develop .#quickshell` for hot-reload QML development with `qmlls` LSP
- **Wallpaper management:** DMS owns wallpapers natively. awww is RETIRED. `dms-wallpaper-init` service seeds a random wallpaper from `~/.local/share/wallpapers/` (installed from `wallpapers-src` flake input) at session start. DMS derives cycling directory from current wallpaper's parent dir. `Mod+W` = `dms ipc call wallpaper next`. Dynamic theming (`enableDynamicTheming = false`) is DISABLED — matugen overrides Catppuccin Mocha (our global theme). Re-enable if committing to Material You dynamic colors. **Dangling-pointer self-heal (2026-09-14):** DMS stores the wallpaper as a bare FILE path — a deleted file leaves `wallpaper get` exiting 0 with a dead path (blank screen; hit when the auto-commit daemon baked a `~/projects/wallpapers` deletion into `53fe554`). The init script now re-seeds from the collection when the current path is missing/unset (healthy path still exits untouched). Test point wallpaper OUTSIDE `~/projects` — the daemon commits deletions there
- **dms-wallpaper-init needs `dms` in runtimeInputs** — The service calls `dms ipc call wallpaper next` but `dms` is NOT on PATH by default in a systemd service context. Must add `dankMaterialShell.packages.${pkgs.system}.default` to the script's `runtimeInputs`. Side effect: runtimeInputs dirs sit FIRST in the script PATH — a stubbed `dms` for testing must be sed-injected into the script text, PATH-shadowing cannot win
- **Waybar RETIRED:** Completely removed (import, package, service, scripts). DMS is the sole shell
- **Rofi migrated to DMS (2026-06-30):** niri's 5 rofi keybindings rewired to DMS IPC (`spotlight toggle`, `clipboard toggle`, `keybinds toggle niri`, `spotlight toggleQuery ":e"`, `spotlight toggleQuery "="`). Rofi leaked 7 GB and OOM-killed niri. Rofi config (`rofi.nix`) remains for Sway backup WM only. DMS service has `MemoryMax=4G` as defense-in-depth. Emoji via dms-emoji-launcher plugin (trigger `:e`), calculator via DankCalculator plugin (trigger `=`)
- **Runtime verified:** DMS owns `org.freedesktop.Notifications`, `org.gnome.ScreenSaver`, `org.kde.StatusNotifierWatcher` DBus names
- **DMS niri module:** Import `dankMaterialShell.homeModules.niri` for niri-specific integration (workspace IPC via `$NIRI_SOCKET`)
- **`inputs.nixpkgs.follows`** on the DMS input is MANDATORY — mismatched Qt causes runtime crashes
- **Shutdown countdown overlay (2026-08-14):** `modules/nixos/desktop/shutdown-overlay.nix` runs a SECOND Quickshell instance (`services.shutdown-overlay`, user service) that shows a fullscreen overlay on ALL monitors when `/run/systemd/shutdown/scheduled` has ≤60s left — `WlrLayer.Overlay` + `ExclusionMode.Ignore` + click-through `mask: Region {}` (DMS FrameWindow pattern). It reads the µs timestamp from line 1; `shutdown -c` removes the file and the overlay hides within 200ms. niri's built-in hotkey overlay ("Important hotkeys", compositor-drawn while a keybind chord is pending) renders above the ENTIRE layer-shell Overlay layer (`Niri::render_inner` pushes it before `Layer::Overlay`) — no client can top it; only session-lock/exit-dialog do. A standalone quickshell run from SSH needs `DISPLAY` set or it dies silently after a Gtk warning (session user services get both DISPLAY and WAYLAND_DISPLAY imported, so the unit is unaffected)
- **Offline banner (2026-10-16, EXTRACTED to github:LarsArtmann/offline-banner; v3 via the input rides the next switch):** `services.offline-banner` (user service, second-Quickshell-instance pattern) — the module lives in the `offline-banner` flake input (locked fff0b61; repo owns the QML, the options incl. `package`/`layerNamespace`, its own flake checks, and the module debts in its TODO_LIST); `modules/nixos/desktop/offline-banner.nix` is a thin wrapper (import + `layerNamespace = "systemnix:offline-banner"` live parity — what the niri-msg-layers recipes grep). Yellow top-strip on all monitors while offline, after 2 consecutive failed probes (~10 s debounce), hides on the first clean probe. **v2 behavior (owner request):** the strip is `WlrLayer.Top` + `ExclusionMode.Auto` with an ANIMATED height (InOutCubic 450 ms) — it claims the top edge and the DMS bar slides DOWN beneath it, sliding back up on recovery (do NOT revert to Overlay+Ignore: that covers the bar instead of pushing it). Caption "last online X ago" ticks 1/s (`unknown` until the first clean probe — never lies). **v3:** click-to-dismiss (whole strip, pointer-hand) slides it away for the rest of the outage; the next clean probe re-arms it. Probe is carrier-glob + ICMP to 9.9.9.9 (the dual-wan-plugin check), NOT `nmcli networking connectivity` — eno1 is NM-unmanaged (static IP), so NM connectivity reads "none" even while online (live-verified 2026-10-16); never "simplify" it back to nmcli. The unit sets `environment.PATH` with `mkForce` (bash + iputils only) because systemd's user-unit default PATH is defined via the same option and a plain set is an eval-hard conflict. Probe timeout must stay < probe interval (assertion). Deploy lesson (2026-10-16): stc does NOT start a NEWLY-ADDED user unit on a live session — it lands `enabled` but `inactive`; start it once by hand (`systemctl --user start offline-banner`), same class as the post-deploy dms restart. Demo/verification recipe (NO deploy needed): extract the module's shell.qml to a tmp dir and run a STANDALONE quickshell instance with the session env (`WAYLAND_DISPLAY`/`NIRI_SOCKET` via `systemctl --user show-environment`) + `OFFLINE_BANNER_PROBE_HOST=203.0.113.1 OFFLINE_BANNER_FAILURES=1`; `niri msg layers | grep offline-banner` must show the namespace — and make the harness FAIL LOUD on missing env (an `|| echo NO SURFACE` once laundered a connection error into a false "does not render" verdict). **v4 legs + phase ladder (2026-11-10, deployed pin a5673f7):** the banner tracks FOUR independent legs — link (carrier-glob + ICMP to 9.9.9.9, the v3 probe), tcp (`/dev/tcp` dial to 1.1.1.1:53), dns (`getent ahostsv4 one.one.one.one` — the glibc/NSS path applications actually use) — each with its own 2-failure debounce. Phase ladder: **degraded** (a leg down, another up — the gateway-polices-new-flow-ICMP class, 206 false-OFFLINE shows in 8h before the fix) = slim BLUE info-strip naming the down legs, NO sound, NO ledger entry, auto-fades after `OFFLINE_BANNER_DEGRADED_DWELL` (15 s), re-shows only on a NEW down-leg set; **offline** (link death / tcp+dns both down / all net legs down) = the yellow v3 alarm verbatim. State file is ADDITIVE: legacy keys unchanged, new `phase`/`legs`/`degradedLegs`/`degradedVisible`/`updatedAt` — consumers (waybar-style) must read the phase keys, never infer from legacy fields. State writes are ATOMIC (tmp+mv rename, 2026-11-10: the plain truncate-write had a real empty-file tear window caught by CI on x86_64). **PATH-phantom lesson (gen-995 live bug):** the mkForce'd unit PATH must carry REAL packages — `pkgs.getent`, NOT `pkgs.glibc` (glibc.bin stopped shipping getent in this nixpkgs; the dns leg failed all 1448 probes on gen 995 while every grep-based check stayed green because the test seams stub the whole probe) — upstream module-contract now RESOLVES timeout/getent/ping against the rendered PATH and is negative-tested at both layers; never "simplify" that gate back to a name grep.

## Clipboard + Snippets (PasteBot parity, 2026-10-15; extracted to github:LarsArtmann/dms-paste 2026-10-16)

PasteBot-equivalent muscle memory from macOS, built entirely on DMS primitives (no cliphist/wtype/ydotool/fuzzel). **Ownership split since the extraction:** the snippets plugin, the clipboard-parity settings, and the clipboard-modal patches live in `github:LarsArtmann/dms-paste` (consumed via the `dms-paste` flake input: `homeModules.dms-paste` + `lib.patchDms`); SystemNix keeps the niri binds, the weather patch leg, and the consumer-side audit (`pastebot-parity-audit.nix`). Plugin id: `paste-snippets` (was `systemnix-snippets`; the rename was free — the DMS state writer is broken on the pinned rev, so no persisted state existed under the old id).

- **Clipboard history `Mod+Shift+V`** (secondary `Alt+C`) → `dms ipc call clipboard toggle`. `clipboardEnterToPaste`/`clipboardClickToPaste` are true (mkDefaults from the dms-paste module) → Enter/click pastes DIRECTLY into the focused window like PasteBot; without them selection only copies. Paste keystroke is synthesized by the DMS Go daemon through the compositor's `zwp_virtual_keyboard_manager_v1` (niri implements it — verified via binary protocol strings; no uinput/input-group needed, works on XWayland windows too). Graceful fallback: if the compositor lacked the protocol, `pasteEntry` degrades to copy-only.
- **Snippets picker `Mod+Shift+C`** → `dms ipc call spotlight toggleQuery ":s"` — the `paste-snippets` launcher plugin (dms-paste repo `plugins/snippets/`, registered by `programs.dms-paste` in quickshell.nix). One `.txt` file per snippet in `~/.local/share/snippets/` (filename = name, content = payload, multiline by design; preview shows first line + `· N lines` marker). Enter pastes via `dms cl copy` + `dms cl send-paste` (also lands the snippet in clipboard history); Shift+Enter uses the launcher's native `getPasteArgs` path. **`:s > name`** saves the CURRENT clipboard as a new snippet (`dms cl paste > dir/slug.txt`, then `chmod 600` — saved clipboard content can carry secrets, and the dir sits inside the forever-pool-snapshotted `@` subvol; exposure decision pending docs/todo/desktop.md). **`:s -name`** trashes matching snippet files (runs `trash`, never rm; empty-name guarded so a bare `trash "$DIR/"` can never swallow the dir). Scan skips files >64K (framed TOO_LARGE marker; listed as inert hint rows, content never loaded into QML). Recency ordering is SESSION-SCOPED (in-memory; see the savePluginState bullet below). Calculator moved to `Mod+Ctrl+C` (`=` trigger unchanged).
- **`dms cl` CLI** (the daemon's clipboard surface, `dms cl --help`): `copy` (stdin/arg, records history), `paste` (clipboard → stdout), `send-paste` (synthesized Ctrl+V), `watch`, `history`, `get`, `delete`, `clear`, `search`, `config`, `export/import`. Live roundtrip verified 2026-10-15 (copy → history ID → search → delete).
- **Clipboard modal UI polish (2026-10-15/16, package-level patches)** — `lib.patchDms` from the dms-paste input (composed into quickshell.nix's `programs.systemnix-quickshell.package` default, weather leg chained after; Weather.qml precedent): no per-row "Text" caption for plain-text entries (`visible: entryType !== "text"` via perl), 2-line previews (`maximumLineCount: 2`), modal 650×550 → 880×620, itemHeight 72 → 68. Plus settings-side `clipboardVisibleEntryActions = ["pin"]` (default shows a 3-icon cluster on every row; all actions stay in the right-click context menu). Every patch has a `grep -q` guard — the build FAILS if upstream QML text drifts, and the guards also run as a build-time check in the dms-paste repo's own `nix flake check`. **Gotcha: the DMS package's Go build env has NO perl — `patchDms` adds `nativeBuildInputs = (prev.nativeBuildInputs or []) ++ [ pkgs.perl ]` itself** (cost one failed deploy, exit 127). Two `*-dms-shell-*` store paths in the closure are EXPECTED: the patched package (shell) + the raw input package (dms-wallpaper-init runtimeInputs — CLI only, no QML).
- **DMS 1.6.3 `savePluginState` is broken upstream — never use it ON THIS REV** (FIXED UPSTREAM 2026-10-11: issue #3611 + merged PR #3733; our pin 4a87e82 = 2026-10-07 predates it — on the next DMS bump, re-add persistence to the paste-snippets plugin in the dms-paste repo and delete the in-memory workaround, docs/todo/upstream.md bump row) — mechanism on this rev: `PluginService._flushStateToDisk` does `stateSaveFvComp.createObject(...)` which returns `false`, then `fv.loaded.connect(...)` throws `Property 'connect' of object false is not a function` — every call WARNs in the journal and persists NOTHING (the FileView writer is never created; `_stateWriters[id] = false` stays falsy so every flush retries and fails). The flush is timer-debounced (~75 s), so the WARN can land long AFTER the triggering call — do not mis-attribute it to the code running at WARN-time (cost a false "my reload re-broke it" hypothesis). systemnix-snippets deliberately uses in-memory recents until the bump. `loadPluginData`/`savePluginData` (settings-backed) are unaffected.

DMS launcher-plugin authoring traps (learned shipping systemnix-snippets):

- **Contract is `getItems(query)` / `executeItem(item)` / optional `getPasteArgs(item)`** — there is NO `search()` function (dms-emoji-launcher 1.7.x ships `getItems`; older references say `search`). Items: `{name, comment, action, icon, categories}` + arbitrary `_private` fields (survive to executeItem). `getPasteArgs` returning `["sh","-c",…,"copy",text]` enables the launcher's Shift+Enter copy+keystroke flow (Controller `copyProcess.onExited → pasteTimer`).
- **`QtObject` has NO default property — inline child objects fail** `Cannot assign to non-existent default property` at the child line and the plugin stays `[disabled]` with only a journal ERROR (PluginService:480). Background `Process` objects must be `property Process scanProcess: Process { id: scanProcess … }` (keep the id: nested bindings resolve inner properties lexically through ids, not through the property name).
- **plugin.json `id` MUST equal the nix `plugins.<attr>` key** or the `enabled: true` written to plugin_settings.json misses `getPluginSetting(manifest.id, "enabled")`. All embedded systemnix plugins + paste-snippets follow id == key == dir name; the community plugins (emojiLauncher, calculator) show `[disabled]` in `dms ipc call plugins list` yet still work because launcher instances are created on trigger-demand, bypassing the enabled gate.
- **A running DMS does not see NEW plugin dirs or settings.json changes from a deploy** — `dms ipc call plugins reload <id>` re-reads QML for EXISTING plugins but not first-time discovery or startup-loaded settings; restart the unit (pkill the `bin/dms -c` process — `Restart=always` supervises it; `systemctl --user restart dms` when available). Settings land in `settings.json` (SettingsData keys like clipboardEnterToPaste), per-plugin config in `plugin_settings.json` (read via `pluginService.loadPluginData(id, key, default)`), volatile state via `savePluginState` (separate `_state.json`).
- Debug entry points: `dms ipc call plugins list` (look for `[loaded]`), `journalctl --user -u dms | grep -i "component error"`, `dms ipc call settings get <key>` (in-memory truth, not file truth).
- **quotaboard bar widget (2026-11-02, first EXTERNAL-repo DMS plugin)** — the AI-quota dashboard plugin lives in `github:LarsArtmann/quotaboard` (Forgejo-primary, `dms-plugin/` there), NOT in `pkgs/dms-plugins/`; consumed as a HOME module (`quotaboard.homeModules.quotaboard` in quickshell.nix, dms-paste contract: the module only ASSIGNS into `programs.dank-material-shell.*`). `services.quotaboard` runs the Go server (user unit, `ports.quotaboard` = 8791 loopback); the widget polls `GET /api/quotas` (JSON projection, one doc for all providers) and renders `Z 43%  S 78%` — muted `·` per unconfigured provider, `!` in error color when the SERVER is down (distinct states by design). It is also the first plugin placed INTO the bar declaratively: `dmsPlugin.placeInBar` writes `settings.barConfigs` (the 12 systemnix plugins are installed-but-unplaced — bar placement lives in barConfig widget lists, and the default spec lists contain only built-ins; `dms ipc call settings get barConfigs` shows the in-memory default). Overriding barConfigs stomps UI bar customization on rebuild — same declarative-settings contract as the rest of `programs.dank-material-shell.settings`. Widget QML verified pre-deploy with `qmllint -I <dms-share>/share/quickshell/dms -I <quickshell>/lib/qt-6/qml` against the LIVE DMS store path (imports resolve, zero errors); stc does NOT start the newly-added user unit (offline-banner class) — `systemctl --user start quotaboard` once, and a dms restart is needed for first-time plugin discovery. **Widget-click lesson (2026-11-03/04, generalize to every bar widget):** NEVER route a pill's left click straight into `xdg-open` — a single-instance browser (Helium) receives the URL via its ProcessSingleton and opens a TAB in the existing (often background-workspace) window WITHOUT raising it, so on a multi-workspace compositor the click reads as dead (eight invisible dashboard tabs accumulated on workspace 5 before diagnosis). Click = DMS popout (anchored, visible on every workspace); browser = right-click or the popout's button. The popout contract: `popoutContent != null` ⇒ `hasPopout` ⇒ click opens via `PopoutManager.requestPopout`; `closePopout()` dismisses; Esc handled by PluginPopout.qml. **Env wiring:** keys ride `osConfig.sops.templates."quotaboard-env".path` (re-renders crush.yaml zai + crush-daily.yaml synthetic) via `services.quotaboard.environmentFile` — without it the API answers `state: unconfigured` and the widget renders muted. Poll cadence is per-instance tunable (QuotaSettings 10–120 s + jitter), so monitor battery should expect ~2 GETs per interval, not lockstep pairs. **Focus-on-open follow-up (2026-11-04, D4 ruling "focus on whatever it opens"):** the widget's `openDashboard()` now follows every open with a best-effort `niri msg --json windows` title poll ("quotaboard" token, ≤10 × 500 ms) + `focus-window --id` on the newest match — because `focus-new-windows` (this module) can NEVER cover the single-instance-browser case: a ProcessSingleton tab activation fires no `WindowOpened` event, so the parked window only changes its title. The bar process env carries `NIRI_SOCKET` + full session PATH, so the widget needs no extra env wiring; without niri the probe exits 1 and the widget degrades to plain `xdg-open`. Coverage split: COLD browser starts (new window ⇒ `WindowOpened`) stay covered by `focus-new-windows`; the widget's loop exists precisely for the tab-activation case that fires no event — the two mechanisms are complementary, neither subsumes the other.

## Focus-New-Windows (launch follow)

**Module:** `modules/nixos/desktop/focus-new-windows.nix` (`services.focus-new-windows.enable`) — user systemd service watching `niri msg --json event-stream` (smart-audio pattern), deployed live 2026-08-16

- **Purpose:** niri never moves focus to a window opening on another output (the `open-on-workspace` → `chat`/`media` on DP-2 case). The daemon calls `focus-window --id` on newly opened unfocused windows so spotlight launches take you there
- **`WindowOpenedOrChanged` fires for opens AND updates** — the daemon tracks known window IDs (seeded from the `WindowsChanged` snapshot, pruned by `WindowClosed`) so a title change on a background window never steals focus
- **`is_focused` gate:** niri-unstable already focuses same-output opens itself (verified live). The daemon only acts on cross-workspace/cross-output opens — same-workspace launches stay zero-touch
- **`startupGraceSeconds`** (default 10): windows opening right after session start are NOT followed (login autostart would otherwise drag focus across workspaces)
- **`skipAppIds`:** regex list (Python `re.search`) of app-ids that must never steal focus
- Cross-workspace `focus-window --id` verified live (switches active workspace). The true cross-OUTPUT case (DP-2 connected) is untestable from SSH — verify after DP-2 reconnect

## Smart-Audio (focus-following HDMI audio router)

**Module:** `modules/nixos/desktop/smart-audio.nix` (`services.smart-audio.enable`) — user systemd service, deployed live

- Python stdlib daemon watching `niri msg --json event-stream`; maps focused workspace → output → Radeon HDMI profile; switches via `wpctl set-profile` + `wpctl set-default`. HDMI audio profiles on the Radeon card are MUTUALLY EXCLUSIVE — profile switching (not just sink switching) is required
- **Device discovery is DYNAMIC (2026-08-31)**: `deviceName = "auto"` resolves the ALSA card offering HDMI profiles (the GPU audio function) from `pw-dump` at startup, retrying up to 120s; sink names use a `{card}` placeholder substituted with the resolved token (e.g. `pci-0000_c6_00.1`). The old hardcoded `pci-0000_c5_00.1` died to start-limit-hit after the post-crash PCI renumber (c5→c6, same class as the NIC-vanish / sd-letter traps) — never pin PCI addresses here again. Verified live: auto-resolved `pci-0000_c6_00.1`, routed DP-1
- **PipeWire OBJECT IDs DRIFT — resolve the device by NAME before every switch (2026-09-06 live incident: "audio doesn't follow to the TV")**: the daemon cached the device id at startup (Radeon=69); after device re-registrations id 69 became the RYZEN analog card, so every `wpctl set-profile 69 3` silently mutated the WRONG card (`check=False` swallowed it) — the HDMI profile never changed, the extra2 sink never appeared, and the daemon error-looped "sink not found" while ALSO flipping the Ryzen card's profile as collateral (killing the mic source on DP-1-bound switches). Fix: `resolve_device()` re-resolves by the stable `device.name` (with auto-scan fallback) before every profile switch, `wpctl` output is captured and logged on rc≠0, and sink-not-found logs the live hdmi node names. DP-1↔DP-2 both verified live post-fix. Class lesson: PipeWire numeric object ids are ephemeral; NAME is the stable handle — same doctrine as PCI addresses and sd-letters
- **Jack↔profile↔output mapping VERIFIED (2026-09-06, authoritative source `/proc/asound/card0/eld*`)**: DP-1 (LG HDR 4K monitor) = eld#0.1 = `output:hdmi-stereo-extra1`; DP-2 (LG TV SSCR2) = eld#0.2 = `output:hdmi-stereo-extra2` — the module defaults are correct. Diagnose jack wiring with `grep monitor_name /proc/asound/card*/eld*` (wpctl's `[monitor]` suffix on the sink description is cosmetic and can be missing on freshly flipped profiles); don't confuse it with a dead jack
- **niri `focus-workspace <number>` is ambiguous with named workspaces** — numeric refs resolve unexpectedly across outputs (verified: `focus-workspace 4` landed on an unnamed DP-2 workspace). Drive tests with workspace NAMES (`focus-workspace main` / `focus-workspace chat`)
- Supersedes the static WirePlumber profile-priority rules in `audio.nix` — RESOLVED 2026-09-19: the `51-hdmi-monitor-priority` block was REMOVED (it was doubly dead — its `alsa_card.pci-0000_c5_00.1` match pinned the pre-crash PCI address that renumbered to `c6` on 2026-08-31, so it matched nothing, and `device.restore-profile = false` would have re-applied priorities on every device event against the daemon's switches). smart-audio is the sole HDMI profile router; WirePlumber keeps its default `restore-profile` so device events re-apply the daemon's last choice
- **`pkgs.writers.writePython3Bin` runs a strict pyflakes/pycodestyle linter at build time** — use `pkgs.writeScriptBin` with a `python3.interpreter` shebang for daemon scripts (cost a full build+deploy cycle to learn)
- **Audio debugging tools (2026-08-22):** `alsa-utils` (speaker-test, aplay, amixer) and `pipewire` (pw-cat, pw-play, pw-cli) are in `linuxUtilities` in `base.nix` for audio routing verification. `speaker-test -c2 -twav` plays test tones on the default sink; `pw-cat -p /usr/share/sounds/...` pipes audio through PipeWire directly
- **TV HDMI input audio format: PCM, not Bitstream (2026-09-25)** — with the LG TV SSCR2 set to Bitstream, the PC's stereo-PCM stream audibly lost dialogue clarity (the TV routes plain PCM through a mismatched decode/DSP path); switching to PCM matched the sender and improved it. "DTV Audio Setting"/"Digital Sound Out" are tuner/ARC-scoped and INERT for PC-over-HDMI streams. Same-day diagnosis method for muffled dialogue: inspect the playing stream via `pw-dump | jq` (`media.class == "Stream/Output/Audio"` → `.info.params.Format[0].position`) — Helium negotiated proper FL/FR stereo on stereo YouTube, so a "muffled pirates" movie stream was the SITE serving a MONO re-encode, not the audio stack
- **Idle DPMS via swayidle (raised 2026-09-14):** swayidle has a 14400s (4h) timeout that calls `niri msg action power-off-monitors` (DPMS off) before the existing 43200s (12h) suspend timeout (was 1200s/20min until `af870305`; the deployed generation still carries 20min until the next `nix run .#deploy` — verify with `systemctl --user cat swayidle.service | grep ExecStart`). The user-reported "~5 min to black" predates the raise and is unexplained (deployed-generation drift or another timer — the post-deploy grep is the real check). `sway-audio-idle-inhibit` inhibits idle during audio playback, so the TV-as-audio-sink case is handled — DPMS won't fire while audio is playing. Any input (mouse/keyboard) turns monitors back on; no explicit `power-on-monitors` needed

## Desktop (DMS / Quickshell / Helium)

- **Never pull `graphical-session.target` into the user-manager boot transaction (2026-08-18 black-screen incident)** — any unit enabled via `default.target` that sets `Wants=graphical-session.target` starts the target at lingering boot (before SDDM exists), which starts `niri-session-manager` (`Requires=niri.service`) → a headless zombie niri with zero outputs.
