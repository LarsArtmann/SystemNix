## Flake Updates (local loop + weekly bot)

- **`nix flake update` walks all 387 lock nodes SERIALLY** (421 before the 2026-10-02 infra-follows dedup, see below) — Nix fetches/evaluates inputs one at a time during locking (Nix 2.31 release notes call it "serialized on-demand fetching"; still true in 2.34, Lix too). Warm-cache full sweep ≈ 40s of pure metadata round trips; the minutes-long pain is moved revs downloading serially (148 git+ssh nodes = one ssh handshake + `git fetch` each, 271 tarball nodes = one api.github.com lookup each). Parallel fetching exists ONLY as `nix flake prefetch-inputs` (Nix ≥ 2.31, thread pool sized by `http-connections`, default 25 — all 420 inputs in ~13s warm).
- **Why plain flake EVAL is slow here (ranked, 2026-09-29)** — every `nix fmt`/`eval`/`check` pays the same base latency (~30-90s warm, minutes cold), NOT a bug: (1) Nix removed the flake eval cache (~2.20 era) — every command re-evaluates the whole module fixpoint from zero, nothing incremental survives between invocations; (2) the ~390-node lock graph (421 pre-dedup, 2026-10-02) — forcing ANY output (even just `formatter`) pulls dozens of input flakes' flake.nix + module trees through the store; (3) the eval-time guard army is O(repo) BY DESIGN — gatus-pattern-lint reads EVERY module file, systemd-shape/port-registry/deploy-restart audits force every unit's rendered text, sops-key-audit reads every secrets file, catalog cross-check, dns-local assertions — the evo-x2 toplevel eval is a full-repo scan (the prevention-layer tax); (4) this repo's `formatter` output is itself eval-expensive — it wraps treefmt-full-flake with eval-time `builtins.readFile` of the wrapper + config string-patching (the `nix fmt` HTML-exclude machinery), forcing the treefmt wrapper store path to be present (a wrapper REBUILD after lock churn reads as "slow eval"); (5) the repo tree lives on QLC `@` — cold page cache turns the module scans into seeky QLC reads, and every concurrent agent session pays the same eval so sessions contend with each other. For `nix flake check` add (6): it evals ALL 37 VM tests incl. hermes/uv2nix, whose dependency-graph eval alone is tens of seconds. NO flag fixes this on Nix 2.34 — mitigations: batch eval-needing commands, keep the page cache warm, expect ~minutes for the first eval after lock churn (wrapper rebuild rides it). **Landed mitigation (2026-09-29): the pre-commit formatter leg + `scripts/fmt-cached.sh` memoize the resolved `.#formatter.$sys` store path** (`scripts/lib/precommit-eval-cache.sh`) — content-keyed on flake.nix/flake.lock/overlays/lib + nix version, so module-only commits (the agent-common case) skip the formatter flake eval entirely; GC'd-path MISS, no TTL (content-keyed), `PRECOMMIT_EVAL_CACHE=0` hatch, CI `nix fmt -- --ci` backstops drift, fixture-proven by `checks.x86_64-linux.precommit-eval-cache-selftest`. The `nix flake check` leg is deliberately NOT memoized (docs-only/no-staged fast paths already cover the cheap cases; a verdict cache on the primary gate is phantom-green risk for a thin win — decision recorded in docs/todo/pipeline.md).
- **Local loop doctrine (2026-09-29):** default to TARGETED updates — `nix flake update <input>` re-resolves only that subtree (the flake.nix per-input comments already govern which inputs may move). Full sweep = `nix flake prefetch-inputs && nix flake update` (prefetch warms unchanged revs in parallel; it CANNOT prefetch revs that are about to move, so moved inputs still download serially inside update — inherent until Nix parallelizes lock updates, tracked by NixOS/nix#9077). The weekly bot (below) owns full sweeps; local full sweeps should be rare.
- **Weekly bot**: `flake-update.yml` runs Mondays 06:00 UTC — `prefetch-inputs` → `nix flake update` → nixpkgs-node normalization → `flake check --no-build` → PR on `automated/flake-lock-update`. BLOCKED on `NIX_GITHUB_RO_TOKEN` (see CI auth bullet above) — without it the bot still dies on the first private `github:` tarball. Merge the bot PR weekly, then local deploys are `git pull && nix run .#deploy` with no update step at all.

## Infra follows & lock hygiene (2026-10-02)

**Why:** Nix locks one node per input-graph PATH — any root input that declares an infra dep (`flake-parts`, `treefmt-nix`, `nixpkgs`, `systems`, `flake-utils`) without a `follows` pin carries its own duplicate lock copy. That grew the lock to **421 nodes for 235 unique revs** (23× flake-parts, 18× treefmt-nix, …). The 2026-10-02 dedup collapsed it to **387** via a data-derived `infra-follows` group (attrpath follows lines at the END of the inputs attrset in flake.nix).

**Rules:**
- Eval-only deps (flake-parts, treefmt-nix, systems, flake-utils) are ALWAYS safe to follow — they never enter FOD hashes.
- `nixpkgs` follows change the consumer's build env — only follow inputs whose FODs were NOT validated against a foreign nixpkgs. Deliberate non-follows live in `lib/lock-audit.nix` `deliberate` (qmd bun-FOD, discordsync rollback, nsfw-classifier local checkout).
- NEVER follow Go source deps (`go-*` tarballs, `go-nix-helpers`) INTO tool flakes — changes vendored module content → vendorHash FOD mismatch (2026-08-25 got-hash drift class).
- **NEVER run bare `nix flake lock` on this repo** (2026-10-03): it performs a BLANKET re-lock — one such run mid-deploy-unblock produced a 241-line lock diff, floated a dozen inputs, and trampled every deliberate pin (enumeration-consistent revs had to be restored by hand). Pin-only moves: `nix flake lock --override-input <name> github:LarsArtmann/<repo>/<full-sha>`; everything else goes through targeted `nix flake update <input>` per the local-loop doctrine above.
- The lock CANNOT be computed: Nix's flake input parser rejects `let … in` and `//` merges on `inputs` ("expected a set but got a thunk") — follows must be literal attrset lines. That's why the group is a literal block, not a generator.

**Enforcement:** `lib/lock-audit.nix` runs at EVAL time (forced via `allEvalGuards` → `builtins.seq` in outputs) and throws when a root input re-grows its own infra lock node — a blanket lock wave that reintroduces dups bricks eval with a self-describing error instead of silently regrowing the lock. Also flags stale `deliberate` entries (table rot). `checks.x86_64-linux.lock-audit-selftest` pins the behavior with 5 fixture legs (clean/dup/drift/allowlisted/stale) — the gitleaks-coverage pattern: the audit's first live run caught a real miss (emeet-pixyd, whose lock entry was typo'd `emeet-pixd` pre-reconcile).

**Known residual (deliberate):** deep duplicates (a tool's copy of another tool locking infra — e.g. `discordsync → art-dupl_3 → flake-parts_*`) are NOT fixable from SystemNix; they need `follows` in the upstream LarsArtmann tool repos (queued in TODO_LIST). `flake-compat` (7×) and `git-hooks` (5×) dups need root-input promotion first (rev-drift risk for 5 repos' pre-commit evals) — also queued.

## Cross-platform eval coverage (2026-09-28)

**Cross-platform eval coverage (2026-09-28):** the pre-commit hook AND the CI eval step run `nix flake check --no-build --all-systems` — plain `flake check` on x86_64-linux SILENTLY omits aarch64-darwin, which once let 8 apps (Linux-only runtimeInputs: systemd/procps/efibootmgr/btrfs-progs/glibc), the `quickshell` devShell (dms-shell is upstream Linux-only), and `borg-restore-drill-fixture` (`nixosSystem { inherit system; }` with a darwin system) eval-break on the Mac while every gate stayed green. Rules: (1) apps/devShells whose runtimeInputs carry Linux-only nixpkgs go in the `lib.optionalAttrs pkgs.stdenv.hostPlatform.isLinux` block in `flake.nix` (cross-platform ones like validate/fix-nixpkgs-lock/pocket-id-login-code stay ungated); (2) checks that call `nixosSystem` must pin `system = "x86_64-linux"`, never `inherit system` — the eval is platform-independent, and pinning keeps the negative cases live on BOTH checking platforms; (3) the darwin eval delta is ~1s, so `--all-systems` is cheap. Also: `go-cqrs-lite` has NO `systems` input anymore (flake-parts native) — don't re-add `systems.follows` (dead override, warns on every nix invocation).

## Nix & Nixpkgs

- **SystemNix overlays can NEVER reach packages built inside followed input flakes — and a fix must CHANGE the affected drv path, evaluated from the CONSUMING flake** (2026-09-20, nodejs-slim saga): `hermes-agent`'s flake evaluates its packages against the FOLLOWED root nixpkgs via `inputs.nixpkgs.legacyPackages` — OVERLAY-LESS (chain proven by `nix why-depends --derivation`: toplevel → system-path → hermes-agent → nodejs-26-npm → nodejs-26.9.0 → nodejs-slim-26.9.0). Fixes for such chains belong in the input's own flake or via the lock. Verification doctrine: (1) **drv-path-diff** — any override/fix must change the failing derivation's path evaluated from the CONSUMING flake; eval-green alone is the weakest signal; (2) **harmful-shim-lifecycle** — a shim whose own comment says "drop once the lock carries it" and SURVIVES that condition actively breaks substitution (on nixpkgs 20b1ddd the nodejs shim forked a THIRD drv no cache serves, forcing 2 from-source nodejs builds; removed in `1bfe5ae2`).
- **`mkMerge` on flake-parts top-level `config`** — Does NOT work; use inline config or imports. `mkMerge` on `serviceConfig` inside `systemd.services.<name>` IS safe.
- **`//` on `serviceConfig` discards priority** — Shallow merge clobbers `mkDefault`/`mkForce`. Always use `lib.mkMerge [...]`. Enforced: `scripts/audit-serviceconfig-merge.sh` (pre-commit + CI, selftesting) rejects `serviceConfig = X // Y` source lines
- **`//` between module-config branches that share the `services` key keeps ONLY the last branch** (2026-09-14, integration.nix): `config = { ... } // optionalAttrs (...) { services.a.x = …; } // optionalAttrs (...) { services.b.y = …; }` is a SHALLOW merge — every branch carries the top-level `services` key, so all fan-outs except the LAST silently vanish (live: only the pocket-id branch fired; miniflux's vHost/checks/tile/backup/monitoring went dark while evals stayed green). Same class as the `serviceConfig = X // Y` rule, one level up. Combine cross-module config branches with `lib.mkMerge [ base (lib.optionalAttrs (options ? services.a) {…}) … ]` — never a `//` chain
- **A registry entry with `subdomain` + `port` + `vHost.layer != "none"` RENDERS A VHOST THAT OVERRIDES THE HAND-WRITTEN ONE** (2026-09-15, paperless): caddy.nix merges hand-written `virtualHosts` with the registry's `extraVHosts` — a registry plain-layer entry for `paperless` silently REPLACED the hand-written vHost and DELETED its `/admin/*` 403 hard-block (SSO-only defense), while evals stayed green and the vHost count was unchanged. Rule: whenever a vHost must stay hand-written (custom blocks: paperless /admin, seo GSC exemption, dnsblock redirect pair, monitor @noCache, timers file_server), the entry MUST set `vHost.layer = "none"` — it keeps DNS + tile derivation while caddy owns the proxy. Caught only by the baseline diff — never trust "evals green" for surface-preserving refactors (see the worktree-baseline gotcha below).
- **Duplicate entries in `monitoredServices ++ extraMonitoredServices` = duplicate metric series = node_exporter rejects the WHOLE textfile** (2026-09-15, pocket-id): the registry fan-out appends unit names to `extraMonitoredServices`; a unit left in the default list while its entry sets `monitored = true` produces two `system_service_state{service="X"}` lines — the whole system_health.prom goes dark and every dependent Gatus check reds out fleet-wide. Coupling rule: removing a unit from the default list and setting the entry's `monitored = true` are ONE atomic change. Final default list (2026-09-15): [monitor365, monitor365-server] only — disabled services keep default-list monitoring (missing-unit-tolerant) because their enable-gated entries vanish.
- **Surface-preservation baselines: eval a PRE-MIGRATION GIT WORKTREE, not /tmp files** (2026-09-15) — /tmp baseline JSONs die to tmp cleaners and go stale relative to lock churn; the reproducible method is `git worktree add /tmp/pre-mig <pre-change-commit>` + `nix eval` the same option paths in both trees, then set-compare (order-insensitive for endpoint/tile lists; `logoFile`-style store-path diffs from old-lock source hashes are noise, not drift). This is what caught the paperless /admin deletion — per-file "looks right" inspection did not.
- **`with pkgs;` hides missing attrs** — Falls through to enclosing scope on missing attrs. Use explicit `pkgs.` prefixes.
- **`lib.types.path` on multi-GB runtime files is doubly wrong — use `types.str` + quoted literals (llama-vlm, 2026-09-19)** — `types.path` copies the referenced file into the store when the config is built, and unquoted absolute-path literals (`modelPath = /data/ai/...`) abort pure eval with `access to absolute path ... forbidden in pure evaluation mode`. For values only ever string-interpolated into ExecStart args, declare `types.str` and quote the literals. A parallel session's fresh `types.path` declaration blocked EVERY deploy on the box (eval blockers are fleet-wide, not per-feature) until the type was flipped
- **go-standard's `proxyVendor` option defaulted `true` while prepared-source builds force it `false` at render — every deps consumer warned 7×/eval with nobody misconfigured (fixed upstream 2026-09-30, `go-nix-helpers` ≥ `a15d726`; re-locked in SystemNix same day, 0 warnings verified)** — the fix pattern is `go-standard.proxyVendor = lib.mkDefault (cfg.deps == { })` at the module's TOP-LEVEL config (option scope); a `let`-binding inside `perSystem` defines a dead local and ships silently inert (the first fix attempt was pushed unverified in the wrong scope and cost a second commit). Verify-then-push: a targeted eval (warning count before/after + churn-guarded toplevel drvPath A/B) proves render-neutrality BEFORE committing; drvPath A/Bs on the shared tree are only valid with `git rev-parse HEAD` + `git status --short` snapshots on BOTH sides — parallel-session churn poisons sequential evals.
- **`buildGoModule` silently drops unknown `env` attrs** — Only forwards a whitelist (`CGO_ENABLED`, `GOWORK`, etc.). Use `export VAR=value` in `preBuild` for anything else.
- **`buildGoDir` swallows build-constraint errors** — Returns 0 with empty output. Add post-build assertion that `$out/bin/` is non-empty.
- **flake-parts `mkFlake` does NOT accept a bare list** — Use `{ imports = [ ... ]; }` attrset instead. Nested lists crash evaluation.
- **`builtins.toString null` = `""`** — Does NOT throw. `config.users.users.<name>.uid` is `null` at eval time for `isNormalUser`. NEVER use it in slice/service names without null-checking.
- **deadnix `--fix` removes lambda params** — Does NOT add `...` when removing all params. Verify output leaves `...` in patterns whose callers pass extra attrs.
- **stdenv runs flake-check scripts with `shopt -s nullglob` — a command stored in a variable and expanded unquoted (`$strip "$file"`) silently DROPS every word containing glob chars, turning the check phantom-green (2026-08-27, `signoz-query-lint` v1)** — a `strip="grep -v '^[[:space:]]*#'"` loses its single quotes at expansion time (they are DATA, not syntax); the pattern word then contains `[...]`/`*`, matches no file, and nullglob REMOVES it — the pipeline becomes `grep -v <file>` with no pattern, outputs nothing, and every trap condition sees EMPTY input and passes. The build succeeds while the check guards NOTHING — verified by running the identical script text standalone (bash, no nullglob) where it correctly failed. Two rules: (1) indirect commands in check scripts MUST be shell functions (`strip() { grep -v '...'; }`) — quotes parse at definition time, no word-splitting of the command ever; (2) NEVER trust `nix build .#checks...` exit 0 alone for a check you just wrote — negative-test it THROUGH nix (`scripts/negative-test-lints.sh` is the persisted harness: copies the git-tracked set to a git-less flake source — plain-dir flakes see ALL files, no tracked-files filtering — applies one incident-shaped mutation, builds the REAL check derivation, and asserts the lint's own FAIL marker appears; an eval error does NOT count as a catch. Its first run caught module-shape-lint's `\b` accepting renamed wrappers). The static sweep `scripts/audit-shell-nullglob.sh` (pre-commit + CI) rejects the command-position-var class on every commit. /tmp paths don't exist in the nix sandbox — another silent-empty-input trap.
- **`nix fmt` is NEVER path-scoped in this repo and RE-LOCKS moving-ref inputs** — two distinct traps: (1) it reformats WHOLE files, so never run it while a parallel session owns the tree — stage your semantic edits and let the owner's fmt pass format (2026-08-27: `nix fmt -- <files>` reformatted 837 lines across gatus-config.nix + cv.nix under a parallel session, recovered only by luck); (2) plain `nix fmt` re-evaluates the flake and SILENTLY re-locks every moving-ref input (browser-history, CV, go-cqrs-lite ride `ref=master`) to current upstream heads, churning flake.lock as a side effect of formatting — always prefer `nix fmt --no-update-lock-file -- --ci` (checks formatting, zero lock writes), and treat any flake.lock diff after a formatter run as accidental churn to revert, never to commit
- **ONE formatter arbiter: pre-commit and CI MUST run the same nix formatter** — pre-commit formats staged `.nix` with the repo's own locked `.#formatter.$system` (treefmt/nixfmt-RFC), and CI arbitrates with `nix fmt -- --ci` over the SAME locked formatter. Until 2026-08-29 the hook ran floating `nixpkgs#alejandra` instead — a SECOND formatter with a DIFFERENT style — so every commit re-broke CI's fmt check with alejandra-shaped output and the tree oscillated between two styles (the "nix fmt --ci nondeterminism" red class; the drift was NOT treefmt version drift). Rule: never add another formatting tool for an already-formatted language; a new formatter means replacing the old everywhere in the same change

## Safe verification of a disabled service (never force-enable)

- **Never force-enable a disabled service in the working tree "just to verify", and never manually activate a built toplevel** (`sudo ./result/switch-to-configuration …` or any activation outside `nix run .#deploy`) — a manual activation leaves NO profile generation (the 2026-08-18 00:33 google-sync 226 crash-loop ran for 47 min with zero generation trail; deploy.sh post-switch steps are also skipped). The SAFE verification pattern is a throwaway expression that never touches the tree: `nix build --impure --no-link --print-out-paths --expr 'let f = builtins.getFlake (toString /home/lars/projects/SystemNix); sys = f.nixosConfigurations.evo-x2.extendModules { modules = [{ services.X.enable = true; }]; }; in builtins.head sys.config.systemd.services.X.serviceConfig.ExecStartPre'` — if it fails with "string has context with the output 'out'", the error names the store paths; build the leaked `.drv^out` directly and run the real artifact

## Store-hit first: giant uncached builds, same-version drv drift (2026-10-03)

- **Before letting ANY giant build run, assert WHICH derivation — not WHICH version string.** A nixpkgs bump can change a package's drv while the version string stays identical (2026-10-03: clickhouse 26.8.7.19 built fine from the 2026-10-01 lock; the 2026-10-02 bump produced a DIFFERENT drv → 1h16m from-source rebuild; `cache.nixos.org` carries no clickhouse at all). Check: `nix eval <pkg>.drvPath` + `nix path-info <drv>^out` — 30 seconds, vs hours blind.
- **Drv-archaeology method** (recovering which nixpkgs rev built a cached output): list lock revs from `git log -p -- flake.lock`, then for each candidate `nix eval --raw github:NixOS/nixpkgs/<rev>#<pkg>.drvPath` and compare against `nix-store -q --deriver <cached-output>`. The matching rev's `narHash` (from any historical flake.lock carrying it) feeds a `builtins.fetchTarball` import for a bit-identical pin — zero builds.
- **`nixos-version --json` disambiguates generation-name suffixes**: `nixpkgsRevision` vs `configurationRevision` — the `…-nixos-system-<host>-<ver>.<7hex>` suffix is the nixpkgsRevision prefix; don't confuse it with a SystemNix commit.
- **A `^C` mid-build leaves `<out>.lock`** (0-byte, root) next to the unbuilt output path — residue, GC-able, but it makes `nix path-info <out>` report "not valid" while the sibling file sits there; same invalid-output family as the 203/EXEC pre-deploy-check trap (2026-10-01).

## Hunting eval warnings to their source (2026-10-04)

- **`NIX_ABORT_ON_WARN=1 nix eval <attr> --show-trace` aborts on the FIRST eval warning with a full stack** — the fastest way to attribute `evaluation warning:` noise (deprecated accessors, renamed options). Traces read innermost-LAST: the offending access is the deepest non-nixpkgs frame. `nix flake check` prints warnings only inline, no stack.
- **An input's flake evals DIFFERENTLY standalone vs inside our flake** — inputs that `follows` our pins (go-nix-helpers, nixpkgs) use OUR rev inside our flake but THEIR OWN pinned rev when evaled via a `/nix/store/…-source` path ref. Warning-bisection over standalone input evals therefore misses emitters that only fire through our flake. Bisect through our context instead: `nix eval --impure --expr '(builtins.getFlake (toString /home/lars/projects/SystemNix)).inputs.<i>.packages.x86_64-linux.<a>.drvPath'`.
- **Which pin does a consumer actually resolve?** `jq -r '.nodes.<input>.inputs."<dep>"' flake.lock` — a plain string = follows a node; node names are suffixed (`go-nix-helpers_2`, `rust-overlay_2`) and root's is whatever `.nodes.root.inputs."<dep>"` names. Nine coexisting go-nix-helpers revs is normal graph shape, and `nix flake lock --update-input` only sees FLAKE.NIX inputs — orphan lock nodes reachable via a consumer's follow need a root-input declaration + explicit follows to move.
- **Throwaway `extendModules` disables a service for warning isolation without touching the tree** (the safe-verification pattern, same expr shape): `evo-x2.extendModules { modules = [{ services.X.enable = evo-x2.lib.mkForce false; }]; }` — use it to unmask the NEXT warning when an upstream noisemaker fires first. Never `mkForce` in the tree itself.
