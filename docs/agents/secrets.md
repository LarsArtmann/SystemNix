## Sops + Age

**Encrypting a NEW secret file** — NO sudo needed. The age PUBLIC key in `.sops.yaml` is sufficient:

```bash
echo "secret_key: $(openssl rand -base64 32)" > platforms/nixos/secrets/newservice.yaml
sops -e -i platforms/nixos/secrets/newservice.yaml
git add -f platforms/nixos/secrets/newservice.yaml  # secrets/ matches .gitignore pattern
```

**Modifying or decrypting an existing secret** — requires the age PRIVATE key (from SSH host key, needs sudo):

```bash
SOPS_AGE_KEY=$(sudo cat /etc/ssh/ssh_host_ed25519_key | ssh-to-age -private-key) sops --set '["key"] "value"' file.yaml
```

- `SOPS_AGE_KEY` in RAM only — never write age key to disk. `SOPS_AGE_SSH_PRIVATE_KEY_FILE` does NOT work with `sops` CLI
- `sops -e` (encrypt): needs only the PUBLIC key recipient from `.sops.yaml` — NO sudo. The private key is only needed at DEPLOY time (sops-nix activation script runs as root on the target host)
- `sops --set` / `sops -d` (modify/decrypt): needs `SOPS_AGE_KEY` env var with the private key — requires `sudo` to read the SSH host key
- Secrets with service-specific owners MUST be guarded with `lib.optionalAttrs config.services.X.enable` — one bad owner blocks ALL secrets atomically
- **`sops-key-audit.nix` (2026-09-05) makes missing sops keys an EVAL-TIME failure** — the 2026-09-04 incident (db_token declared on master, key absent from browser-history.yaml) blocked every deploy at ACTIVATION (after a full build, the worst moment). sops encrypts VALUES but keeps key NAMES plaintext, so a pure `builtins.readFile` + top-level-line scan needs no age key. Scope: top-level keys only (nested `key = "a.b"` skipped), string-typed sopsFiles skipped (runtime paths like `/run/secrets/sops-nix-age-key` — quickshell.nix; `builtins.tryEval` CANNOT catch the pure-eval absolute-path error, and `builtins.toFile` returns a STRING not a path, so the negative-test fixture must be a real tracked file). Negative test: `tests/test-sops-key-audit.nix` (missing key fires, present passes, nested skipped, runtime skipped)
- **sops CIPHERTEXT-PRESERVATION (verified experimentally 2026-09-11): a value's ENC blob changes IFF its plaintext changes** — unchanged values' blobs AND the `age:` data-key stanza survive both `sops --set` and editor saves. Consequence: `git log -p` on a sops file is a sanctioned NO-SUDO rotation verifier — a single-blob diff dates AND proves a surgical value replacement (this confirmed the 2026-09-06 Pocket ID SMTP paste via `467983e8`). Inventory the file's FULL top-level key list BEFORE citing "only key X changed" (a 3-name grep of a 6-key file makes the claim load-bearing on a subset)
- See `.crush/skills/sops-secret-management/SKILL.md` for full workflow
