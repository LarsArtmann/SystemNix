## §e WHAT WE SHOULD IMPROVE

1. **Producer inventory before enforcement (the d2 rule).** Any new gate must enumerate its non-human subjects — daemons, bots, merge/revert drivers, codegen — and either exempt them (with evidence, like a2's merge census) or fix them upstream FIRST. House precedent exists (pre-deploy §10's per-service endpoint-down opt-ins); generalize it into a reflex: "who else commits?" is a pre-landing grep, not a post-incident report section.
2. **Fixture evidence hygiene: the measured property IS the evidence; the PASS label is decoration (d1).** Always print length/rc/diff-stat beside verdicts; never cite a label. Consider whether the tq verify harness could someday diff claimed-vs-printed — for now it is discipline.
3. **A gate without a standing fixture is half-shipped (b1).** The house already built the patterns (`scripts/test-*.sh`, `checks.*-fixture`, negative-tested); reaching for "smallest correct change" to skip them is a scope-creep inversion — the fixture IS part of the smallest correct change for anything gated. Default reflex going forward: new gate = gate + fixture + negative case, one commit.
4. **Extensionless shell scripts are invisible to every shellcheck surface (b2).** One-line fix in the pre-commit leg's pathspec (`.githooks/*` in addition to `*.sh`); the CI job deserves the same. The blind spot predates this task (hooks pre-commit/post-commit were never shellchecked either) — this task just added the highest-churn file to it.
5. **The daemon-race protocol needs its daemon-side half landed (d3).** 13 occurrences across ~10 sessions, each burning a full flake-check gate run; per-agent discipline has converged every time but prevents nothing. The queued codification row already names the two candidate mechanisms (honor-file/lock, or sweep-suppression while a queue worker is live). Until one lands, the mandatory post-commit `git show --stat` check should be treated as part of writing `git commit`, not part of reviewing afterward.
6. **Locale semantics of the length check are unpinned (c1's multibyte half).** `${#first_line}` counts characters under a UTF-8 locale and bytes under C; the hook inherits whatever env git hands it. Harmless today (subjects are ASCII), worth one fixture case + a comment when the standing test lands.
7. **The CONTRIBUTING hooks table is decorative, not accurate (c5).** Tables that name hooks that aren't wired and omit legs that are actively gate commits undermine the "read before you write" contract — reconcile against the actual `.githooks/pre-commit` leg list and fix the `pre-commit install` framing.
8. **Cross-project shell-interpreter note (d1's root).** mvdan/sh (this CLI's shell) and bash disagree silently on some printf forms; anything that must run identically in both should stick to boring constructs (`head -c`, `awk`, plain loops). Session-level lesson — recorded here because it cost one false fixture run and will recur in any fixture I write from this CLI.
