## e) WHAT WE SHOULD IMPROVE

1. **Fire permission belongs in deploy.sh, not in a hand-rolled watcher.** A one-line green-eval pre-gate (`nix eval --raw …toplevel.drvPath`) before the battery would have refused the 19:26 and 20:20 fires in seconds instead of ~8-minute battery deaths. Impact: every future mid-executor deploy attempt. Fix: §f.1.
2. **Stability threshold must be derived from the thing it protects**: quiet-period length ≥ battery duration + margin. Hard-code the relationship in the script (constant + comment), don't re-derive per incident.
3. **One shared definition of "eval-relevant tree"** for heat-checks and §11's stamp — my hand list missed `flake.lock` once already; the list lives in at least two places now (AGENTS.md prose + any future script). Fix: a tiny `scripts/lib/eval-relevant-paths.sh` (or equivalent) both consume.
4. **The §11-only probe before a deploy is an anti-pattern under concurrency**: it duplicates validation the deploy battery will redo minutes later, and the probe+pre-gate sequence WIDENS the race window it tries to shrink. Only the eval pre-gate earns its keep. (AGENTS.md entry records this.)
5. **Watcher stop-on-rc=1 should classify**: a §11-void/flake-check rc=1 under a live executor is EXPECTED and retryable; anything else stops for review. One output-grep classification turns 3 manual re-arms into 0.
6. **Analysis one-liners deserve the pre-commit discipline deploy commands get** — the repo already learned this twice (17-45 §d.2 junk awk; my near-miss). A standing check ("would I quote this number in a report? then sanity-check one known value first") belongs next to the 2026-10-23 `rg -r` rule in AGENTS.md session discipline. Impact: report integrity.
