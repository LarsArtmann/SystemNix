04D) Totally Fucked Up

Critical

Memory budget is mathematically impossible

All MemoryMax values vs. actual available RAM

The sum of all per-service MemoryMax quotas is ~94 GiB+:

MemoryMax quotas ├── ollama: 32G ├── hermes: 24G ├── whisper-asr: 8G ├── clickhouse: 4G ├── immich-ml: 4G ├── minecraft: 4G ├── gitea-runner: 4G ├── 20+ services @ 256M-2G: ~14G └── TOTAL: ~94G+ (but only ~43G actually available)

oomd kills at 50% pressure / 20s. Services die → restart → 5 restarts in 300s → start-limit-hit → reset-failed needed on every deploy. This is the engine that generates the problem, and it's baked into the architecture.

Fix: Right-size quotas to actual usage, disable unused heavy services (ollama 32G + whisper 8G = 40G freed), or constrain GPUActive via amdgpu.gtt_size kernel param.
Critical

reset-failed band-aid masks chronic crash-loops

scripts/deploy.sh

systemctl reset-failed runs before every deploy — not as defense-in-depth, but as a load-bearing crutch. It clears the start-limit-hit state that accumulates because services keep crash-looping between deploys. The band-aid hides the underlying failures instead of fixing them. A healthy NixOS box never needs reset-failed.

Trap: Removing it now would block every deploy until root causes are fixed. Must fix the crash sources first.
Critical

Strix Halo GPU memory management is uncontrollable

/proc/meminfo → GPUActive · boot.nix

GPUActive consumes 51+ GiB (55%) of visible RAM with GPUReclaim=0. The TTM pool is configured with pages_limit = page_pool_size = 112 GiB — which exceeds the 94 GiB visible. The GPU driver can consume virtually all system RAM. /proc/meminfo has a GPUActive counter but standard tools (free, htop) don't show it — making the "missing" RAM invisible.

Known mitigations deployed: User slice MemoryMax=64G, oomd at 50%, MGLRU min_ttl_ms=1000, Helium --disable-gpu-watchdog. But the pool size (112 GiB) and GPUReclaim=0 mean the fundamental problem persists.
Critical

Pocket ID provisioning desync chain

modules/nixos/services/pocket-id.nix

Pocket ID is a single point of failure for the entire OIDC chain. If pocket-id is slow to start (30 retries × 120s window), 4 downstream services (gatus, forgejo-oidc-setup, oauth2-proxy, immich-server) all wait, then start simultaneously, spiking memory. Historical desync: client-secret file had old sops value while DB had null/stale → 401 at token exchange. Migration block now removed, but the boot-time cascade remains.

05E) What We Should Improve

1. Memory budget reconciliation

Create a centralized lib/memory-budget.nix that sums all MemoryMax values and validates against available RAM (visible − GPUActive headroom). Fail eval if overcommitted.

2. Boot ordering: stagger downstream starts

Add RestartSec=10 + StartupIntervalSec=10 to services after pocket-id-provision so they don't all hit simultaneously.

3. Service defaults: add RestartSec + RestartSteps

Add RestartSec=5 and RestartSteps=3 to serviceDefaults to space out restarts (5s → 10s → 15s) and avoid hitting the 5-in-300s limit.

4. Disable unused heavy services

ollama (32G), whisper-asr (8G), minecraft (4G) — disabling frees 44G. Start ollama on-demand via socket activation.

5. Cloud backup — zero off-site recovery

No off-site backup exists. BorgBackup to Hetzner StorageBox is researched but not started. This is the single highest-risk gap.

6. Firewall hardening

NixOS allows all inbound. Docker punches its own holes. Transition to explicit allowlist with deny-by-default.

7. Typed NixOS module options

Most modules use mkEnableOption only. Add typed options for ports, paths, timeouts → enables validation, testing, and self-documenting config.

8. Module splitting

monitor365 (716L), signoz (705L), forgejo (583L) are too large. Extract sub-modules for testability and readability.

9. GPUActive visibility

The GPUActive field in /proc/meminfo is the ONLY way to see the memory drain. Add it to the DMS widget + Gatus monitoring + SigNoz metrics. Make it impossible to miss.

10. Comprehensive memory diagnostic script

Write a scripts/memory-audit.sh that shows: visible RAM, GPUActive, per-service MemoryMax vs actual RSS, overcommit ratio, failed units, OOM history. Run it before every deploy.
