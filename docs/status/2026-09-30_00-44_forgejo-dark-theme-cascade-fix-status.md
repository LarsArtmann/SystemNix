Those checks CANNOT see rendering. ## e) WHAT WE SHOULD IMPROVE

1. **Visual features need visual gates.** Smoke checks that prove "the file is served and referenced" are plumbing checks. For theme/UI changes the gate must render (screenshot or computed-style probe) — or at minimum assert the decisive CSS values in the SERVED text (cheap curl+grep). This is the UI-shaped instance of the existing "assert WHICH question your evidence answers" doctrine and deserves a line in `docs/CONTRIBUTING.md`'s guard inventory.
2. **Trap → guard doctrine has a lag cost.** AGENTS.md gotcha recorded, guard not built. Every gotcha whose failure mode is mechanically checkable (this one: a set-diff over three CSS blocks) should get its guard in the SAME session as the fix, not queued. The set-diff is ~15 lines and fits the existing eval-time theme audit's home.
3. **Tool-flake escalation discipline.** When a verification tool flakes mid-session, the next attempts should change STRATEGY (different transport, different binary, different protocol), not flags. Also: first-attempt hygiene — fresh `--user-data-dir` + `--disable-dev-shm-usage` from the start; the first chromium run succeeded with defaults, the following three did not, and profile/state pollution is the known cause class.
4. **curl-banned shells slow every HTTP probe.** I hit the ban on the first probe and pivoted to the `fetch` tool (strips HTML — useless for head inspection) before landing on python urllib. A tiny documented pattern ("use python urllib for raw HTML/heads in agent sessions") in the repo's agent docs would save this improvisation every session; the reusable-screenshot helper (§c6) is the same theme.
5. **Daemon batch commits bury fixes without dedicated messages.** My one-line fix landed inside `d9494ea4` "chore: auto-commit 5 changed file(s) (heuristic)" together with a parallel session's hot-db work. Doctrine-compliant (pathspec commits are the author's option; the daemon batches), but archaeology for "why does this CSS line exist" now routes through AGENTS.md only. Per `git_commits` rules I did not hand-commit; noting the tradeoff, not proposing a change.
6. **Hand-rolled delta themes are a permanent maintenance surface.** The delta approach is elegant (upstream improvements flow through the `@import`) but owns two scheme blocks that must never drift apart, against an upstream file that changes on every forgejo bump. The official catppuccin/forgejo theme exists; aligning or switching shrinks the surface (§g3).
