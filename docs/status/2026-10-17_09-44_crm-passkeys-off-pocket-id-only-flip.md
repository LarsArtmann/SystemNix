## e) WHAT WE SHOULD IMPROVE (systemic, from this session)

1. **Probe ≠ probe unless it touched the intended tree.** The stash no-op (§d6) is the third session-era instance of an evidence command that silently proved nothing (siblings: the 2026-09-18 browser-history gate, the 2026-10-10 §11 false-green). Candidate fleet rule: after any evidence-producing command, assert it acted on what it claims (for stash: `git stash list` non-empty before pop; for probes: verify the probed rev in output).
2. **Zero-value-safe config structs by convention.** `serverConfig`/`Options` bools that default ON must be stored as their negation (or `*bool`) so direct constructors (tests, the sync job) can never inherit "off". Worth writing into the crm repo's AGENTS.md Go notes.
3. **§-class checks should pin the UNIT CONTRACT, not just the journal line.** §20 reads readiness from the journal; a one-line grep for `-passkeys=false` in the unit file would pin the deployed POSTURE, catching flag-drift that serves both buttons again. Same pattern generalizes to other flag-defined postures.
4. **Heavy verification under PSI needs a policy.** The box now runs continuous pma fleet builds; "run the full suite" and "wait for calm" are both losing strategies mid-storm. Either a PSI-aware test runner (skip+mark convergence-class tests above a threshold) or an explicit decision that scoped-package runs + pre-existence proofs are the accepted standard of evidence.
5. **The deploy lock belongs in `/run`, not `/tmp`.** Root-vs-user invocation flips ownership and wedges the other class; `/run/systemnix-deploy.lock` (or per-boot scoping) removes the whole class. Trivial fix, real blast radius (it blocked THIS deploy).
6. **Owner-risk calls must be surfaced BEFORE execution.** §d4 passed fine, but the correct move was: finish everything else, then ask "force past the storm gate or wait for the pma window?" — the question costs one round-trip; a kernel freeze costs a reboot and possibly worse.
