## e) WHAT WE SHOULD IMPROVE

1. **Verification commands must be constructed so lying is impossible.** Concrete rule (now in AGENTS.md, needs to be reflex): every `nix build`/eval in a chain runs with `set -o pipefail`, rc captured into a variable or `&&`-gated on the REAL command — never `cmd | tail && echo OK`. Better: a tiny `nixbuild` wrapper (fish function / script) that hard-codes pipefail + prints rc, so the safe path is the lazy path.
2. **Baseline probes need a depth contract.** When bisecting "did I break this?", probe with the same forcing depth as the failing gate (`drvPath`/derivationStrict for eval-time failures), and diff the LOCK (root-input map) between baseline and HEAD — the lock diff saved this diagnosis.
3. **Daemon-race-proof commits as a reflex.** In fleet repos with the auto-commit daemon: `git add <paths> && git commit -m … && git push` in ONE chained command, `git status --porcelain` immediately before. I adapted after two losses; make it the default from the first commit.
4. **Fix upstream first worked — keep it, and encode the protocol.** The probe → got-hash → paste → push → re-probe → re-lock → from-our-lock-verify loop was executed 6+ times by hand across two sessions. It should be a `nix run .#lift-input -- <input>` helper (or BuildFlow step) that does the dance and refuses to finish without the from-our-lock build green.
5. **The wave's root cause is structural, not per-repo.** Daemon dep-sweeps + no post-commit FOD probe = every LarsArtmann Go flake master rots silently (CV's CI is dead, so no signal there at all). The durable fixes are: daemon-side hash refresh after Go commits, and/or a per-repo scheduled `nix build .#default.goModules` CI step, and/or making `nix flake lock --update-input` probes part of the sweep. Pick one (question g2) — otherwise this evening repeats weekly.
6. **`vendorHash.nix`-style imported hash files are a sed footgun** (overview). Anything that writes into them must write a QUOTED string; a pre-commit `nix-instantiate --parse` fast-gate on `vendorHash.nix`-pattern files would have caught my broken push before it left the machine. Cheap, universal.
7. **Parallel-session coordination worked but cost real cycles** (mid-flight lock moves invalidated one toplevel build; a race fix landed under me in overview). The existing doctrine (flag foreign changes, verify at quiescent moments) is right; what's missing is a cheap "who else is active" check before starting long builds (e.g. `git log --since='10 minutes ago' --all -- flake.lock` + staged-diff sniff).
