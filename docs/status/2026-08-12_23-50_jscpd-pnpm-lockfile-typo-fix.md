## e) WHAT WE SHOULD IMPROVE!

1. **Stop hand-vendoring lockfile entries with typos.** The `pnpm-run-path` entry had the correct SRI hash for `npm-run-path@4.0.1`, which strongly suggests a manual search/replace accident. Vendored lockfiles should be generated by `pnpm lockfile-only`, not edited by hand.
2. **Add a lightweight `fetchPnpmDeps` dry-run in CI.** A `nix build .#jscpd` in the GitHub Actions workflow would have caught this immediately; `nix flake check --no-build` does not exercise fixed-output derivations.
3. **Document the `cache.home.lan` expectation.** If the cache is intentionally LAN-only, document that off-site builds fall back gracefully. If it should be reachable, fix DNS/VPN/routing.
4. **Consider dropping `jscpd` or replacing it with `art-dupl`.** `art-dupl` is already a Go-based duplicate detector in the ecosystem and avoids the entire Node/pnpm lockfile maintenance burden. Re-evaluate whether `jscpd` still provides unique value.
5. **Use `git commit` discipline for lockfile changes.** The diff is a single changed file; the auto-commit daemon will pick it up, but a manually written commit message should explain the typo and the 404 root cause.
