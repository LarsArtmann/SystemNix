## e) WHAT WE SHOULD IMPROVE

1. **Runbook stale-state half-life**: the runbook's "pending signal" guidance
   (`status=bounced`) silently rotted when Resend's behavior changed (550 → 250).
   Suggested fix: runbook verification steps should say what to RE-RUN to re-derive
   state (the journal grep + DNS dig pair), not just what to look for. I added the
   dated status block this run; a one-line "re-verify with these two commands" pattern
   would survive behavior changes better.
2. **Owner-allowance vs verified-domain is invisible from the outside**: Resend
   accepting mail for the account-owner address looks identical to full verification
   from postfix's view (250 both ways). Nothing in our monitoring can distinguish
   them. Suggested fix: after the user verifies the domain, add a paperless
   share-link send to a NON-owner address as a recurring or at least deploy-time
   smoke signal (runbook step), so a future Resend-side regression is caught by the
   real failure mode (non-owner delivery), not the allowance path.
3. **Agent-session capability boundaries undocumented for mail tasks**: this run
   rediscovered (curl banned, sudo banned, journal readable) by trial. A short
   "what an agent session can/cannot verify on this host" table in the runbook (or
   AGENTS) would save the rediscovery each time.
4. **SPF lockdown record coexistence trap**: the DKIM record was added while SPF kept
   `-all` — a natural "add the records Resend shows" mistake that leaves SPF failing
   forever. Worth an explicit warning line in any future domain-verification doc
   (REPLACE, don't append). Added to the runbook this run.
