04Totally Fucked Up

Critical

Unbound was crash-looping for hours from a one-character typo

modules/nixos/services/dns-blocker.nix:212 · introduced in d9dc7d30

infra-cache-numhost (missing trailing 's'). Unbound treats unknown directives as fatal errors, so it rejected the entire config and crash-looped 93+ times. DNS was completely down. This was introduced by a "fix memory" commit that was supposed to bound caches — instead it broke the entire DNS stack. The typo passed nix flake check --no-build because Nix doesn't validate unbound config syntax.

Lesson: NixOS should add a systemd.services.unbound.serviceConfig.ExecStartPre = "${pkgs.unbound}/bin/unbound-checkconf /etc/unbound/unbound.conf" to catch config errors at service start instead of crash-looping.
Critical

systemd-logind is degraded with no clear recovery short of reboot

systemd-logind · session scope creation fails · userdb socket missing

Every SSH session shows "Failed to start session scope: Transport endpoint is not connected". The /run/systemd/userdb/io.systemd.Multiplexer socket doesn't exist. switch-to-configuration-ng calls logind.list_users() which times out, causing every deploy attempt to fail with exit code 11. The system has been in this state since at least the OOM events ~13 hours ago. A simple systemctl restart systemd-logind might fix it, but if the dbus connection is deeply broken, only a reboot will do.

Critical

05What We Should Improve

!
Add unbound-checkconf ExecStartPre Prevents crash-loops from config typos. Should be in the NixOS unbound module upstream.
!
Add logind health check to pre-deploy-check Test loginctl list-users before attempting activation. If it fails, warn that a reboot may be needed.
!
Lower pre-deploy-check disk threshold from 95% to 90% 97% with 4 GiB BTRFS unallocated is too dangerous. Catch it earlier.
!
Always use nix run .#deploy not nh os switch The deploy script runs systemctl reset-failed first. Direct nh skips this, causing exit code 4/11 from start-limit-hit units.
!
Schedule periodic BTRFS data balance Weekly btrfs balance start -dusage=50 prevents the slow space exhaustion that leads to ENOSPC.
!
Add metadata_ratio=1 to BTRFS mount options Forces allocator to give more chunks to metadata, preventing the data/metadata imbalance that causes ENOSPC.
!
Consider growing the root partition 722 GiB is full at 97%. The permanent fix for the recurring BTRFS crisis is more space. /data has 349 GiB free — consider rebalancing.
