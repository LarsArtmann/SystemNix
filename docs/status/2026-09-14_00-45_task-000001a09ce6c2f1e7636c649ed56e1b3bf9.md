## e) WHAT WE SHOULD IMPROVE (systemic, from this session)

1. **Identity-invention guard (OPEN since 2026-08-18 §e1)** — a cheap
   pre-commit or CI check that fails when the repo has a LOCAL `user.name`/
   `user.email` override that differs from the canonical identity, and when
   a commit's author is neither canonical nor in a known-allowlist (bots,
   dependabot). The Unknown-Author guard only rejects one literal name.
2. **The 08-18 audit methodology was too narrow** — grepping for the ONE
   known bad identity found only that one. Any future identity audit must
   whitelist the CANONICAL set and report everything else (invert the
   search), which is how this session found charm.land/MiniMax Crush and the
   ~6k-commit Unknown Author/Claude cohorts.
3. **docs-only commits should not pay the full VM-test gate** — the pre-commit
   hook runs `nix flake check` (which BUILDS VM tests) unconditionally;
   a markdown-only fast-path would have saved ~5 minutes and the stash
   disaster that followed it.
4. **Background jobs must never hold git state** — stash/checkout/rebase in
   a background shell that a timeout or human can kill is a self-inflicted
   data-loss pattern. Rule candidate for AGENTS.md: git state mutations are
   foreground-only.
5. **Pre-existing red inventory is tribal knowledge** — the cv VM-test red
   was already documented by a parallel session in `4228d56d`'s report, and
   I nearly re-verified it from scratch. A one-line "known pre-existing
   check reds" list in TODO_LIST (or the flake-check output carrying a
   skip-list) would stop duplicate archaeology.
