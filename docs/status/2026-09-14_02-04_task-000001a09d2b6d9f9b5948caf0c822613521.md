## d) TOTALLY FUCKED UP (caught + fixed in-session, listed honestly)

1. **First disk-busy implementation SUMMED io_ticks across all disks** — live test immediately returned 395.1% "busy" (>100% is impossible per-disk; a sum exceeds 100% on multi-disk boxes). Fixed to MAX-per-disk via paired sampling. Caught because I live-tested before moving on.
2. **Second implementation indexed pasted stat lines by fixed field numbers (`$11-$15`)** — `/sys/block/*/stat` lines have VARIABLE field counts (nvme with discard/flush = 17 fields vs 15), so a fixed index into the pasted pair is wrong for some devices. Fixed by sampling io_ticks (field 10) per device with a glob-guarded loop and joining on position, which is field-count-independent.
3. **Unmatched shell globs under `set -euo pipefail`**: `cat /sys/block/{sd*,nvme*n*,vd*}/stat` exits 1 when a glob class has no match (e.g. `vd*` here), and with pipefail the command substitution returns 1 → `set -e` would have aborted the deploy gate at the sampling line. Live test exposed it (`sample rc=1`). Fixed with the `[ -e "$d/stat" ]` guard loop + explicit `return 0`.
4. **Commit dance was messier than it should have been**: the auto-commit daemon committed my worktree mid-verification (`f0e3c493` "chore: auto-commit 3"), so the final commit had to be an AMEND of the daemon's TODO_LIST commit (`5daa85cc`) with the real message + footer, while the code itself carries a heuristic daemon message.
