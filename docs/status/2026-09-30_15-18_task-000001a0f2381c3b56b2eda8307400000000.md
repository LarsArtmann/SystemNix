## The finding, restated

The T14 monitoring shipped a fail-closed *emission* story but had NO layer that detects the
collector itself dying. The anchored Gatus conditions
(`[BODY] != pat(*<metric> 0\n*)` + `[BODY] == pat(*\n<metric> *)`) only fail on metric
ABSENCE — true for the never-ran case (no textfile yet), but after the FIRST successful run
`hot-db.prom` persists forever, and a later collector death (start-limit, mv/mktemp failure,
sandbox breakage) leaves node_exporter serving frozen last-good values: permanent phantom
green. This contradicted the repo's own forgejo-github-sync doctrine ("mid-run death leaves
last-good values and the UNIT-state alert owns that failure mode") and the memory-guard/niri
freshness doctrine. The module comment and the parent report's §b1 asserted coverage that
did not exist.
