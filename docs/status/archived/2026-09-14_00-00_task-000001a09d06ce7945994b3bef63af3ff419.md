# Task 000001a09d06ce7945994b3bef63af3ff419 — `InvokeNamed[interface]` sweep

**Date:** 2026-09-14 · **Scope:** all local LarsArtmann Go repos under `~/projects`

## Method

Grepped every non-vendor, non-test Go file under `/home/lars/projects` for
`do.InvokeNamed` and `do.MustInvokeNamed` (both match the samber/do v2 named
resolution family; `InvokeNamed[T]`/`MustInvokeNamed[T]` match `T` against the
registration's EXACT type parameter, so an interface `T` never resolves a
concrete `ProvideNamedValue` registration — the DiscordSync 2026-08-16/17
crash-loop class). Every call site was then cross-checked against its repo's
registration call for type-parameter agreement.

Also probed Sourcegraph for public `LarsArtmann` repos (0 matches — the private
repos are not indexed; local checkouts are the practical sweep surface).

## Residual risk

Repos are living code: a future `ProvideNamedValue(inj, name, concrete.New())` +
`InvokeNamed[Iface]` pair would reintroduce the class silently. Mitigation that
already exists: branching-flow's own `doanalyzerv2` analyzer covers provide/invoke
pairs (run as a linter there); DiscordSync's guard comment documents the rule at
the point of use. A repo-generic CI analyzer across all repos remains a possible
future hardening (not done here — out of scope).
