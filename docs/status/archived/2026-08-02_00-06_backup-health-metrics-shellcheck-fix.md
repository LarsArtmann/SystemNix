## D) TOTALLY FUCKED UP / MISTAKES MADE

1. **FORGOT TO FORMAT**: Did not run `alejandra` or `nix fmt` after editing. The
   pre-commit hook uses `alejandra` directly on `.nix` files. Caught this only during
   the self-review for this report. Fixed retroactively.

2. **FORGOT THE TAB-IN-FILENAME EDGE CASE**: The `find -printf '%T@\t%p\n'` followed
   by `cut -f2` will break if a backup filename contains a literal tab character.
   Backup filenames are generated by scripts (`*.backup_*.db`, timestamps, etc.) so
   this is extremely unlikely in practice — but it IS a correctness regression from
   `ls -t` (which doesn't have this problem). Could use `find ... -printf '%T@ %p\n'`
   with a space separator + `cut -d' ' -f2-` or `sed` instead, or better yet:
   `find ... -printf '%T@\t%p\n' | sort -rn | head -1 | cut -f2-` (note the `-` on `cut`)
   to handle tabs in filenames. Currently `cut -f2` drops everything after the first tab.

3. **REDUNDANT `stat` CALL**: The `find -printf '%T@'` already outputs the mtime as
   epoch seconds. The script then runs `stat -c %Y "$LATEST"` to get the SAME value.
   This is redundant work — could capture mtime from the find output directly. Not a
   bug, just wasted effort.

4. **DID NOT SCAN FOR THE SAME BUG CLASS ELSEWHERE**: There are 21 other
   `writeShellApplication` blocks across the codebase. I did NOT audit them for the
   same SC2012/SC2086/SC2129 patterns. Some may have the same latent issue that just
   hasn't been triggered yet (or was triggered and fixed ad-hoc without scanning).

## E) WHAT WE SHOULD IMPROVE

1. **Always format after editing** — `alejandra` / `nix fmt` is a mandatory post-edit
   step. Internalize this.

2. **`cut -f2` should be `cut -f2-`** — preserve everything after the first tab to
   handle filenames with embedded tabs (defense-in-depth, even if unlikely).

3. **Eliminate the redundant `stat` call** — extract mtime from the `find` output
   rather than re-statting the file. This would simplify the pipeline:
   ```bash
   LATEST_LINE="$(find "$BACKUP_DIR" -maxdepth 1 -type f -name "$PATTERN" -printf '%T@\t%p\n' 2>/dev/null | sort -rn | head -1)"
   if [ -n "$LATEST_LINE" ]; then
     MTIME="$(echo "$LATEST_LINE" | cut -f1)"
     LATEST="$(echo "$LATEST_LINE" | cut -f2-)"
     ...
   ```
   This avoids a second syscall and makes the logic clearer.

4. **Audit all `writeShellApplication` blocks** for shellcheck compliance — a one-time
   `nix build` sweep or a CI check that builds all script derivations would catch these
   before they hit a deploy.

5. **Consider a pre-commit shellcheck hook** — the existing pre-commit hook runs
   `statix` and `alejandra` on `.nix` files but does NOT run `shellcheck` on the shell
   snippets embedded in Nix strings. Since `writeShellApplication` runs shellcheck at
   build time, these only surface during `nix build`/deploy. A pre-commit shellcheck
   pass (extracting shell from Nix strings or building the derivations) would catch
   them earlier.

6. **GNU find `-printf` is a non-portable extension** — fine for Nix (always GNU
   findutils), but worth documenting in the script that this is GNU-specific.
