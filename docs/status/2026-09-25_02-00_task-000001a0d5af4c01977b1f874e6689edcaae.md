## §c Host regression discovered while verifying (the reason no sandbox build could run)

Chain of evidence, all probed live this boot:

1. Every sandbox build fails `error: getting attributes of path "/run/binfmt": No such file or
   directory` — the daemon's `extra-sandbox-paths = /run/binfmt …` (from `boot.binfmt.emulatedSystems`,
   boot.nix:143) is stat'd during build-env setup; `/run/binfmt` does not exist.
2. `/run/binfmt` is created by the nixpkgs binfmt module's TMPFILES rules (`d /run/binfmt 0755 -` +
   `L+ /run/binfmt/aarch64-linux …`, present in the deployed `/etc/tmpfiles.d/00-nixos.conf`) — not by
   the binfmt unit itself.
3. `journalctl -b -u systemd-tmpfiles-setup.service`: the unit has NO start/finished lines — at
   22:35:09/10 systemd logged TWICE: `hot-user-caches-nix-bootstrap.service: Found ordering cycle:
   systemd-tmpfiles-setup.service/start after local-fs.target/start after home-lars-.cache-nix.automount/start
   after hot-user-caches-nix-bootstrap.service/start - after systemd-tmpfiles-setup.service` →
   `Job systemd-tmpfiles-setup.service/start deleted to break ordering cycle`. **No boot tmpfiles rule
   ran at all this boot.**
4. The booted generation IS `system-797` (`/run/booted-system` == `/run/current-system`), whose unit
   already carries `DefaultDependencies=false` + `After/Wants=mnt-hot.mount` + `Before=home-lars-.cache-nix.automount`
   — the documented 2026-09-20 fix is deployed, yet the cycle still fired; `systemd-analyze verify` on
   the unit shows no cycle statically (unit + no drop-ins), so the residual edge only manifests in the
   full boot transaction.
5. Blast radius observed: fixture builds, `nix flake check` (formatter check's `derivationStrict`),
   `nix build --option sandbox false` (daemon rejects the client override), and any emulation-needing
   build (the `/proc/sys/fs/binfmt_misc/aarch64-linux` registration points its interpreter at the
   dangling `/run/binfmt/aarch64-linux`). This also explains the pipeline row's 2026-09-25
   `treefmt.drv`/`disko-layout` "is not valid" instances (same root cause, not check-specific) and the
   "/run/binfmt-shaped build-env error" the 2026-09-25 00:20 session noted inside storage.md:47.
6. Recovery requires root: `sudo systemd-tmpfiles --create` recreates `/run/binfmt` + the interpreter
   symlink (exactly what the skipped boot phase would have done). Agents CANNOT run it — `sudo` and
   `systemctl` are blocked in agent sandboxes (attempted; both rejected). The box therefore runs with
   sandbox builds broken until a root shell applies the tmpfiles rules or the cycle fix reboots in.
