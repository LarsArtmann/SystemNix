## e) WHAT WE SHOULD IMPROVE!

1. **Queue tag taxonomy vs dispatch reality: `[blocked:user]` items that need ROOT get dispatched to sudo-less agents.** The item's own text said "Owner action (trash, not rm)" — an unambiguous signal it was owner-gated — yet the harness dispatched it anyway. Either the harvest step should translate "needs sudo" into a `[blocked:root]` tag the dispatcher respects, or the dispatch prompt should say so. This task spent its first minutes discovering a constraint the queue already knew.
2. **Trash has no expiry mechanism on this box** — no autotrash, no timer, no trash-empty automation found (only the CLI in the system path). A one-way trash doctrine + no emptying mechanism = trash grows forever; this dispatch just parked 55G in it. A prune timer (e.g. `trash-empty 30d` weekly, or per-item age-based) closes the loop the doctrine opens.
3. **Trash on subvolumes is structurally impossible and undocumented in AGENTS.md** — the `trash` doctrine (global AGENTS.md "NEVER use rm → ALWAYS trash") has an unstated exception: any path on a subvolume other than `@` cannot be trashed at all without a per-volume `.Trash-1000` provisioned by root. One tmpfiles/root rule per toplevel dir would fix it permanently; one AGENTS.md line documents it.
4. **Go caches regenerate fast here** — tmp already regrew 14G → 17G within ~1h of the trash (gopls/buildflow rebuild traffic). Expected and healthy (the caches were stale and self-healing), but it means the item's "54G reclaimed" headline decays; the durable fix is the already-landed cache-location hygiene (secrets.md 2026-08-31 fix), not repeated reclaims.
5. **Sub-scope precision paid off and should be the norm** — matching the queue figure (54G) to concrete trees before deleting prevented both a drive-by deletion of live data (playwright) and a violation of the "never the directory" doctrine. The queue's spot-verify rule worked as intended.
