1. **Vacuous-green gates need a live negative test as part of close-out.** The §13/§14 anti-blind-skip discipline (neuter the gate, prove it RED, restore) exists for pre-deploy checks; assertion-type eval gates deserve the same rule. Green selftest + green flake check ≠ the gate bites the real config.
2. **Re-dispatch check should also grep the daemon commits.** `git log --grep 'Task-Queue-ID:'` only sees footer commits. A twin session's work arrives as heuristic commits hours before any footer exists; a secondary probe (e.g. `git log --since 1 day --name-only` intersected with the batch's expected files) would have surfaced `902911b94` up front and reframed the session as "verify + close out" from minute one, instead of discovered mid-flight.

4. **Daemon-swept code changes need their lint legs re-run standalone.** Item 3's forgejo.nix deletion rode commit `8de92e3a7`; the pre-commit legs are keyed on staged paths and were green only because the diff is trivial. The docs-health-era rule (re-run skipped lints after any daemon-swept commit) applies to Nix files too (statix/deadnix/alejandra via the treefmt gate) — I leaned on `nix flake check` instead, which is stronger for eval but does not run the formatters.
