## Root cause (live-verified)

`system_service_restart_churn` fired on **cumulative NRestarts >= 5 since the last explicit start**, and systemd's NRestarts only resets on reboot/explicit restart. The 2026-11-25 morning (two crashes: WDT 08:57, panic 11:05 → boots `b4931451`/`8b31b428`/`0737ecd7`) left the box in a 2.5h IO storm (PSI some avg10 65-99%). `tq-agent-pool`'s PSI entry gate (`maintenance-entry-gate --psi-max 30`, ExecStartPre) **refused starts as designed unit failures** (refire-until-calm — the documented contract in tq-agent-pool.nix and docs/services/tq.md), which systemd counts in NRestarts exactly like crashes:

- boot `0737ecd7` 11:06:51 → 26 counted restarts by 11:20 (gate REFUSE at 11:19:59 "IO PSI 32.82%", journal verbatim)
- gate passed 11:20:29 ("PSI 28.39% < 30") → pool STARTED, healthy since (7.5h at closeout: `ActiveState=active`, `crash_loop` self-cleared to 0)
- `nrestarts=26` stays >= 5 → `restart_churn=1` latched → Gatus check red for hours with **no self-clear path** (the flag outlived the condition it described). Live at 18:5x: pool running, churn flag still 1.

The alert text's own design comment ("deploy restarts reset NRestarts, so deploy churn cannot false-fire") enumerated deploys as the only benign restart source — the pool's designed gate refusals were the unenumerated class. Attribution guidance (journalctl the service) works — a refusal chain reads as `maintenance-entry-gate REFUSE`, not a crash — so the fix belongs on the metric, NOT on the pool's pinned gate wiring (ExecCondition was deliberately rejected in tq-agent-pool.nix; VM test `test-tq-agent-pool.nix` pins it).

## Fix — active-churn semantics (modules/nixos/services/system-health.nix)

The churn flag now reports **ACTIVE churn**: cumulative NRestarts >= 5 **AND** a restart observed within a trailing 60-min quiet window (`restartChurnQuietMinutes`, new let-binding).

- Growth epochs per service in a NEW sibling state file `.system_health_churn_state` (`svc last_growth_epoch`; 0 = never/pre-tracking/counter-drop). Deliberately NOT a 3rd field of `.system_health_restart_state`: that 2-field schema is pinned by the restart-tracking probe's sed slice + assertions (tests/test-scripts.nix).
- A restart seen in the current collection (`r_delta > 0` vs the persisted prev) counts as just-now; an NRestarts **drop** (deploy/manual restart) resets the epoch to 0.
- Detection classes preserved: hermes exit-75 chains (minutely) and the nsfw 2026-10-20..25 class (~30-min cadence) still fire; a storm-churned-but-recovered service reads 0 within the hour.
- `crash_loop` (per-interval delta) untouched — it self-clears by construction.
- HELP text (per-service aggregate), the Gatus check comment + alert text, and SigNoz's `unit-restart-churn` rule (name/description/comment) reworded to the active-churn semantics. CHANGELOG entry added.
