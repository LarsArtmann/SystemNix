## e) WHAT WE SHOULD IMPROVE

1. **"What does the backup contain" claims must be derived, not recalled.** Before writing any provenance
   sentence in a DR runbook: trace the artifact's rendered location (sops template? tmpfs? state dir?) AND
   the archive path list (`backup.nix`), then write only what the intersection supports. DR runbooks are the
   highest-stakes prose in the repo — this is the class that bites at 3 AM.
2. **Same-file contradiction sweep.** When asserting where something lives, grep the same document for
   sibling claims about the same artifact. The dead-host table contradicted my sentence from day one; the
   reviewer needed one look to catch what a self-check would have caught earlier.
3. **Proactive daemon-race avoidance.** Check `git status --short` immediately before `git commit` (the
   daemon commits continuously). The amend-forward recovery was correct per AGENTS.md but reactive — the
   race was foreseeable and the confusing exit-1 avoidable.
4. **Fix-commit messages should cite verification anchors.** This fix's message describes the mechanism but
   not the file:line evidence (sops.nix:479-497, backup.nix:52-57). Including them lets a reviewer re-verify
   in seconds.
5. **Cheap process guard candidate:** a one-line checklist entry in `docs/CONTRIBUTING.md` for DR-runbook
   provenance claims ("derive from rendered-path + archive-path intersection") — a lint guard against
   "in the archive" phrasing would be over-engineered; the checklist is the right weight.
