## e) WHAT WE SHOULD IMPROVE

- **Check the guard surface before staging, not after the hook fails.** One `grep` of `.githooks/`
  for patterns present in touched files is cheap insurance against the abort-amend cycle.
- **Daemon race window:** stage + commit in ONE pathspec command immediately after the last edit;
  the daemon commits every ~3 min and it fired twice during this run's verification gaps.
- **The GOTOOLCHAIN guard has no selftest.** Every other scanner in this repo got a
  `negative-test-lints.sh` case or flake check after its first FP; this hook rule is now the second
  FP incident (after the dead-guard-lint `$((` class) with no pinned regression test. Hook guards
  should be negative-tested like flake checks.
- **Env-less cache convergence is whack-a-mole.** This is the third round (go-build 2026-08-16,
  BuildFlow names 2026-09-17, pnpm/cargo now). A single declarative inventory (option listing
  `home file → buildcache target` pairs) that generates symlinks + reap list + activation migration
  from ONE source would end the per-tool drift and keep `buildcache.nix`'s reap list and home.nix's
  file entries from being edited in lockstep by hand — they are already a documented
  "kept in sync" burden.
- **Report the PSI gate result prominently when deferring gated work** — done here, but the queue
  harvester would benefit from the gate value being machine-greppable in the row (it is now).
