05What We Should Improve

1. Enforce a root free-space floor mechanically

Wire an auto-response into btrbk-pool-clean (or its own timer): when root usage >90%, run btrbk prune immediately and emit a textfile metric + notify. The ladder today is: 93% gatus alert → (nothing) → 100% → outage. Prune is already fail-safe (send-parents preserved). Effort: S/M.

2. Centralize label escaping in every textfile writer + add a parse gate

Two quoting incidents from the same collector (2026-09-20 nrestarts, today \x2d) — by the feedback-loop rule this deserves a mechanical gate, not a third manual fix: a shared sanitize function for label values AND a check (or VM test) that renders a hyphen-carrying unit name and validates the .prom with a real parser (promtool/expfmt).

3. Textfile presence canary

Add a gatus check asserting system_health_ series presence in node_exporter /metrics — the phantom-metric canary pattern already used for nvme and coverage audits. Catches ANY future whole-file rejection, not just this escape bug.

4. Schedule hot-tier migrations BEFORE the next 100% event

Two incidents have now preceded the migration windows. The wave plan (one service per window) is sound; the windows need dates. Owner call.
