04TOTALLY FUCKED UP

DESIGN BUG: daemon cannot read its own client keys (crash-loop, caught by the VM test)

Evidence (VM log): ai-meter exited: load config: client vmtest: read key file: open /run/ai-meter-keys/vmtest: permission denied → 5 restarts → start-limit-hit.

Root cause: the mint oneshot writes each client key 0400 owned by the CONSUMER's user (crush→lars, paperless-gpt→paperless-gpt) — but the ai-meter DAEMON (ai-meter user) must read every key at startup to authenticate clients. 0400 + foreign owner = unreadable. The design conflated "who consumes the key" with "who verifies the key".

Fix shape (not applied — session hard stop): the mint writes TWO copies per client from the same random value: the consumer copy (as today) AND /run/ai-meter-keys/config/<name> owned ai-meter 0400; the sops template's clients[].key_file points at the config copies. Alternative: 0440 + shared group (rejected: groups are single). Then re-run ai-meter-vm (all 6 subtests) and only then deploy.

Self-inflicted breakage en route (all fixed, all mine)

  • sed blunder #1: sed 's|^{$|_: {|' replaced TWO lines in the module (the in { body opener became a lambda) → "module does not look like a module", burned 3 build cycles to find. Lesson already in AGENTS: sed on nix files is a footgun; the edit tool with exact context is the tool.
  • lib.shellEscape doesn't exist at top level (it's strings.shellEscape); fixed to lib.escapeShellArg — caught by eval, fine, but I guessed instead of checking.
  • Nix lambda-in-list needs parens in this parser ([ { config, ... }: ... ] is a syntax error without (...)) — the test mock module tripped it; cost 2 cycles.
  • Untracked-file skew: debugging a "syntax error" that was the STALE git-HEAD copy in the flake source before git add — the documented tracked-files trap, re-hit anyway.
  • python3 heredoc used twice for file edits (zero-Python doctrine is about repo scripts; still the wrong tool — edit/multiedit was available).
  • Stale LSP noise: gopls/golangci-LSP diagnostics referenced a pre-fix state for the whole session ("undefined: LoadConfig" after the package compiled green) — ignored once buildflow became ground truth, but it cost attention.

05What we should improve

  • VM-test-first for anything touching runtime file permissions — this session is the proof: the exact class eval cannot see (0400 foreign-owner read) was caught pre-deploy by ai-meter-vm. Make "new service with file-based credentials gets its VM test in the same change" a standing rule.
  • mock-sops needs a placeholder mock — every future service test whose module uses config.sops.placeholder.* will re-derive this session's workaround (attrsOf str mapped from declared secrets). Fix the shared helper once in tests/mock-sops.nix.
  • Stop sed-ing .nix files — two of the three syntax incidents were sed; the edit tool exists. Corollary: never blind-replace regex shapes like ^{$ in brace-delimited languages.
  • Design data models around BOTH readers of a secret file — the key-perm bug was a data-model miss (who reads what), not an implementation slip; the "mandatory reflection" questions would have caught it at design time.
  • Trust buildflow/nix as ground truth, treat LSP panels as advisory when they contradict a green pipeline run.
