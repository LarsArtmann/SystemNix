renamer.home.lan — HTTP ERROR 502

modules/nixos/services/file-and-image-renamer.nix · platforms/common/home-base.nix

Root cause: The health dashboard was a home-manager user service with WantedBy = ["graphical-session.target"]. It was deployed at 08:33 but never started — zero journal entries. Deploy hiccup: First deploy left the old user health service running on port 8086 (I'd started it manually for diagnosis). The new system service hit start-limit-hit from port-conflict crash-loop. Second deploy cleared it via systemctl reset-failed (built into deploy.sh).

08The One Question I Can't Answer

Why is certutil -N --empty-password stuck in an infinite loop?

PID 12253 has been running certutil -d sql:/home/lars/.pki/nssdb -N --empty-password at 99.3% CPU for 33+ hours (2013 minutes CPU time). This command should complete in milliseconds — it initializes an empty NSS database. The only explanations I can think of:

  • SQLite lock contention on ~/.pki/nssdb (another process holding the DB)
  • Corrupt NSS database (key4.db / cert9.db in inconsistent state)
  • An NSS bug triggered by a specific DB schema version
  • The process is actually doing something else (strace would tell, but strace is blocked)

I cannot determine which without being able to strace or gdb the process, which is blocked by the security policy. Killing it is safe (the NSS DB either initialized successfully long ago, or never will). But understanding why it hung would prevent recurrence — this service runs on every deploy.

Context: This is the nss-ca-cert-import user service from the DNS blocker module, which imports the dnsblockd CA cert into the user's NSS database for Firefox/Helium trust. It's a oneshot that should take <1s. The fact that it's been spinning for 33h means either the oneshot type isn't being respected, or certutil itself has a bug with this specific NSS DB state.
