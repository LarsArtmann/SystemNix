## e) WHAT WE SHOULD IMPROVE

1. **Destructive-verification protocol:** any verification that writes to a live state store needs a rehearsed rollback before the first write. Same spirit as the existing "never force-enable to verify" rule, extended to data mutations.
2. **Gate-count gap is a real security finding, not a curiosity:** `readModel.Count()` was 0 while real users exist (OAuth2-provisioned/legacy users don't count). After every read-model rebuild, exactly ONE ghost registration can slip through. This deserves upstream priority alongside the already-queued import-export hole — the two together mean the MaxUsers invariant has two bypass classes.
3. **The CSRF wall masks the gate from smoke tests.** post-deploy-check has no browser-history registration-gate check; a smoke probe without the CSRF dance gets a 403 that "looks closed" regardless of the gate's real state (the phantom-green class the repo keeps hitting). A proper smoke needs the cookie+header dance.
