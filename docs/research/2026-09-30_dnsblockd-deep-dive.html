00Summary

“Are we using dnsblockd superbly?” For the resolver half — yes, genuinely: sole-resolver posture with fail-closed semantics, DNSSEC validation, DoT upstreams, a hermetic SRI-pinned blocklist pipeline with a beyond-upstream runtime whitelist filter, Pocket ID SSO on the dashboard, OTel spans flowing to SigNoz, and an OOM-immune unit hardened by incident lessons. For everything upstream built in the 0.9.x arc — no. The deployed binary (verified: store path dnsblockd-75b4ce9 in the live unit’s ExecStart, byte-consistent with flake.lock) already contains device attribution, per-device policies and pause, a persistent permanent allowlist, Likely-Broken Sites detection, proxy history, and day-in-the-life analytics. None of it is configured, the permanent allowlist silently loses data on every restart, and the lock sits one minor version plus 64 commits behind on the exact day upstream shipped v0.9.3.

The bottom line Not to the max. One wrapper line (allowlist_path) stops today’s silent data loss of every “Always allow” click; a lock bump to v0.9.3 (which also fixes the device-Allow bug and hardens CSRF) plus a devices registry and one owner decision on the tracking dial would light up the entire household layer the deployment already paid for.

◆What's already excellent

The baseline before the criticism — this is how the resolver is actually run, every claim cited to the deployed config (the rendered YAML and live unit were both read for this audit, not just the Nix source).

+
Sole-resolver posture, fail-closed dns_enabled + dns_exit_on_failure=true, :53 ACL'd to LAN + loopback (dns-blocker.nix:254-257, dns-blocker-config.nix:103-107), VRRP failover partner unit (dns-failover). Upstream's F120 passthrough default means browsers get the real backend certificate — no CA dance, no DNS-cache wait. proxy_tls_passthrough is intentionally left at its default true.
+
Full observability chain otlp_endpoint wired to the local SigNoz collector (dns-blocker.nix:241, dark until the 2026-08-31 coverage audit), signoz-coverage-enforced, sdns telemetry bridge + cached /health anti-wedge fix both ride the deployed v0.9.2 binary. Gatus watches resolver health, metrics freshness, and DNSSEC composites.
+
Incident-hardened unit oomd-exempt + OOMScoreAdjust -1000 (the 730-kills/day lesson), MemoryMax 4G + GOMEMLIMIT 3GiB, GOTRACEBACK=all armed for the next :9090 wedge forensics, trustedProxies so Caddy-fronted audit rows carry the real LAN client (dns-blocker.nix:829-849).
+
Dashboard SSE live push dashboard_sse_enabled defaults on and is not disabled — live top-clients, block-rate, and the Live DNS Wire panel stream; admin actions (allow, cache flush, report) push immediately.

Architecture of the integration: SystemNix does not consume dnsblockd's upstream NixOS module (services.dnsblockd, in ~/projects/dnsblockd/nix/modules/nixos/). Instead, modules/nixos/services/dns-blocker.nix is a ~900-line wrapper declaring its own camelCase option surface (services.dns-blocker), fetching and whitelist-filtering blocklists at eval time, rendering dnsblockd's YAML config verbatim into the store, and running a systemd unit harder than upstream's (oomd immunity, GOMEMLIMIT, attach-ip ordering). That wrapper is the single integration point — and the single choke point — for every gap below: each dormant capability is off not because dnsblockd lacks it, but because the wrapper never renders the key.

Missed Opportunity · loses data today

Permanent allowlist is volatile — every “Always allow” is wiped on restart

modules/nixos/services/dns-blocker.nix:245 (temp_allowlist_path is set; allowlist_path is never rendered) · confirmed absent in the deployed YAML

dnsblockd maintains two allowlists. The temp allowlist (5m-24h, block-page “Continue to site”) is persisted — temp_allowlist_path = "/var/lib/dnsblockd/temp-allowlist". The permanent allowlist (“Always allow” on the block page, POST /api/allowlist, and the whole F143 “Likely-Broken Sites” bulk-allow workflow) defaults to allowlist_path: "" = in-memory only. With the key unset, every permanent allow silently evaporates on every restart — and the unit carries restartTriggers on config/binary/blocklists, so every deploy restarts it. On this fleet that means the operator's false-positive verdicts have a lifetime of one deploy. F143 specifically folds blocked domains against the live permanent allowlist (CHANGELOG 0.9.2): the feature's accumulated knowledge is the part being discarded.

Fix: one line in the wrapper's config render StateDirectory = "dnsblockd" already covers the path — no ReadWritePaths or mount work needed. 
# modules/nixos/services/dns-blocker.nix — config render attrset
temp_allowlist_path = "/var/lib/dnsblockd/temp-allowlist";
allowlist_path      = "/var/lib/dnsblockd/allowlist";   # ← add: persist "Always allow"
# dnsblockd creates the file on first write; entries survive restarts + deploys
Partially Used · deliberate choice, uncosted

tracking_mode = METADATA_ONLY starves every domain analytic the dashboard advertises

modules/nixos/services/dns-blocker.nix:246 · dnsblockd internal/tracking/mode.go:111 (IncludesDNS() requires mode ≥ METADATA_AND_DNS)

The tracking ladder is NO_TRACK → METRICS_ONLY → METADATA_ONLY (deployed) → METADATA_AND_DNS → +HEADERS → FULL, plus BLOCKS_ONLY. At METADATA_ONLY the store keeps request metadata (method, path, IP, UA) but no DNS information — no domains, no categories. Consequence: Top Blocked Domains (server-rendered since 0.9.3), the Query Log, Likely-Broken Sites data, the Day Weather Map, per-device day maps, and the durable proxy-history table (F136 — its own test pins zero rows written at METADATA_ONLY) are all data-starved by design. Aggregate Prometheus metrics (block rate, cache, latency histograms, DNSSEC coverage) remain fully alive. This is a defensible privacy stance — but it is one notch on a dial, and the cost (the dashboard's entire domain-level surface) is undocumented anywhere in SystemNix. Owner decision required: keep METADATA_ONLY, or step to METADATA_AND_DNS (domains + categories, still no headers/payloads) to light up the analytics half. 

# The dial — dns-blocker.nix:246
tracking_mode = "METADATA_ONLY";       # today: no domains stored
tracking_mode = "METADATA_AND_DNS";    # option: domains + categories, no headers/payloads
# retention already bounded: 30d tracks / 90d metrics / 365d block-rate (defaults)

Missed Opportunity · defense-in-depth

csrf_enabled false — dashboard action forms ride the SSO cookie unprotected

config.example.yaml csrf_enabled (default false) · absent from the wrapper render and the deployed YAML

The dashboard's action forms (temp-allow, report false-positive, “Allow all N” bulk) accept POSTs authenticated only by the SSO httpOnly session cookie. Modern SameSite=Lax browser defaults block plain cross-site POSTs, so this is belt-and-braces rather than a gaping hole — but the OIDC flow's own CSRF (state TTL) shows upstream's standard here, and v0.9.3's T300 batch hardened the CSRF path end-to-end (login double-submit fixed, e2e smoke pins csrf_enabled: true with the allow-form flow). Enabling is one key: csrf_cookie_secure stays true (the dashboard is HTTPS via Caddy). Order matters: bump to v0.9.3 first. 

# After the v0.9.3 bump
csrf_enabled: true          # double-submit token on dashboard forms
csrf_cookie_secure: true    # default — correct behind Caddy HTTPS
Missed Opportunity · medium

Per-device policies + shadow mode unused (F122/F124)

config.example.yaml policies: · FEATURES F122, F124

Scheduled per-device/group allow-block overrides (e.g. block games or doomscrolling domains on the desktop 09:00-17:00), with truthful block pages naming the policy and its window. The shadow-mode dry-run (F124 — GET /api/policies/shadow) measures a candidate policy's would-block volume before enforcing, exactly the trial-before-commit posture this repo likes. Missed Opportunity · assorted small knobs

Smaller dormant capabilities, graded honestly

all verified absent from the deployed YAML

Trial blocklists (dns_blocklist_trial_urls, T197): shadow-only sources that never enforce but attribute would-block hits — ideal for evaluating a HaGeZi tier change before committing; costs a runtime URL fetch + persistent cache dir, a departure from the hermetic build-time pipeline. ECS (dns_ecs_enabled): forward a /24 client subnet to Cloudflare/Quad9 for CDN geolocation (big HuggingFace downloads); trades a little privacy for better edge selection. Per-client DNS rate limit (dns_rate_limit_per_sec): disabled at 0 — the resolver is ACL'd to the LAN, so this is pure defense-in-depth (50/s + burst 100 would be the values). h3 block pages (tls_h3_enabled): QUIC block pages, in the deployed binary, off. Log sampling (log_sampling_threshold): off — would damp journal floods during IO storms (the 2026-09-06 forensics class). DoT/DoH/DoQ client listeners: off and likely correct — Android Private DNS requires a system-trusted cert, and the dnsblockd CA is custom (N/A on this LAN without a client-trust project).

Anti-pattern (latent) · dead config surface

extraDomains option declared, never rendered — setting it does nothing

modules/nixos/services/dns-blocker.nix:408-412 (option) · zero uses in the config render

The wrapper declares services.dns-blocker.extraDomains (“Additional domains to block”) but the render block never reads it. Anyone setting it expects extra blocking and silently gets none — the phantom-config class this repo's eval-time guards usually catch. Either wire it (feed a generated hosts file into dns_blocklists) or delete the option.
