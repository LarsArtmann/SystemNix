Caddy — Feature Deep Dive

00Summary

Scope: every Caddy surface in the repo — modules/nixos/services/caddy.nix (941 lines), the services.integration registry fan-out (integration.nix), the adjacent consumers (SigNoz scrape, gatus admin check, crowdsec + geometrikks log tails), the VM tests (tests/test-caddy-*.nix), and the runbook (docs/services/caddy.md). Method: repo-wide directive inventory → full Caddy 2.11 capability map from official docs + changelog → per-capability grading. Inventory: 41 capability rows, of which 27 applicable (14 graded Not-Applicable with reasons in the appendix), 24 fully leveraged, 3 missed opportunities, 0 misused. Score: round(100 × 24/27) = 89/100 — very high.

The deployed surface is not a default nixpkgs caddy: it is a hand-built edge with a three-helper vHost factory, a fail-closed oauth2-proxy forward-auth gate, boot-minted dual-zone certificates, edge OpenTelemetry spans, per-vHost access logs with a mode contract for two log consumers, and eval-time assertions guarding the vHost set. Most audits in this class read as a list of neglect; this one reads as a list of deliberate, documented decisions — auto_https off, no ACME, restart-not-reload, unauthenticated-but-firewalled admin API — each with its rationale in the runbook.

The bottom line Caddy is already used close to its ceiling for this deployment's shape (private CA, no ACME, single-upstream backends). The three things worth taking are cheap: metrics { per_host } (one word → per-vHost RED metrics the current dashboard cannot show), a branded 502 via handle_errors (dead backends currently serve Caddy's plain-text default), and routing Caddy's own runtime logs into journald so SigNoz — which already ingests the journal — can alert on proxy failures.

◆What we already use — the baseline

Ten usage patterns, each load-bearing. Together they are why this audit scores 89: the hard parts (auth gating, cert lifecycle, observability) are already solved with Caddy-native primitives, not workarounds.

+
Three-helper vHost factory (single source of truth) plainVHost / protectedVHost / renderVHost render every vHost — hand-written AND registry fan-out — through one tls+headers+auth composition. No snippet drift is possible. modules/nixos/services/caddy.nix:205-268, 718
+
Fail-closed forward_auth with response matching The @unauth status 401 → login redirect AND the @gatefail status 5xx → honest 503 arm use handle_response response matchers — the gate can never fail open. This is beyond most published forward_auth configs. caddy.nix:137-155
+
Split-horizon cloud mirroring + branded 404 catch-alls Every home.lan vHost mirrors 1:1 under larsartmann.cloud by an attrset transform; unknown hosts get a real 404 status with a branded page via error 404 + handle_errors (not a redirect that masks typos). caddy.nix:526-537, 746-776
+
Edge OpenTelemetry tracing The tracing directive emits one span per request with the span name pinned to the requested host — SigNoz spanmetrics cardinality stays bounded by the vHost count. Exporter scheme is pinned after the 2026-08-14 startup-hang class. caddy.nix:186-188, 886-894
+
Boot-minted dual-zone certificate, fail-closed A oneshot signs a 365d leaf (4 SANs) from the sops'd CA into tmpfs every boot, self-asserts the SANs before install, and Requires= blocks caddy start on mint failure — a broken cert fails the mint (OnFailure → Discord), never the first TLS handshake. caddy.nix:792-855, 872
+
Minimal-capability hardening with proof gate CAP_NET_BIND_SERVICE only (the dead ACME-DNS rationale for NET_ADMIN removed), ambient caps under NoNewPrivileges by design, OOMScoreAdjust −500, StartLimit pinned. checks.caddy-mint boots caddy and does real TLS handshakes without the dropped caps. caddy.nix:899-926
+
Compression + cache-header policy done right encode zstd gzip on every vHost plus the set-if-absent ?Cache-Control "no-cache" default — apps serving immutable content-addressed media keep their own long-lived headers. The app-vs-edge compression interplay is documented with probe evidence. caddy.nix:157-175; docs/services/caddy.md
+
Per-vHost access logs with a two-consumer mode contract Every vHost logs JSON to its own file; a Nix-level map forces mode 0640 because open(2) never re-modes existing files — the crowdsec acquis and geometrikks tailer both consume this surface. caddy.nix:485-492, 720-743; crowdsec.nix:83-95; geometrikks.nix:56-75
+
DNS/registry truth enforced at eval time Every vHost subdomain must exist in dns-local.nix AND map to a registry entry (or a justified exemption table) — the tile/gatus/OIDC fan-outs can no longer be silently missed. Ghost dns-local entries warn at eval. caddy.nix:432-455, 466-469
+
Derived smoke coverage, zero hand-maintained lists The /etc/caddy/vhost-layers map (layer + first proxy port per vHost) is computed from the same rendered attrset as the proxy, so post-deploy auth-gateway smoke covers new vHosts with zero script edits. caddy.nix:341-364

Architecture of the current usage: NixOS renders the Caddyfile at eval time — the Nix helper layer REPLACES what upstream Caddyfile snippets ((name) {} + import) would do, with type-checked options and assertions instead of string inclusion. globalConfig carries auto_https off, default_bind to the LAN IP only (dnsblockd coexistence + NetBird arrival semantics), strict_sni_host on, and the metrics global option (caddy.nix:493-508). TLS is static/minted — no ACME surface exists at all.

01Findings — the 3 gaps, then what's already right

Ordered by impact. Each gap names what Caddy offers (with doc source), what the repo does instead (with file:line), and the fix.

Missed Opportunity · High impact

metrics { per_host } unused — dashboard is aggregate-only

not used anywhere · globalConfig at modules/nixos/services/caddy.nix:507 sets bare metrics · consumer dashboard modules/nixos/services/dashboards/caddy.json: all 7 queries are sum(...) with no host dimension

Caddy's global metrics option takes a per_host subdirective that adds a host label to every caddy_http_* series (requests, errors, duration, in-flight). Since 2.11 the cardinality is bounded by design — on HTTPS servers each configured host is observed explicitly and unknown hosts aggregate under _other (caddyserver.com/docs/metrics) — and the 2.11.2 per-route instrumentation fix cut metrics CPU ~5× (caddyserver/caddy#7492). Today a per-service error-rate alert requires log parsing or tracing queries; with the label, it is one PromQL clause in the existing SigNoz scrape (signoz.nix:1210 already scrapes :2019). 

# modules/nixos/services/caddy.nix — globalConfig, before:
metrics

# after:
metrics {
  per_host
}

# dashboard/alert query that becomes possible:
sum by (host) (rate(caddy_http_requests_total{code=~"5.."}[5m])) > 0
Fix One word in globalConfig; add host breakdowns to the existing caddy.json dashboard panels and (optionally) a SigNoz alert on per-host 5xx rate. Verified: per_host is a global-option subdirective, not a handler one — it belongs in globalConfig, not in a site block.
Missed Opportunity · Medium impact

Dead backends serve Caddy's plain-text 502 — no branded error route

not used anywhere · every proxy vHost renders through proxyTo (modules/nixos/services/caddy.nix:191-203) with no handle_errors / handle_response for proxy failures; the repo's only handle_errors is the 404 catch-all (caddy.nix:526-537)

The repo already brands unknown-host 404s with a real status and a styled page. A dead backend gets the default plain-text "502 Bad Gateway" instead. Caddy's semantics (verified against docs + caddyserver/caddy#7283): dial failures (backend unreachable) raise an error that handle_errors catches — an upstream 5xx response does NOT trigger error routes and needs handle_response @e status 5xx on the proxy block. Maintainer francislavoie in #7283: "a 502 isn't a response from upstream, but rather an error triggered inside the reverse proxy logic... you have to use handle_errors for this." 

# in the shared vHost helpers (caddy.nix) — one place, every vHost:
error_404_root = ...;  # existing notFoundRoot derivation pattern

handle_errors 502 503 504 {
  rewrite * /502.html
  file_server
}
# page lives in the same store-served linkFarm as notFoundRoot:
# "backend unavailable — {err.status_code}" + dash link, Catppuccin style
Fix Add the error route in plainVHost / protectedVHost / the catch-alls (helpers render it everywhere at once). If forward_auth-vs-proxy 502s ever need distinguishing, the #7283 vars flag pattern is the documented approach. Scope note: oauth2-proxy gate failures are already handled by the @gatefail arm (caddy.nix:150-153), so this gap is specifically backend-down UX.
Missed Opportunity · Medium impact · tradeoff

Caddy's own runtime logs never reach SigNoz — default logger is file-only

modules/nixos/services/caddy.nix:485-492 (global logFormat → output file /var/log/caddy/access.log) · consumer: geometrikks tails the same file (geometrikks.nix:58-63) · SigNoz ingests journald directly (docs/services/caddy.md logs section)

Every vHost carries its own log block (the Nix map at caddy.nix:732-743), so the global DEFAULT logger carries only Caddy's runtime logs — startup, config errors, panics — and they land in access.log, invisible to the journald→SigNoz pipeline that sees every other unit. A caddy crash-loop or config-load failure is currently observable only via unit state, not its own error text. Since 2.11.3 Caddy ships a journald encoder wrapper that prepends journal priority prefixes so per-line severity survives (caddyserver.com/docs/caddyfile/directives/log, PR #7623). 

# caddy.nix logFormat — before:
output file /var/log/caddy/access.log {
  roll_size 100MB
  roll_keep 3
  roll_keep_for 168h
}
format json

# after (runtime logs → journald with severity → SigNoz):
output stdout
format journald {
  wrap json
}
Fix — with a decision Caddy allows ONE default-logger output, so this displaces the file: geometrikks's access.log tail must be dropped (its per-vHost tails are unaffected — those files stay), and the caddy runbook log map updated. Tradeoff is small — the file holds only runtime lines today — but it touches a second consumer, so it is a [decision], not a drive-by.
Optional hardening · Low impact

Slowloris timeouts are inherited defaults — an explicit pin is cheap

globalConfig servers block sets only strict_sni_host on (modules/nixos/services/caddy.nix:504-506)

Being on 2.11.7, the 2.11.6 slowloris defaults apply automatically: 1-minute read/write stall limits with optional minimum transfer rates, 5-minute keep-alive idle (caddyserver.com/docs/caddyfile/options). But read_body (the WHOLE-upload hard limit) still defaults to unlimited — the 10GB request_body cap (caddy.nix:173-175) bounds size, not duration; a steady trickle upload can hold a connection indefinitely. Exposure is low (LAN/VPN-only names; unknown cloud names NXDOMAIN before reaching caddy), so this is polish, not a gap. 

servers {
  strict_sni_host on
  timeouts {
    read_body 15m
  }
}
Watch / owner decision · Low-now impact

No rate limiting — sanctioned path is crowdsec stage-3, not a Caddy plugin

crowdsec.nix:5-7 declares "stage 3 (firewall-bouncer ENFORCEMENT) is still NOT enabled" · caddy.withPlugins is callable in this nixpkgs (__functor verified: nix-instantiate --eval -E 'let pkgs = import <nixpkgs> {}; in pkgs.caddy.withPlugins ? __functor' → true)

Core Caddy has no rate limiter; the community module (mholt/caddy-ratelimit) would require a plugin build (pkgs.caddy.withPlugins { plugins = [ … ]; hash = …; }) plus a vendorHash-style FOD pin. The repo's declared enforcement path is crowdsec's firewall bouncer (log-driven detection is already live on these access logs). Keeping ONE enforcement mechanism is the better trade — record this as the Caddy-side alternative if stage-3 stalls.

Already right — the decisions that would be wrong to "fix"

The audit also confirmed several non-usages are correct: XFF/Forwarded spoofing is blocked by Caddy's post-2.8 default (no trusted proxies — a LAN browser cannot forge X-Forwarded-For toward backends); credential redaction in access logs is on by default (log_credentials correctly absent); admin API stays unauthenticated but loopback-bound and firewalled (only 80/443 open); SSE/streaming backends need no flush_interval tuning (text/event-stream auto-flushes); health checks and load balancing are pointless with one localhost upstream per vHost; and enableReload is correctly avoided — the harden PrivateTmp namespace breaks the reload path, so deploy.sh restarts (docs/services/caddy.md ops section).
