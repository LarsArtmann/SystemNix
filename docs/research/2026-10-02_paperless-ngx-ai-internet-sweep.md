# Paperless-ngx AI — Internet Sweep (what the internet actually does)

**Date:** 2026-10-02 · **Session:** follow-up to the [Paperless-ngx AI deep dive](2026-10-02_paperless-ngx-ai-deep-dive.html) (adoption audit, score 42/100)
**Question:** what does the internet do with Paperless-ngx AI — from "simple and works" to "extreme but fuck cool"?
**Method:** agentic web research (GitHub discussions, project docs, community blogs). Reddit itself was unreachable from the research sandbox (DNS-blocked); the r/paperlessngx crowd's input arrives via GitHub discussions + blogs that mirror it.

## Tier 1 — Simple and works (the community consensus)

| What people do | Details / proof | On evo-x2 |
|---|---|---|
| **Native v3 AI + ONE scoped Apply-AI-suggestions workflow** | The 2025/26 default: fields title+tags+correspondent+doc-type, overwrite ON for title/date, tags always additive. Upstream docs warn: one LLM call per matching document — nobody runs whole-archive scopes blindly. Sources: [jacar.es guide](https://jacar.es/en/paperless-ngx-3-local-ai-ollama/), [paperless discussion #14003](https://github.com/paperless-ngx/paperless-ngx/discussions/14003) | Exactly the deep-dive Stage-1 (option A). The box's scale (~5–30 docs/day ingest) is why a broader scope is safe here than for the average 50k-doc archivist |
| **Non-reasoning models — reasoning modes break structured output** | `llama-index-llms-ollama` drops `think=False` → Qwen3.5 burns 2,700+ tokens → empty JSON / 400 errors. Gemma 3 4B works stock; Gemma 4 E4B needs a one-line patch. Source: [discussion #14003](https://github.com/paperless-ngx/paperless-ngx/discussions/14003) | ⚠️ **Directly relevant:** qwen3.6-moe (flm) is thinking-capable. The box rides `openai-like` (not the buggy ollama client), but if suggestions return empty/timeout: suspect reasoning-token burn FIRST. Watch in Stage 0 eval |
| **Expectation calibration** | One documented tested setup: correspondent + dates ~100% correct, **document type correct 1 in 5** — "use it to propose, not to file without looking" (community write-ups) | Leave doc-type OUT of the workflow fields initially |
| **Model bake-off (community, 2025)** | gemma2:9b won; llama3.1:8b on par; phi4 good for medical terms; Mistral 7B / llama2 poor (missing tags, hallucinated "tag1/tag2"); GLM4 recommended for German but fragile on messy scans; translating the prompt into the document's language improved results. Current-era pick: **qwen3:8b** base (qwen3-vl silently returns empty on structured output). Sources: [clusterzx discussions #185](https://github.com/clusterzx/paperless-ai/discussions/185), [paperless-gpt discussions #287](https://github.com/icereed/paperless-gpt/discussions/287) | qwen3.6-moe:35b-a3b is a class above every model in that bake-off — but unproven on THIS archive (zero observed traffic). Stage 0 answers it |
| **paperless-gpt for bad scans** | Vision OCR "night and day" vs Tesseract; `minicpm-v:8b` / `qwen3:8b` typical; tag-triggered auto (`paperless-gpt-ocr-auto`). Source: [Techno Tim](https://technotim.com/posts/paperless-ngx-local-ai/) | The llama-vlm **Qwen3-VL-8B is a generation newer** than minicpm-v — already queued (`[watch]` vision-OCR row) |

## Tier 2 — Standard cool

| What people do | Details | On evo-x2 |
|---|---|---|
| **Tag-chained queues** (`ai-pending` → process → `ai-processed`, cleanup removes) | THE community-standard scope mechanism — doubles as the escape hatch when quality disappoints: scope down by tag without losing automation. Source: [clusterzx discussions](https://github.com/clusterzx/paperless-ai/discussions/185) | Free with native workflows. **This is the pre-planned fallback if Stage-A quality disappoints** |
| **Custom-field extraction with real field lists** | Live invoice/statement setups extract: `Amount`, `Bill Period`, `Expiry Date`, `Document Year`, `Account/Policy Number`. Hard-won prompt rules: all custom-field values must be JSON strings, **≤120 chars** (paperless-ngx limit), never the literal string `"null"` for correspondent, explicitly forbid human-only status tags. Sources: [yanghu blog](https://yanghu.github.io/posts/paperless-ai-setup/), paperless-gpt custom-field PR (2025) | **Feeds open question §g.3** (extraction schema) — the starting field menu. Verify the 120-char claim against paperless source before encoding |
| **paper-llama principle: never invent metadata** | Uses ONLY existing correspondents/types/tags — explicitly avoids model-invented clutter, with better accuracy than built-in matching. Source: [seabadger-io/paper-llama](https://github.com/seabadger-io/paper-llama) | Independent community validation of the deep-dive's create-missing-OFF stage A |
| **Searchable-PDF regeneration** | paperless-gpt rebuilds scanned PDFs with precisely positioned transparent text layers (hOCR), re-uploads with metadata copied, optionally replaces the original. Source: [icereed/paperless-gpt](https://github.com/icereed/paperless-gpt) | Free with the paperless-gpt module — retro-rescues the worst scans in the archive |
| **4 swappable OCR backends** | paperless-gpt: vision LLM / Google Document AI / Azure Document Intelligence / self-hosted **Docling server**. Some route hard invoice extraction to Google Doc AI's prebuilt invoice processor (~30 fields) | Cloud legs rejected (privacy posture); local vision + Docling remain. Docling = heavy CPU; llama-vlm path preferred |

## Decision hooks (open §g questions)

**Q1 — AI scope:** the internet's consensus mechanism is the **tag-chain**, not all-documents — but that consensus exists for 50k-document archives on shared queues. At this box's ingest volume, **Stage A (all non-empty, create-missing OFF, overwrite OFF = blanks-only)** remains the recommendation, with the community's tag-chain as the pre-planned fallback. The sweep adds one thing the deep-dive plan lacked: **expectation setting** — document-type suggestions are ~20% accurate everywhere, so leave doc-type out of the workflow fields.

**Q3 — extraction fields:** start from the proven community menu — statements: `Amount`, `Bill Period`, `Account/IBAN`, `Document Year`; receipts: `Total`, `Merchant`, `Expiry` (warranty documents get the HA-style deadline-reminder pattern for free via a custom field). The LedgerBridge confidence-routing pattern is the upgrade path: extracted fields → bank-sync reconciliation with a review queue instead of blind trust.

## Adopt-queue (promoted to ROADMAP if owner bites)

1. Confidence-gated extraction feeding bank-sync reconciliation (LedgerBridge pattern) — pairs with the paperless-gpt module
2. `paperless-mcp` NixOS module (loopback, sops token) — AI sessions manage the archive directly
3. Weekly LLM digest via mail-relay (tiny oneshot)
4. `paperless_inbox_count` + AI-task textfile metrics (folds into the queued failed-tasks collector)
5. Warranty-expiry custom field + deadline reminder hook (after extraction lands)
