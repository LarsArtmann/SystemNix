00Summary

Agent Router is the Envoy AI Gateway renamed — an Agentic AI Foundation (Linux Foundation) project, current release 1.2, Apache 2.0, powered by Envoy and Envoy Gateway. It puts one OpenAI-compatible API in front of 21 providers (plus any OpenAI-compatible backend, including local llama.cpp), and moves credentials, failover, token limits, model-name virtualization, and MCP tool aggregation out of agents and into gateway configuration. It runs standalone via aigw run on loopback:1975 with an admin interface on :1064 — no Kubernetes, no Docker.

For this stack — one host, one user, a Crush-centric agent fleet (interactive sessions, crush-daily, tq-agent-pool), a local GTT-backed llama.cpp/Jan serving tier, and OpenRouter as the de-facto cloud router — the verdict is watch, do not deploy. The project’s core pitch (multi-team credential governance and quotas) does not exist here, and the real integration cost is Nix packaging: aigw is absent from nixpkgs and downloads Envoy at runtime via func-e into ~/.local/share/aigw, which violates the declarative model. This is the same class of verdict as the Ollama removal: a heavy abstraction whose center of value sits outside this deployment shape.

What is genuinely valuable here: OTel GenAI attribution into SigNoz, credential centralization that matches the sops doctrine, unified local→cloud failover, and LAN exposure of the GPU stack to the MacBook — the first three only become worth their cost when specific triggers fire. Two moves are available today at zero deployment cost: stealing the OTel GenAI observability pattern, and using aigw run as a dev/test harness for go-aichat.

The bottom line Do not deploy. Record a [watch] row in docs/todo/ai-stack.md with the four named triggers from §06 (event-driven, no revisit date), and take the two zero-deployment moves now if desired. Reassess the moment aigw lands in nixpkgs — that alone removes the largest friction.

◆What Agent Router does well

Credible engineering, not vaporware — this is Envoy Gateway’s AI control plane with production adopters (Bloomberg, LY Corporation, Nutanix, Tencent Cloud, Stacklok) and a foundation home. The merits that matter for a hypothetical future here:

+
One API, 21 providers, any OpenAI-compatible backend Model switching becomes a model-name change; auto-configuration accepts plain OPENAI_BASE_URL, so local llama.cpp or Jan slots in as a first-class backend next to cloud keys.
+
Standalone mode without Kubernetes aigw run config.yaml is a real single-process deployment (Envoy child + extproc), which is the only shape that could run on this Docker-free host. Config mirrors the k8s CRDs, so a laptop trial graduates to a cluster unchanged.
+
Observability is first-class, not an afterthought OTel spans with OpenInference or GenAI semantic conventions, request/response capture behind explicit redaction switches, header→span mapping for session attribution (agent-session-id:session.id by default), and a Prometheus /metrics LLM endpoint on the admin port.
+
Credential centralization done right Clients authenticate to the router and nothing else; provider keys live in one config, rotated in one place. This is the gateway restatement of this repo’s own sops doctrine — and the direct answer to the fish_history leak class.
+
Institutional durability LF-hosted (Agentic AI Foundation), weekly public meetings, four maintainer companies, stable CRD/API group guaranteed across the rename — a low-likelihood-of-abandonment dependency if it ever enters this stack.

02Fit assessment for this stack

The deployment shape that would receive Agent Router: one NixOS host (evo-x2, 128 GB, GTT-first GPU), one user, Crush as the primary agent surface plus daemon sessions, SigNoz for OTel, Caddy + Pocket-ID at the edge, sops for secrets, zero Docker, zero Python.

Leverage point Fit Reasoning
Unified local+cloud endpoint — Jan/llama-router + zai/minimax/openrouter behind one URL; local→cloud failover as config, not per-agent logic Medium — trigger-bound Aligns with the pending llama.cpp router-mode revisit row (2026-10-12 status); today llama.cpp’s own router mode covers the local-only slice more cheaply
Credential centralization — provider keys only in sops-rendered router config; Crush/hermes/go-aichat daemons hold one router key each High Directly serves the fish_history leak lessons; rotation collapses to one sops file; per-client keys give free attribution
OTel GenAI spans + :1064 metrics → SigNoz — per-agent token/cost attribution, TTFT, which model answered, where fallback fired High — strongest single-user value Native fit with the existing SigNoz stack and monitoring discipline; no agent-side instrumentation required
Hard spend caps for the daemon fleet (crush-daily, tq-agent-pool) via per-key token limits Medium The memory-emergency-guard philosophy applied to money; only matters once cost is a live constraint
MCP gateway — one tool catalog, per-agent filtering Low HTTP-only transport excludes local stdio servers (qmd); Crush already owns MCP per-client; single-user means no identity-filtering value
When it becomes compelling Any two of the three high/medium rows activating at once — e.g. the router-mode consolidation landing while wanting cloud failover and spend attribution. One alone does not justify owning an Envoy control plane.

03Frictions — why not today

Honest blockers and costs, ordered by weight.

Blocking · The real cost

Nix packaging friction

nixpkgs by-name search · docs/cli/aigwrun §File Locations

aigw is not in nixpkgs, and standalone mode downloads Envoy at runtime via func-e into ~/.local/share/aigw. A deployment here means: a custom buildGoModule package, pinning Envoy from nixpkgs, neutralizing func-e (pre-provisioned AIGW_DATA_HOME or a wrapper), and maintaining it across a fast-moving upstream. That is the dominant cost of adoption — larger than configuration, larger than operations.

Fix: wait out the friction The “aigw lands in nixpkgs” trigger (T4 in §06) deletes this entire issue. Contributing the packaging upstream is the constructive alternative — see §04.
Important · Wrong shape

The core pitch does not exist here

theagentrouter.ai solutions · repo precedents: Ollama removal, Docker removal

Multi-team credential isolation, per-team quotas, platform-team governance — v1.2’s headline features — have no buyer in a single-user homelab. Deploying anyway risks the Ollama verdict (“bad abstraction on top of llama.cpp”): an always-on Envoy control plane owned for plumbing value. The two-tier gateway pattern’s Tier Two (k8s InferencePool endpoint picking) is k8s-only and permanently out of scope here.

Important · Blast radius

Single point of failure for all agent traffic

deployment-shape consequence

One wedged gateway takes down every daemon simultaneously — crush-daily, tq-agent-pool, and interactive sessions alike. It would need the full treatment from day one: lib/systemd.nix hardening, gatus liveness coverage (the in-use-port audit generalizes to a served-port check), MemoryMax doctrine, and a documented client-side escape hatch back to direct provider keys.

Watch · Low weight

Upstream velocity and rename churn

project blog · release notes

Renamed 2026-09-10; v1.2 is the first release under the new name. API stability is explicitly promised (“manifests from yesterday apply tomorrow”), but a five-week-old identity moving at this pace warrants pinning discipline (tag, never float) if it ever enters the flake — the repo already enforces that pattern for inputs.

Gap · Low weight here

MCP stdio gap

docs/cli/aigwrun §MCP Configuration

The MCP gateway accepts http / streamable-http transports only. Local stdio servers (the qmd MCP pattern) cannot be aggregated without a bridging hop — one more moving part that erases the simplification the feature promises.

04Angles beyond deployment

Value extractable from Agent Router without putting it in the critical path — ranked by leverage per unit of cost.

1
LAN GPU endpoint for the MacBook — the one genuinely new capability Today no model endpoint is reachable off-host: Jan’s router is ephemeral loopback by design (docs/services/jan.md). A router on evo-x2 behind Caddy + Pocket-ID SSO (ai.home.lan) would hand the 24 GB MacBook a credentialed OpenAI-compatible endpoint into the 124 GB GTT stack, with cloud failover when the GPU is saturated. That is a product feature, not plumbing — and the strongest future justification for the whole exercise.
2
go-aichat dev/test harness — zero-deployment leverage, available today aigw run is explicitly pitched for “local development of provider-agnostic AI applications”. go-aichat is exactly that: the router provides provider-switching and model-name-virtualization test paths against local llama.cpp, without burning N real provider keys in CI. Runs on the dev laptop, never enters the flake.
3
nixpkgs packaging as the decisive watch signal — and a contribution opening Someone else packaging aigw deletes the main blocker (T4). Conversely, contributing that packaging upstream fits the established OSS contribution pattern (charmbracelet, jj) — an LF project with weekly public meetings is a receptive venue, and it converts adoption cost into reputation.
4
If triggers fire, compare LiteLLM first LiteLLM is the default everyone reaches for — and it is Python, which collides with the zero-Python doctrine (2026-10-15). Agent Router (Go + Envoy) fits the Go-native stack without a fight. The comparison must still be made honestly before any deploy: LiteLLM’s operational surface is a single pip-installable process.
5
Steal the patterns without the gateway OTel GenAI semantic-convention dashboards in SigNoz and per-session attribution headers (the OTEL_AIGW_REQUEST_HEADER_ATTRIBUTES pattern) apply equally to direct OpenRouter and llama.cpp traffic. The observability value is mostly a convention, and conventions are free.
6
Tetrate hosted service: no router.tetrate.ai relays every prompt through a third party, cannot serve the local GPU tier, and its trust model is OpenRouter minus the local-model capability. It solves exactly the part of the problem this stack does not have (managed infrastructure) while breaking the part it does (local models).

05Target shape if a trigger fires

A sketch, not a plan — the point is to show the shape a deployment would take as an ordinary SystemNix service module, so the eventual cost is legible now. Sequence matters: one client first, evidence in SigNoz, then the fleet. 

modules/nixos/services/agent-router.nix
  systemd.services.agent-router
    serviceConfig = lib.harden { ... }          # lib/systemd.nix defaults
    loopback bind (default) or Caddy-fronted    # vHost only when LAN access wanted
  ports: 1975 (proxy) + 1064 (admin)            # lib/ports.nix — registry-audited
  config: sops template                         # provider keys never in the repo
  OTEL_EXPORTER_OTLP_ENDPOINT -> SigNoz         # GenAI semconv spans
  backends: llama-server (local GTT) + zai / minimax / openrouter
  clients: Crush provider -> http://localhost:1975/v1
1

Package it

buildGoModule for aigw + Envoy pinned from nixpkgs; neutralize func-e by pre-provisioning AIGW_DATA_HOME or wrapping the launcher. Skip entirely if T4 fired first.

2

Module + registry

Service module with harden{}; ports registered in lib/ports.nix so the eval-time port audit passes by construction; gatus check wired from day one.

3

Secrets + per-client keys

Provider keys via sops template only. Distinct router keys per client class (crush-daily, tq pool, interactive) — attribution comes free at the gateway.

4

Observability

OTLP → SigNoz (GenAI semconv, content capture OFF by default); :1064 scraped into the metrics pipeline; dashboards for tokens/cost/TTFT/fallback per client key.

5

Cut over ONE daemon client first

Not interactive Crush. Verify attribution and failover in SigNoz, keep direct-provider escape hatch documented, then expand to the fleet.

Doctrine check This sequence honors two repo rules: land the replacement before removing the old source (direct provider configs stay until the gateway proves parity), and never assert success from output text — assert which entity served the request, visible in the SigNoz attribution spans.
