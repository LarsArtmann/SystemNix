00Summary

browser-history integrates the module correctly at every seam it touches: PKCE S256 always sent, one-time state consumption, JWKS-verified ID tokens, event-sourced sessions, lockout, and an OAuth-only posture (passkeys disabled 2026-10-16) that fails the boot closed when the provider is missing. The login core is not the problem.

The problem is that the integration stops at login: the IdP's identity data is truncated at the email claim, so RBAC is a server-side env var (SUPER_ADMIN_EMAILS), logout is local-only, server-side PKCE enforcement is missing, and an auth-critical upstream security pair sits unreleased-unconsumed. Meanwhile a shipped CLI that heals the 8 duplicate accounts has never run against production.

The bottom line Solid login plumbing, identity features idle. The highest-leverage step is one line — pkceEnabled = true on the browser-history Pocket ID client (the only fleet consumer missing it) — followed by an oauth2 tag bump and the never-run merge-duplicate-users stop-window.

The baseline is genuinely good — these are verified, not assumed:

+
PKCE S256 on every login, OIDC discovery for endpoints provider.go:225-238 — BeginLogin always adds oauth2.S256ChallengeOption; Pocket ID endpoints come from issuer discovery, nothing hardcoded.
+
One-time state + rate-limited OAuth surface oauth2.go:106 — ConsumeWithNonce deletes the state token on use; OAuthRateLimit covers /auth/oauth/* (usermgmt http.go:88).
+

+

01Findings

Ordered by impact. Misused first, then missed opportunities.

Misused · Anti-pattern · High impact

IdP-side PKCE is not enforced — the ONLY fleet OIDC client without pkceEnabled

modules/nixos/services/browser-history.nix:904-910 · fleet norm: crm.nix:509, immich.nix:212, paperless.nix:1595, cv.nix:1381, monitor365.nix:1230, dns-blocker.nix:1917, geometrikks.nix:875, opencloud.nix:294 — all set pkceEnabled = true

The Go module always sends an S256 challenge (client-side), but Pocket ID only enforces the verifier exchange for clients flagged PKCE — otherwise the code-for-token swap runs without the binding and the challenge is decorative. Paperless even carries an eval-time assertion demanding pkceEnabled = true (pocket-id.nix:460-461); browser-history's registration omits the flag entirely. 

# modules/nixos/services/browser-history.nix (integration registry)
oidc = {
  name = "Browser History";
  clientId = "browser-history";
  launchURL = "https://history.${domain}";
  callbackURLs = [ "https://history.${domain}/auth/oauth/pocket-id/callback" ];
  # MISSING: pkceEnabled = true;  — every sibling sets it
};
Fix Add pkceEnabled = true to the registration. One line, declaratively provisioned by the Pocket ID provisioner, rides the next deploy.
Missed Opportunity · High impact

IdP groups → RBAC unused — super-admin is still a server-side env var

provider.go:159-160 (default scopes openid+email+profile — no groups) · provider.go:110-118 (userInfo has no groups field) · api/oauth2.go:64-71 (no Scopes passed) · fleet fact: docs/agents/sso-dns.md:48

Pocket ID emits the groups claim only when the client requests the groups scope, and the module neither requests it nor carries it through — the extracted claim set stops at email/name/preferred_username. The consequence is visible in today's 403 incident: admin membership is granted by a SUPER_ADMIN_EMAILS env bootstrap (api/admin_panel.go:99), re-coupled to every deploy, instead of being an IdP-declared group that revokes everywhere at once. Paperless already proves the fleet pattern (fail-closed superuser-group mapping, sso-dns.md:48). The module also ships the escape hatch — FinishLoginWithToken returns the verified raw ID token, so groups are readable today without a library round-trip; browser-history simply doesn't call it.

Recommendation Short term: switch the Service to FinishLoginWithToken, read the groups claim, map it to identitymodel roles (fail-closed, paperless style) — plus request the scope and provision the group via pocket-id-config.provision.userGroups. Long term: upstream — extend userInfo with groups + a role-mapping config; needs a provisioner scope field too (oidcClientType has none, lib/types.nix:10-53).

Missed Opportunity · Medium impact

Logout is local-only — no RP-initiated logout

usermgmt http.go:217 (POST /auth/logout clears only the app session) · zero end_session/post_logout references in the module · fleet fact: docs/agents/sso-dns.md:50 · provision schema already has logoutCallbackURLs (lib/types.nix:25-29, unused)

After a Pocket ID logout, browser-history's 24h session cookie survives on shared machines — the IdP session ends, the app session does not, and nothing redirects through the IdP's end-session endpoint. The fleet doc explicitly records this as per-app work that is "not currently done".

Fix Logout handler 302s to the discovered end_session_endpoint with id_token_hint + post_logout_redirect_uri; provision logoutCallbackURLs for the client.
Missed Opportunity · Medium impact

Step-up re-auth available at the IdP, unused — most valuable exactly on /admin/

lib/types.nix:38-42 (requiresReauthentication — per-client passkey re-auth each login, unused by ALL fleet consumers) · /admin/ identity operations sit behind a 24h session

Role changes, tenant administration, and the audit log are reachable for 24h after one passkey ceremony. Pocket ID can force re-authentication per client; a dedicated browser-history-admin client (or upstream prompt=login / max_age=0 on admin routes) would give the privileged surface a fresh ceremony instead of a stale session.

02bWhat the solution could look like

Target state: Pocket ID is the single declarative source for who may sign in, who admins, and how strong each door is — the server consumes identity instead of assembling it. 

# browser-history.nix — integration registration (target)
oidc = {
  name = "Browser History";
  clientId = "browser-history";
  callbackURLs   = [ "https://history.${domain}/auth/oauth/pocket-id/callback" ];
  pkceEnabled    = true;          # server-enforced verifier exchange
  logoutCallbackURLs = [ "https://history.${domain}/" ];  # RP-initiated logout lands
  # scopes = [ "openid" "email" "profile" "groups" ];  — needs schema field upstream
};

// browser-history api — groups → roles at the verified-token seam (target)
tok, info, err := provider.FinishLoginWithToken(ctx, "pocket-id", code, verifier)
roles := mapGroupsFailClosed(groupsFromIDToken(tok))  // paperless precedent
This is the target Admin membership becomes an IdP group (revoke in Pocket ID = revoked everywhere, no redeploy), the code-for-token swap is server-enforced PKCE, and logout actually logs out. The env-var bootstrap and its drift risk disappear.
