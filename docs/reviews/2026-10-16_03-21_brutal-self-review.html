01What did I forget?

Hygiene hole

Snippet files were world-readable — and secrets ride snapshots forever

pkgs/dms-plugins/systemnix-snippets/SnippetsLauncher.qml (save flow) + ~/.local/share/snippets/

The save flow wrote clipboard content with umask-default perms. Verified live today: both seed snippets sat at -rw-r--r--. The feature's entire purpose is "save whatever is on my clipboard" — that includes passwords, tokens, and keys. Worse: ~/.local/share/snippets lives inside the @ home subvolume, whose pool-side retention is forever (docs/agents/storage.md — the exact property that motivated @home-hermes's bounded pool). A secret snippet saved then deleted today still exists in pool snapshots indefinitely.

Fixed on the spot (repo): save flow now runs chmod 600 after writing; live seed files chmod'd 600. Still open (owner): even 600 files ride forever-pool snapshots — accept ("no secrets in snippets" doctrine), bound the retention, or relocate the dir. Queued as a decision row.

Shift+Enter (getPasteArgs) was never live-verified

SnippetsLauncher.qml:261-265 vs status report §b.2

03What could I have done better?

Guard claims verified a session too late

The patch-block comment claims "build fails if upstream text drifts." I verified that claim today — it was true for five of six markers and weak for one (see 05). The 2026-09-16 review's finding was exactly "guard text overclaim went unchallenged"; the lesson from that episode should have made verifying the guard text part of the same session that wrote it. A reviewer a day later is better than none, but the right time was before "verified" appeared in the status report.

The perms fix belonged in the first draft

"Write clipboard content to disk" should trip a secret-hygiene reflex at design time, not at review time. The data-model question — "what is the most sensitive thing this store can contain?" — was never asked. The answer (everything the clipboard ever held) dictates 600 perms and a retention stance by default.

06How can we be less stupid?

Two patterns to adopt

Pair every positive grep guard with its negative twin (post-state present AND pre-state absent) — presence checks alone can false-pass. Any feature that persists clipboard or user content to disk gets a secret-hygiene line in its design notes (perms, retention, backup exposure) before the first line of implementation code. Both are now one-line culture rules in this review; the repo's eval-audit machinery can enforce the first class where it applies.

11Tests — how are we doing?

Gap

Zero automated coverage for the new surfaces

flake/parts/checks/ — nothing covers binds or plugin

The patch block is effectively self-testing (build fails on drift, now from both directions). But the three niri binds and the plugin registration have no guard: a refactor that drops or renames Mod+Shift+C ships silently.
