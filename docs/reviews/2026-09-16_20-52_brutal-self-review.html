02What is stupid that we do anyway?

A safety guard that cries wolf by design

The double-pool guard pattern-matches the path prefix /tmp/tq. Any dev build a parallel session drops at /tmp/tq-redesign, /tmp/tq2, … re-fires the WARN on every deploy. Operators habituate to it, and the day a REAL second harvester runs, the warning drowns in the noise it trained everyone to ignore. Pattern-matched safety checks degrade into decorations.

The un-anchored generation is gated on passive console noise

deploy.sh HAS an anchoring warning and it fired on the 17:48 forced deploy. Warnings that fire and demand human action — for a state that a script can detect exactly (readlink comparison) — are the weakest possible control for a reboot-reverts-everything class of risk. 26 hours after the first exit-4 (08:25 → now), the machine is still two un-anchored systems deep.

04What could I still improve?

Six concrete items, all scoped

  1. Guard semantics: warn only when cmdline contains agent-pool OR the process's TQ_DB targets the pool journal / a repo tasks.db; read /proc/<pid>/environ (same-user). Scratch-DB dashboards go silent.
