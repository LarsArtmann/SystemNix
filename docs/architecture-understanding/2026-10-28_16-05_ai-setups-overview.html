The design in one sentence

Async bulk work goes to the NPU (FastFlowLM, socket-activated, idle-unloaded), interactive agent turns go to a CPU-resident llama-server (llama-chat, always warm, thinking off), retrieval goes to GPU llama-server instances (llama-rag), vision goes to socket-activated llama-vlm instances — and every call, local or cloud, crosses one loopback metering proxy (ai-meter) that attributes tokens, cost, and latency per client. Ollama was removed by owner directive (2026-10-12) and is never to return.

Why llama-chat is CPU while the GPU exists

The llama.cpp/ROCm path wedges under systemd units on gfx1150 (freeze #5, 2026-09-18 — even the rev-pinned 0.3.0 build: ~94% single-thread CPU spin after the vocab warning, 3/3 repros). llama-rag only runs because it was re-pinned to the byte-identical proven 0.3.0 store path and gated by a soak protocol; the interactive brain went CPU instead. A 3B-active MoE keeps first-token latency in milliseconds without the GPU.

FastFlowLM operational shape

MaxConnections = 8 inetd-style socket (flm's hard limit is 10; the consumer budget peaks at 7). Cold load is 2-5 min for the 21.6 GB mmap'd model, so the socket activation + 1h idle TTL keeps RAM free when idle. The backend is the memory-guard's designated sacrifice (OOMScoreAdjust=300, exponential restart backoff) and carries a release-verified port guard (lib/port-guard.nix) against the 5×-recurred zombie/orphan port-holder class. Gatus must never probe :52625 — every TCP probe is a permanent keepalive that pins the model.

02Metering Layer — ai-meter

Every OpenAI-compatible AI call on the host flows through one loopback Go proxy (~700 lines, in-tree at pkgs/ai-meter/): tokens, cost, latency, TTFT, and per-client attribution without changing any request shape. Proxy on :8107, Prometheus metrics on :8108 (scraped by SigNoz). Client keys are runtime-minted per boot (/run/ai-meter-keys/) — never in the repo, never in sops. Upstream provider keys are sops copies owned by the ai-meter user.

05Hardware Model — GTT-first Strix Halo

+
NPU (XDNA, /dev/accel0) owns async chat FastFlowLM maps Qwen3.6 MoE onto the NPU; socket activation + idle TTL keep the 21.6 GB model out of RAM when idle.
+
GPU is GTT, not VRAM The BIOS UMA carveout is 1 GiB (the floor). All real GPU memory is GTT = shared system RAM (~124 GiB); ttm.pages_limit=120G is a soft eviction trigger, and monitoring uses the node_amdgpu_mem_info_gtt_* metrics, never VRAM-% (which pins near 100% forever on this carveout).
+
ROCm needs two session variables HSA_OVERRIDE_GFX_VERSION=11.5.1 (gfx1150 is not officially supported; without it ROCm silently falls back to CPU) and HSA_ENABLE_SDMA=0; llama-server-rocm additionally bakes in the ROCm library path for dlopen'd libs.
+
Device cgroup isolation is load-bearing rocm.deviceCgroup (DevicePolicy=strict, dri/kfd only) exists because ROCm's libdrm enumeration opens the NPU accel node and wedges every llama-server start in unkillable D-state (2026-09-04 incident, corpses survive SIGKILL until reboot).
