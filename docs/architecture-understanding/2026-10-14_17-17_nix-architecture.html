The one-sentence diagnosis

The architecture the last review prescribed exists and is adopted — but the two files it named as P1 cleanup both GREW (system-health 1616→2602, configuration.nix 1038→1522), and the remaining debt is concentrated: per-service health collectors, host-side config prose, and the SigNoz family scatter.

01Findings

Registry inversion: LANDED (the big win since 2026-09-14)

services.integration.<name> fans out to Caddy vHosts, Gatus checks, dashboard tiles, backup coordination, monitored units, OTel env + signoz-coverage, and Pocket ID clients. 55 of 126 modules declare entries; gatus-config.nix shrank 2479→1374 (infra checks only); caddy.nix is a renderer with policy ownership. Adding a service is now 2–3 files, not 9–11.

system-health.nix grew 61% — the collector god-file

2602 lines, of which ~1400 are ONE systemHealthMetrics shell script inline. Per-service readers (monitor365, signoz rules, forgejo mirrors, pma commits, dnsblockd stats, pocket-id busy, zram) are still centralized options — the exact shape the registry removed for checks and tiles. There is an extraMonitoredServices seam for UNITS, but no seam for COLLECTORS.

configuration.nix is now a documentation carrier

1522 lines: 711 comment vs 579 code. Runbook prose duplicates docs/services/*.md ownership (split-brain doc risk) and every new service grows the hottest merge-conflict file on a multi-session tree.

Deploy-gate packaging died 5× on the same trap class

pre/post-deploy-check apps hand-copied each scripts/lib/*.sh into bin/lib; every new lib shipped without its staging line killed the gate at source time (2026-09-02, 2026-10-04, 2026-10-10, 2026-10-12 ×2). Fixed this session: glob staging.

Convention drift: with pkgs; (29 sites) and 2 rec attrsets

The repo's own documented convention ("with pkgs; hides missing attrs") was violated in 34 sites (29 module/platform + the 5 base.nix manifest lists, ~130 references); rec attrsets hide dependency structure. All fixed this session, plus a lint so the class cannot regrow.

Target ≤600 lines, one enable line + host deltas per service. The prior review's P1 item, still open — the file GREW 47% instead.

Verification method (why drvPath A/B was insufficient here)

The toplevel drvPath could not serve as the sole oracle: it embeds dirtyRev (changes on ANY edit), flake.lock moved mid-session (2-line diff, parallel session), and pocket-id.nix carried parallel edits (84-line delta vs my 8). Triangulated instead: (1) full toplevel eval green — every explicit pkgs.X exists; (2) mechanical scope audit — zero prefixed identifiers shadowed in their files; (3) rendered values spot-checked (package set resolves, theme palette byte-identical across all 11 public keys); (4) both app derivations built and their bin/lib contents enumerated.
