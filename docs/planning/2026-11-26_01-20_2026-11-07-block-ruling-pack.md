A fourth way, dispatch the block: 1,074 rows through a pool that moves about 20 rows a day is 54 days of pool time, 95 % of it on rows whose ask is not in the row. Not recommended.

## 6. Recommendation

**Option C.** Reasons: the dispatch outcome of all three options is the same today (zero), so the ruling changes only whether that is an accident or a rule; C is one reversible commit; it removes 30 % of the queue file for every reader; and the stamp is what lets the verify-first sweeps of plan v6 (T16 to T23, 25 rows a wave) run against parked rows instead of forgetting them: a sweep takes 25 parked rows of one library, closes the stale ones (the sample says about a fifth close on touch), and re-queues the live ones with a full body.

Choose B if the 1,074 notes read as noise; choose A if the queue should keep showing every row ever harvested, whatever the dispatch order does with them.
